# Free-tier combination comparison — manual review sheet

> **COMPILED REPORT — three measurement batches, one table.** This supersedes
> `20260803T112640Z.md`. Every row carries the stamp of the run that produced
> it; nothing was re-run to build this sheet. The Verdict columns are
> deliberately **EMPTY** — the automatic score is a keyword smoke signal, and
> the free-vs-paid decision is made from the hand-filled column.
>
> **What is NEW since the last sheet.**
>
> 1. **The two Tavily tiers are now MEASURED, not skipped.** The previous run
>    recorded them `unconfigured` because `TAVILY_API_KEY` looked unset — but
>    the key **does exist**, in `services/zoe-data/.env`. It is sourced into the
>    run environment from there and is never printed, committed, or written to a
>    results file.
> 2. **A `cloakbrowser` tier exists at all.** It needs broker text extraction,
>    which did not exist: `browser_broker.py`'s executor returned a base64 PNG
>    and nothing else. That is PR **#1626**
>    (`feat/browser-broker-text-extraction`). `websearch/cloak.py` imports that
>    function **by path** rather than vendoring a copy, so the eval scores the
>    real implementation — and correctly reports the tier UNAVAILABLE against a
>    checkout without the PR.
>
> **BUDGET — 33/33 spent exactly, and the cap held.** The free tier is
> 1,000 credits/month ≈ 33/day, enforced client-side (Tavily's API returns no
> remaining quota). Spend: `tavily-free` on the **full 26-query corpus** (26
> calls) + `tavily+scrapers` on a **documented 7-query sub-sample** (7 calls) =
> **33**. The harness's own pre-flight guard was the mechanism — it refuses to
> start a Tavily combo it cannot afford, and 7 remaining was exactly enough for
> the sub-sample. `remaining` is now 0; the counter resets on the UTC date roll.
>
> **THE SUB-SAMPLE IS NOT A 26-QUERY RESULT.** `tavily+scrapers` has **n=7**,
> chosen before the run as *both claim pairs + technical + one local*:
> `claim-t01`/`claim-f01`, `claim-t03`/`claim-f03`, `tech-01`, `tech-03`,
> `local-01`. Its mean score is computed over 7 queries and is **not**
> comparable like-for-like with the n=26 rows.
>
> **LATENCY IS LOAD-CONTAMINATED — do not read the medians as performance.**
> Four other agents were working on this box throughout. Measured `load1` at
> each stage: `tavily-free` 3.63 → 3.97, `tavily+scrapers` 3.83 → 4.25,
> `cloakbrowser` 5.16 → 4.44. All far above the 1.5 threshold, and available
> RAM sat at **190–312 MB** the whole time. The `cloakbrowser` median of
> **10.02s** is the clearest casualty: the same tier fetched
> `en.wikipedia.org/wiki/Canberra` in **4.57s** in an isolated smoke, and
> per-query times in the run ranged 5.2s–33.0s. Treat every median here as an
> upper bound measured under contention, and treat cross-batch latency
> comparisons as invalid.
>
> **`cloakbrowser` RAM profile — 553 MB peak across 12 Chromium processes** for
> a single page, measured by polling `/proc` during the smoke. Every browser
> process ran inside
> `systemd-run --user --scope -p MemoryMax=1024M -p MemorySwapMax=2048M`.
> Verified before the run rather than assumed: the live voice brain
> (`llama-server.service`) holds `MemorySwapMax=0` + `MemoryLow=6G` and Kokoro
> `MemorySwapMax=0` + `MemoryLow=3G`, so a capped browser cannot evict either.
>
> **`cloakbrowser` FLOW CHOICE — a deliberate mirror of `jina-extract`.** Same
> discovery (`ddgs`, limit=3), same target (`results[0].url`), same packet
> shape. The only variable is the extraction backend, which makes those two
> rows the one genuinely apples-to-apples pair in this table. **What it does
> not measure:** CloakBrowser's actual selling point is *stealth* — passing
> Cloudflare/FingerprintJS where a plain client is refused. `ddgs` did not block
> once across either run, so there was nothing to bypass. On this corpus
> CloakBrowser is scored purely as an extractor; its stealth value is
> **UNMEASURED, not disproven**.
>
> **The two `cloakbrowser` blocks are real limitations, honestly reported.**
> `local-05` — Reddit: `Page.content` failed because the SPA was still
> navigating (fixable with a settle wait). `howto-02` — thespruceeats.com
> returned no text at all. Both raised `blocked`; neither degraded into a
> silently short result, which is the harness's headline rule.
