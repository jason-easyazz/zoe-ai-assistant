## Observations (evidence only — the verdict is the operator's)

1. **`ddgs`, `ddgs+scrapers` and `all-free` are the SAME pipeline today, so their
   spread is the noise floor.** With Tavily unconfigured, `all-free` merges exactly
   one batch — `ddgs` — then scrapes the top URL, i.e. it is `ddgs+scrapers` plus a
   consensus merge over a single tier (every row carries the note `tavily
   unconfigured`). Three samples of one stack scored 0.833 / 0.881 / 0.917 with
   medians 2.94–4.20s. **Treat differences below ~0.08 score or ~1.3s median as
   engine noise, not as a ranking.** The same instability shows up directly: two
   `ddgs` calls for the same query minutes apart share only **0.333** of their URLs.

2. **Tier 0 (`scrapers`) is the only combo inside a voice budget, and it cannot do
   claim-checking.** 1.195s median, p90 1.32s, never blocked — versus a 13.4–13.7s p90
   for every engine combo. But it scored **0.000 on all three claim-false queries** and
   0.000 on technical: Wikipedia-search-then-extract retrieves the *topic* page for a
   false claim, never the contradiction. Fast enough to speak, wrong tier for
   "are you sure?".

3. **The instrument mislabels an empty engine result as `blocked` when Tavily is
   unconfigured** (`run_eval.py` `combo_all_free`): `notes` always contains
   "tavily unconfigured", and the return is `"blocked" if notes else "empty"`, so the
   single `blocked` cell (`local-05`, 15.5s) is really an empty `ddgs` batch with no
   `EnginesBlocked` raised. It inverts the harness's own headline rule — a block must
   report BLOCKED, and *only* a block may. Trust the block/empty split in this run only
   after reading the row's `notes`.
   **FIXED IN CODE** (status now derives from a `blocked_tiers` list populated only by an
   actual `EnginesBlocked` raise, pinned by `tests/test_eval_status.py`) — the recorded
   rows below are left exactly as measured, but `all-free` / `local-05` should be read as
   `empty`, and this run's `all-free` block count as **0**.

4. **`jina-extract` stays enrichment-only, now with a sharper number.** 9.125s median
   but **19.60s p90 / 31.87s max**, 2 empties, and **15 of 26 pages truncated at the
   20,000-char cap**. It also scored 0.000 across claim-false.

5. **Structured enrichment fires on a minority of engine results:** `ddgs+scrapers`
   enriched **10 of 26** queries (38%) — the scraper tier only matches Wikipedia/HN
   URLs, so on 62% of queries it is `ddgs` with extra latency and no extra evidence.
