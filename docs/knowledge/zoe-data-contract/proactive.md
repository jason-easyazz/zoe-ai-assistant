### ZD82 Real users and proactive recipients

- **Who is a real user / who a proactive push is for — one rule each, never re-derived inline.** `user_filters.py` (stdlib-only, importable from `proactive/`) owns `GUEST_USERS`, `is_synthetic_user` (guest sentinels + `SYNTHETIC_USER_RE`, case-insensitive: the prefixes `^(test|probe|demo|ci|e2e|bench)[-_]`, our own load-probe run ids `^zoe[-_](hammer|tok)[-_]\d+$` (digits only, whole id, so a real `zoe-hammer-jane` stays a person), and the exact harness ids `zoe-mempalace-baseline` / `zoe-prompt-packet-measure`; bare `zoe-` is never a prefix: panel ids like `zoe-touch-pi` are people; `scripts/maintenance/memory_ledger_audit.py` mirrors the regex and a test pins them equal; `ZOE_SYNTHETIC_USER_ALLOWLIST` opts pattern ids back in, never a guest), `drop_synthetic_users` (logs ONE `<pass>: users kept=N skipped_synthetic=M` line — counts, never ids) and `message_owner_expr` (per-turn `metadata.user_id` first, then session owner). Every `*_for_all` batch pass (dreaming, consolidation, music taste, portrait) filters through it; the nightly digest does NOT (its selection must match its independent input probe). `proactive/recipients.py::proactive_recipients` is the recipient rule for the morning brief / evolution digest (default panel binding ∪ owners of a user turn in 7 days; the evolution digest is then `admins_only` — `auth.is_admin_role`, fail-closed — because its approve/defer links are `require_admin`) and the evening wind-down + emotional follow-up (`include_panel_members=False`), minus synthetic ids — never select recipients by `chat_sessions.created_at` (a session's open time is not activity; that silenced the brief from 09-11). Pinned by `tests/test_user_filters.py`, `tests/test_proactive_recipients.py`, `tests/test_proactive_trigger_pg_interval.py`, `tests/test_emotional_followup.py`. Record: `docs/knowledge/synthetic-users-and-proactive-recipients.md`.

### ZD83 Proactive spoken delivery

- Proactive spoken delivery ("Zoe speaks first", W2): `proactive/presence.py::panel_presence` (read-only primitive — panel_id of a fresh `is_foreground` `ui_panel_sessions` row for the user within `ZOE_PRESENCE_WINDOW_S` (900 s), else None; `panel_presence_tier` returns `(owner|bound_guest|absent, panel_id)` — `bound_guest` = a fresh `guest`-owned row on a panel whose `panel_user_bindings` `default` names the user (the kiosk reclaims the row 300 s after the owner goes quiet; without it the 07:30 brief was refused `panel=none` from 08-16). **`bound_guest` is "the member's panel is on", not "the member is there": the adapter speaks ONLY the trigger's non-sensitive `context["spoken_guest_safe"]` line (first name, no calendar/loops/memories) or nothing; the full brief stays in push + proactive_pending.**; errors read as absence; `last_seen_at` is TEXT so queries cast `::timestamptz`) + the `_maybe_speak_notification` adapter in `proactive/engine.py::fire_notification`, gated by `ZOE_PROACTIVE_SPOKEN` (default OFF, read per call) with trigger allowlist `ZOE_PROACTIVE_SPOKEN_TRIGGERS` (default `morning_checkin`). When flag ON + trigger allowlisted + presence hit, the composed message goes to TWO independent lanes: (1) a `panel_announce` via `ui_orchestrator.enqueue_ui_action` — the kiosk TOAST, whose browser-TTS attempt is a bonus and whose ack now reports the true audio outcome (`event_data.result.tts` in the ledger; the kiosk guest's `/api/voice/speak` 401 is exactly why this lane alone produced silent "success"); (2) the **daemon announcement queue** (P-W2.3, `voice_announce.py` + `voice_announcements` table, migration `0025`) — the lane that reaches the SPEAKER. The Pi voice daemon polls `GET /api/voice/announcements` (device-token ONLY: `_require_voice_auth` + `source=="device"`; guests AND browser sessions are rejected — the daemon is the sole consumer) which claims rows atomically (`delivered_at` NULL→set, rowcount-checked; poll overlap can never double-speak) and marks TTL-expired rows (`ZOE_ANNOUNCE_TTL_S`, default 120 s) `expired=1`, never returning them — a stale "good morning" at noon is never spoken. Claim is panel-alias-tolerant by default (presence records the BROWSER panel id, the daemon holds the DEVICE token id — the #817 alias-mismatch class; `ZOE_ANNOUNCE_STRICT_PANEL` opts into exact matching; rows of a `voice_announce.PANEL_SCOPED_TRIGGERS` trigger — brief-on-arrival's private full brief — always require the exact match). The claim response carries server-computed `expires_in_s` so the Pi clock is never compared to the Jetson's. **Contract: spoken delivery is ADDITIVE, never a replacement — the push is always still sent; a failure in either lane must never block the push OR the other lane (the adapter never raises; it logs one `PROACTIVE_SPOKEN` line with per-lane outcome); flag OFF is byte-identical behaviour.** Pinned by `tests/test_proactive_presence.py`, `tests/test_proactive_spoken.py`, `tests/test_proactive_spoken_daemon_queue.py`, `tests/test_voice_announce_queue.py`; the daemon-side poll/defer/expire logic lives in `scripts/setup/zoe_voice_announce.py` (stdlib-only, deployed next to the daemon) pinned by `tests/test_voice_announce_daemon_logic.py`.

### ZD84 Brief on arrival

- **Brief-on-arrival (B2.1, flag-dark): `proactive/arrival.py`.** Needs `ZOE_PROACTIVE_BRIEF_ON_ARRIVAL` AND the master `ZOE_PROACTIVE_SPOKEN`, both read per call. With either off, every entry point returns before any DB access or task. It speaks today's stored `morning_checkin` text once, at the member's first `owner` presence between 07:00 and 11:00 local, on the panel where they were seen, through the shared two-lane `engine._speak_on_panel`. The hook is `routers/ui_actions.py::_note_owner_presence`: the member's own foreground bind/sync; guests and device tokens are ignored. It runs as a background task and never raises into the request. **Once per member per local day, across BOTH paths, is the `proactive_responses` claim, never process memory.** It is a UNIQUE row on `(user_id, claim_key, local_date)`, `claim_key = morning_brief_full` (migration `0030`). With the flag on, the 07:30 owner-tier full brief takes the same claim in `_maybe_speak_notification` (`arrival.claim_scheduled_brief`; a lost claim logs `outcome=already_spoken`; a claim DB error FAILS CLOSED, `outcome=claim_error`: the push still goes, the full brief is not spoken). With this flag AND `ZOE_BRIEF_ON_FIRST_TURN` off, that path takes no claim and does no DB work; with only `ZOE_BRIEF_ON_FIRST_TURN` on it reads the claim and never takes it. A failed speak is not retried. **The arrival row is panel-scoped** (`voice_announce.PANEL_SCOPED_TRIGGERS`): only the daemon whose device-token panel matches may claim it, even in claim-any mode. A presence panel with no live device token gets nothing queued (`outcome=unscoped_panel`). The claim's `announcement_id` is linked in the announcement insert's own transaction (`_speak_on_panel(claim_id=…)`). Other gates: not quiet hours (`engine._is_in_quiet_hours(now)`); not synthetic or guest (`user_filters`); none of today's briefs opened in chat; nothing from today played except a known guest teaser (an unrecognised text counts as heard); nothing still queued; no member user turn in 2 min. Logs `PROACTIVE_SPOKEN trigger=morning_checkin_arrival … tier=owner missed=…`. The slow loop's `evaluate_pending_responses` writes the B2.2 signal: `accepted`, `ignored`, `undelivered`, or `unknown` when no announcement is linked, never `undelivered` in that case. The window is `ZOE_PROACTIVE_ARRIVAL_RESPONSE_S`, default 120 s. Face/voice matches do not raise presence yet (voice-path, replay-gated). Pinned by `tests/test_proactive_brief_on_arrival.py`; record: `docs/knowledge/synthetic-users-and-proactive-recipients.md`.

### ZD85 Brief on first turn

- **Brief on the first turn of the day (flag-dark): `brief_first_turn.py`.** `ZOE_BRIEF_ON_FIRST_TURN` (default OFF, per-call read). No unprompted spoken brief: on a real member's (`user_filters`) brain turn inside `ZOE_BRIEF_WINDOW_START`–`ZOE_BRIEF_WINDOW_END` (default 05:00–12:00 local), when today's `morning_brief_full` claim is free and the day context (`morning_checkin._build_morning_context(include_board=False)`, items decided in code: events whose STORED end (`end_time`, else start + `duration`) has not passed, open loops, ≤1 emotional moment) is non-empty, a `[Today]`…`[END Today]` block rides into THAT turn — Flue lane after the user's words with the household date in the label (`[Today 2026-09-29]`, because Flue never elides and a session can outlive a day) (`run_flue_brain_streaming`, like continuity), core lane as a `_CONTEXT_BLOCKS` entry before the utterance (mirrored in `memory.ts`). Greeting/open turns (`turn_shape`, phrase-gated, never the model) get the full list; any other turn gets one line only for an event within 2 h or an overdue loop, else nothing. Continuity turns defer it. The SHARED claim (`arrival.claim_full_brief`, `trigger_type=brief_first_turn`) is settled in each lane's stream `finally` (shielded): taken once any reply text went out, even if the stream then errors, disconnects or is cancelled by a barge-in; a turn with no text (error before the first token, the fallback), an empty day, outside the window or a deferred command turn never take it. With only this flag on, the 07:30 spoken path checks the claim read-only and queues WITHOUT claiming (queueing is not delivery); a 07:30 brief the daemon ACKed as PLAYED (`played_at`, migration `0032`, `POST /api/voice/announcements/{id}/played` → `voice_announce.mark_played`; `delivered_at` is only the daemon's CLAIM, before playback) is claimed by the first-turn check when seen (`arrival.scheduled_brief_delivery`), and waiting on a queued/claimed row is bounded (TTL, + 180 s once claimed). The daemon claim holds a `morning_checkin` row while ANY of that member's conversational briefs is mid-reply (one hold per TURN, ≤120 s each; `settle` writes the claim BEFORE releasing its own hold and keeps it if the write fails) and suppresses it once the first-turn brief holds the claim (`brief_first_turn.scheduled_row_gate`, in-process — one uvicorn worker). Logs `BRIEF_FIRST_TURN user= items= shape= injected= claimed=`. Pinned by `tests/test_brief_first_turn.py`; record: `docs/knowledge/synthetic-users-and-proactive-recipients.md`.

### ZD86 Proactivity selector

- **Proactivity selector (flag-dark): `proactive/selector.py`.** `ZOE_PROACTIVE_SELECTOR` (default OFF, per-call read; off = no I/O). Nightly (dreaming phase 1.6, `memory_digest.run_dreaming_cycle`) it ranks ≤5 `proactive_candidates` per real member (migration `0033`) from due open loops, recent emotional rows and 48 h events by `importance × recency × relevance` in code (formula in the module docstring; no model call), upserting so cooldown/count/session survive. At runtime both lanes `prepare` before the turn and `settle` in the stream `finally` (shielded, surfaced only once reply text went out): ONE `[RAISE …]` block per conversation on a greeting turn (`brief_first_turn.turn_shape`) or a cue-word turn that is not a deterministic intent, and per member at most `ZOE_PROACTIVE_RAISE_PER_DAY` (default 2) a local day at least `ZOE_PROACTIVE_RAISE_GAP_S` (default 7200, capped at the 3-day cooldown) apart — durable evidence is the candidates' `last_surfaced_at`, plus an in-process per-member hold while a raised turn is unsettled (logged `reason=gap|daily_cap|held`); never with the `[Today]` brief (the brief wins), on a continuity turn, or for synthetic ids (`user_filters.is_synthetic_user`; harness `demo_<tag>_<hex>` ids only via the internal `POST /api/proactive/selector/run-synthetic/{id}` Samantha-bar S5 hook). Flue: after the user's words, and the contact offer defers that turn; core: a `_CONTEXT_BLOCKS` entry mirrored in `memory.ts`; both pairs in the elide tables. Candidates must pass `open_loop_quality.loop_is_concrete`; its anchors are the cue words. Logs `PROACTIVE_SELECT` / `PROACTIVE_RAISE`. Pinned by `tests/test_proactive_selector.py`; record: `docs/knowledge/synthetic-users-and-proactive-recipients.md#proactivity-selector-flag-dark`.

### ZD87 No memory for unidentified turns

- **No durable memory for an unidentified turn (2026-10-14).** `user_filters.is_unidentified` (every `GUEST_USERS` sentinel and any `guest-<id>` principal, case/space-insensitive) is the ONE test. `MemoryService.ingest` / `record_candidate` / `review(edit)` of a guest-owned row refuse it (`guest_drop`, log `GUEST_MEMORY_DISCARD`), and the turn lanes skip their writers up front (`voice_tts._run_voice_memory_passes`, `chat._persist_memory_candidates_impl`, `run_turn_digest` - no model call, `extract_and_ingest`, both person extractors, suggestions, the voice `people_introduce` contact, `_save_portrait`). DISCARD, not hold: an unrecognised voice's words cannot be re-attributed to a member without proof. In-session conversation history is not durable memory and is untouched; `struggle_events` keeps its deliberately anonymised guest row. Existing guest rows: `scripts/maintenance/guest_memory_report.py` (report; purge only on the owner's say-so). Pinned by `tests/test_guest_memory_no_write.py`, `test_guest_memory_report.py`.

### ZD88 Dates roles and corrections

- **Dates, roles, corrections (2026-10-04): `date_locale.py`, `people_roles.py`, `correction_apply.py`.** `date_locale` is the ONE place a numeric date's order is decided (day-first from `ZOE_TIMEZONE`; `ZOE_DATE_ORDER` overrides) — never parse `7/8/1991` anywhere else; extractors, digest/consolidation prompts, the reminder grammar and the brain turn all call it (unflagged). `people_roles` refuses a role the user never tied to a name (unflagged) and holds the neutral roster reply (`ZOE_ROSTER_NEUTRAL_ASK`, flag-dark). `correction_apply` (`ZOE_CORRECTION_APPLY`, flag-dark, reached from `fast_tiers.resolve`) applies "the date is wrong" / "X is their dog" to the STORED rows and says what changed. An explicit same-session correction ("it's actually a bike shop, not a pike shop", `correction_pair` / `maybe_fix_recent`, run BEFORE the store-wide `maybe_swap`, which then acts only when `global_swap_allowed`: a relation said, or no correction cue) rewrites THIS member's rows of THIS session (last 30 min) holding the old phrase via `review(edit)` - only a same-SHAPE value pair (`same_shape`: equal word count <= 3, no verb/auxiliary, time vs time; a clause is never a value) and only rows whose own `source_excerpt` is one of the member's last two turns and states the old value (never a blind token swap), and is kept in process per (member, session) so the deferred turn digest of an EARLIER turn of that session stores the corrected value (`correct_fact`; the correcting words lead the evidence so the excerpt cap keeps them, and the extractor's claim row is rebuilt for the new value or dropped - `correct_claim`) - never across identities, never for a guest. Pinned by `tests/test_date_locale.py`, `test_roles_not_guessed.py`, `test_correction_apply.py`, `test_correction_same_session.py`; record: `docs/knowledge/contacts-people-memory.md#dates-corrections-and-roles-2026-10-04--three-conversation-quality-classes`.

"What's up?" / "anything for me?" / "what have I got?" (whole-utterance, `pull.PULL_PHRASES`; "what's new" stays a greeting so bar S5/S12 and day-sim 1r/7r/7s are untouched) is a deterministic tier in `fast_tiers._pull_tier` (VOICE-PATH file: replay-gated): delivers every pending item once, salience order, Zoe's voice (second person), marks them like a raise (count, cooldown, session; compare-and-set so overlapping asks deliver once), spoken <= 3 with the rest left pending, chat all + a one-tap row (`zoe.component` Welcome/Fine/Not now = the next turn's words); empty = "Nothing new for you right now." ### ZD91 Restraint in code

- **Restraint in code: `restraint.py`** (register item BP1; person-likeness SAL3/SAL6/SAL7; blueprint law L3 *withhold, do not instruct*). `ZOE_RESTRAINT` = off | **shadow (default)** | enforce, per-call read. A sensitivity class (health, money, family_conflict, grief, other_member, affect) decided in code (structured signals first, an English word list second), stored (memory-row metadata `sensitivity`/`_v`/`_h`; threads in `restraint_classes`, migration 0042; invalidate, never delete) and REMOVED from the recall packet (`routers/memories.py`), the `[Today]` brief (`brief_first_turn`) and the `[RAISE]` pick (`proactive/selector.py`) unless the turn pulls it (a topic overlap, a named class, a mood statement for feelings, an open question like "what's up?"); a bare greeting is not a pull. A spoken mute ("don't mention that again", "leave it") is a `restraint_mutes` row with provenance and no words, honoured by all three surfaces, released by "you can mention it again", acknowledged by code in enforce (`run_flue_brain_streaming`, the Flue lane). Back-off from the ledger's `outcome` (doubling, pause after three unanswered); the guest rule (`speaker_verified is False`, bound in `voice_tts.voice_command`) withholds sensitive classes whatever is pulled. Fail-open everywhere except the guest rule. **Never add a "do not mention" line to a prompt: remove the material.** Doc + limits + operator steps: `docs/knowledge/restraint.md`; tests: `tests/test_restraint.py` (ci_safe), `tests/test_restraint_checkout.py` (Jetson lane). **Enforce-ready (2026-10-09, `docs/knowledge/person-half-enforce-pack-2026-10-09.md`):** the WORDS are data - `lexicons_data/<lang>.json` "restraint" (en pre-move + widening, es/fr/de/zh/ja author-written `reviewed:false`), compiled by `restraint_lex.py`; `restraint.py` holds no word list (`tests/test_restraint_lexicon.py` pins it, English byte-identity included, and measures the class recall on held-out sets: the word list ALONE is 63 % class-exact, NOT the 90 % the ledger asked). **Semantic head (2026-10-12):** `restraint_head.py` + `models/restraint_head.{npz,json}` (6 logistic units, ~10 KB, on the bge-small embedding `semantic_router` already holds; trained by `scripts/maintenance/train_restraint_head.py` on the DEV split only) is UNIONED with the word list and structured signals in `classify_full(head=...)`: it can only ADD a class, never loads a model (inert unless `semantic_router._MODEL` is in memory), embeds only on the write path (`stamp`) and the nightly thread pass, and the hot read path (`row_classes`) answers from its in-process cache only. Measured by `scripts/perf/restraint_eval.py` (dev / held-out split, fixture `tests/fixtures/restraint_labelled.json`): held-out 61.6 % -> 90.8 % class-exact; `VERSION` is 3. The head runs only on POSITIVE English evidence (`restraint._head_applies`: the detector says en AND the text has an English-only marker word or an English contraction; the detector's hit count is not evidence, so Dutch / Afrikaans / German never reach the English head), and a text deferred before `semantic_router`'s model loads is parked (bounded) and retried, not dropped (`restraint_head.retry_pending`). Doc: `docs/knowledge/restraint.md` "Semantic head"; tests `tests/test_restraint_head.py`. The always-present user-model card is filtered at serve time in enforce (`restraint.filter_card_items`: money / grief / family trouble off, the Health line reduced to the lexicon's `health_safety`). A spoken mute is recorded on the core lane too (`zoe_core_client.run_zoe_core_streaming`). `exact_words.lookup` applies the guest wall and the mutes (`restraint.filter_extra`). `scripts/perf/person_half_enforce_ab.py` is the enforce-vs-shadow rig (in-process, live brain, per-run env).

### ZD93 Recall relevance gate

- **The recall relevance gate: `recall_gate.py`** (register item BM4; blueprint 2.8, the SillyTavern World Info *semantics*, no AGPL code). `ZOE_RECALL_GATE` = off | **shadow (default)** | enforce, per-call read. Per turn it decides WHICH durable rows enter the recall packet (`routers/memories.py` `memory_for_prompt`) and the personalisation hop (`personalisation_hop.build`) and in what order: entity/key/clock triggers derived from the row at write time (`gate_t`/`gate_v`/`gate_h` stamped in `MemoryService._build_metadata`, per-language words in `lexicons_data/<lang>.json` `recall_gate`, no English in the code), the floor's similarity hit as one signal (a distance floor), `sticky`/`cooldown`/`delay`, a 400-token budget and a stable (admission) order, authority respected (inferred rows never stick; guests never; an off-record turn abstains; a pool row must pass `restraint.decide`). `shadow`: the packet is byte-identical (proved over a seed set), the gate runs in the background and logs one `RECALL_GATE user= served= would_add= would_drop= budget=` line per turn; `enforce` swaps in its selection; every failure falls back to the floor. The Flue seam calls `recall_gate.note_turn` once per turn. VOICE-PATH (`zoe_flue_client.py`, `routers/memories.py`): replay-gated.
