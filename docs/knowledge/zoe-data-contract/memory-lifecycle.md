# zoe-data contract detail: Memory write, forgetting and maintenance

Each section below is the **full text, verbatim**, of one bullet of `services/zoe-data/AGENTS.md` as it stood before the 2026-10-18 DOX pass (roadmap task B10). The short binding form lives in the contract and links here. If the two ever disagree on a rule, the contract bullet wins and this record is stale; record new rationale and measurements here, never new rules. Part of the [bundle index](index.md).

### ZD124 Ambient memory ownership

- `ambient_memory` rows always carry the owning `user_id` (migration `0017`): the `/api/voice/ambient` write path files a segment only under its OWN speaker's identification (a server-gated, consented voice claim, or the caller's own signed-in session — never the panel's member, owner or last sign-in, never `guest`) and otherwise neither transcribes nor stores it (never store ownerless audio; contract in `routers/AGENTS.md`); the `ambient_search` MCP tool filters on the caller's resolved user unconditionally (`tests/test_ambient_memory_scoping.py`).

### ZD125 Extraction mines user turn only

- Per-turn extraction mines the USER turn only — never feed the assistant reply (or a combined transcript) into `memory_extractor`, `person_extractor`, or `person_extractor_llm` as fact-source text. Zoe's own sentences stored as user facts poison the recall packet (live bug 2026-07-07: "…but I don't have a specific favorite recipe noted for you right now." became an approved memory). Pinned by `tests/test_memory_extractor_purity.py` (extractor contract + AST lockdown of the chat/voice call sites).

### ZD126 Anaphoric capture

- Anaphoric capture: `memory_extractor.extract_and_ingest` keeps an in-process per-(user, session) last-USER-message LRU and passes it to `extract_candidates` as `prev_user_message`, anchoring entity-less corrections ("I meant saturday not friday") and pronoun-subject facts ("she's a doctor" after a person introduction) to the prior user turn. Fail-closed: no prior turn / no matching old value / gender-mismatched pronoun → store NOTHING (never a guessed anchor). Only USER-authored text may enter the LRU (same purity contract as above). Pinned by `tests/test_memory_extractor_anaphora.py`.

### ZD127 Memory opt out

- Memory opt-out (`user_prefs.py`): the per-user `memory_opt_out` flag lives in the existing `user_preferences.prefs` JSON (alembic `0001`) — `user_prefs.py` is the ONE reader/writer of that dict. **Single-key writes are ATOMIC**: `set_pref` is one `jsonb ||` upsert and `delete_pref(only_if=…)` one conditional `jsonb -` update — never a read→modify→write of the whole dict (an opt-out PUT racing a Telegram link would silently drop one of them; the Telegram link/unlink/redeem paths in `routers/user_profile.py` + `routers/system.py` use these). `write_prefs` (whole-dict replace) is for bulk paths only. `GET`/`PUT /api/memories/opt-out` toggle the flag; it is ENFORCED at the `MemoryService.ingest` chokepoint for every AUTOMATIC source (`user_prefs.MEMORY_OPT_OUT_SOURCES`: `chat_regex`, `turn_digest`, `conversation` (person extractors), `ambient`, `digest`, `consolidation`, `synthesis`, `music_digest`) — a chat/voice turn fans out to four writers, so a per-writer guard is never enough; a new automatic writer adds its source string to that set. The reconcile UPDATE path (`svc.review(decision="edit", actor=<automatic source>)`) hits the same wall and returns None — every caller must treat None as "no edit happened" (reconcile callers fall through to `ingest`, which drops; weekly consolidation counts only non-None edits, so its summary never reports refused merges). Explicit teach/ingest sources (`brain_tool`, `voice_fact`, `review_ui`, `proposal`, notes/people/journal) are unaffected; flipping the flag never purges past memories (`POST /api/users/{id}/forget` does). Lookup is fail-open (a pref-read error captures as before) and cached 30 s per user, invalidated by any write through `user_prefs`; a read in flight across an invalidation never stores its result (generation guard), so a PUT can't be shadowed by a stale False. Pinned by `tests/test_memory_opt_out_endpoints.py` (`ci_safe`: runs the REAL `MemoryService` over an in-memory collection, never mempalace/chromadb, which the slim lane lacks; clears the module-wide pref cache around each test so a verdict never leaks into later tests in the same process).

### ZD128 Cross writer supersession

- Cross-writer supersession (QA review F9): EVERY conversational memory writer — `memory_extractor.extract_and_ingest`, `person_extractor._ingest_to_mempalace`, `memory_digest.run_turn_digest` + nightly `run_memory_digest`, `expert_dispatch._ingest_or_supersede` — routes through the shared `memory_quality.reconcile_for_ingest` ADD/UPDATE/SKIP decision (search + entity guards — namesake / third-person-name protection — + `classify_against_existing`) instead of blind-ADDing near-duplicate or contradicting rows. UPDATE supersedes via `svc.review(decision="edit")`; SKIP writes nothing; the helper NEVER raises — any reconciliation error degrades to ADD so a fact is never lost. New writers must call the same helper, not reimplement the guards. Pinned by `tests/test_cross_writer_supersede.py`. **Fail-open observability (QA concern #4):** the ADD-on-timeout/empty/error tradeoff (duplicates over lost facts) stays, but every fail-open ADD is now COUNTED via `memory_metrics.record_reconcile_failopen(cause)` — `zoe_memory_reconcile_failopen_count{cause=search_timeout|empty_results|search_error}` on `/metrics` (cause distinguished by elapsed vs the 15 s search budget) — with a 300 s sliding-window watcher that trips `sustained` (≥20/5 min) and escalates the reconcile log WARNING → ERROR. Surfaced at admin `GET /api/system/memory-reconcile/failopen-status`; PromQL alert rule in `docs/knowledge/incident-runbook.md` §3. Any new fail-open branch must call the same recorder. Pinned by `tests/test_reconcile_failopen_observability.py`.

### ZD129 Semantic search unfiltered first

- **Semantic search falls back when the owner-filtered HNSW query is short** (`memory_service._semantic_search`, 2026-10-04): hnswlib explores `ef` candidates, skips deleted and disallowed ones and stops, so on a tombstone-heavy index (demo churn: 1,591 elements for 258 live rows) a sentence query returned 0 rows WITH the owner filter and 18 without — the packet carried no hits and the brain said it had nothing stored. A short-result trigger was not enough (the filtered query can come back FULL BUT WRONG), so the search queries UNFILTERED first (`max(limit×20, 200)`, capped at the collection size), applies the same `_memory_visible_to_user` / status / expiry rules in Python, and runs the owner-filtered query only as a supplement when the visible rows are still fewer than `limit`; the blend ranks as before. Log line `MEMORY_SEARCH_SUPPLEMENT user= unfiltered_visible= limit= filtered_added=`. The tombstone cause still wants `scripts/maintenance/compact_drawers_index.py`. Pinned by `tests/test_memory_search_fallback.py`.

### ZD130 Drawers index compaction

- **In-process drawers index compaction** (`memory_service.compact_drawers_index_sync`, route `POST /api/memories/maintenance/compact-index`, internal token, flag-dark `ZOE_MEMORY_INDEX_COMPACT` default OFF → 404; owner decision Q12 2026-10-04): rebuilds `mempalace_drawers` from its STORED embeddings without a restart — export (count + dims verified) → JSON export + tar backup under `~/.zoe/palace-backups/` → delete → create in the SAME `hnsw:space` (read from the collection config, metadata fallback, `l2` default = the live palace) → re-add in batches of 100 → verify (count; unfiltered reach for the probe sentence == count; an owner-filtered query returns rows; a metadata update round-trips). Failure BEFORE the delete aborts with no change (structured: `status="aborted"`); the delete itself sits INSIDE the guarded region with `changed=True` marked BEFORE it is attempted (chroma's SegmentAPI removes the segments before the sysdb row, so a delete that raises may already have destroyed data), and any failure from there on restores from the export (`_restore_drawers`: delete-if-listed — absent, partial or broken — then create + re-add) and the 500 body says `restored`. **The gate reopens ONLY after a verified restore** (count == exported); otherwise it stays closed — `_MAINTENANCE_BLOCKED` (`maintenance_state()`, `status="blocked"`), every opener/lease call fails FAST with the reason instead of waiting, `index-health` reports `maintenance_blocked` + `maintenance_reason` + the backup paths, the weekly trigger refuses and exits 1, and the operator restores the tar with zoe-data stopped (runbook §22; a restart or `clear_maintenance_block()` lifts it). **The maintenance gate is the load-bearing part:** `_MAINTENANCE_OPEN` (a `threading.Event`, SET in normal operation) is waited on INSIDE `get_drawers_collection` — not only `MemoryService._collection()` — because `zoe_agent.py` calls the opener directly, and the opener's fallback CREATES the collection as `cosine` when the name is missing, which would race the rebuild into the wrong space. While the swap runs every opener call blocks (bounded, `_MAINTENANCE_WAIT_S` = 60 s → `MemoryServiceError`); the compaction thread talks to the cached client directly and never through the opener. **The gate alone only stops NEW openers** — `_run_sync` runs on the default multi-threaded executor, so an op already holding a handle could still be mid-flight when the gate closes (a write between the export and the delete would be lost; a later one would hit a stale collection id). Hence the **lease** (`collection_op`, reader/writer-lock semantics): `_run_sync` wraps EVERY executor call in it (`_leased_call`), the direct opener user outside the service (`zoe_agent.migrate_mempalace_legacy_records`) wraps its whole read-modify-write, the ASYNC digest passes (`memory_digest._resolve_pending_person_links` / `_rem_reinforce_pass` / `_deep_sleep_pass` / `_synthesis_pass`, which run chroma calls on the event-loop thread with `await`s between them) go through `leased_drawers(svc)` — a per-call proxy that takes the lease, opens a FRESH handle and releases it when the call returns, so no handle is ever held across an `await` (a compaction landing between two calls is fine: the next call opens the rebuilt collection), and `MemoryService._collection()` is never called directly from outside `_run_sync` (pinned by a source lockdown), admission is re-checked under `_OPS_COND` so nothing slips in after a clear, and a leased thread skips the gate inside (`_OP_THREAD.depth`, re-entrant). The compaction closes the gate, then **drains** `_ACTIVE_OPS` to zero (`_MAINTENANCE_DRAIN_S` = 30 s) BEFORE exporting and aborts with no change if it cannot; it runs via a bare `run_in_executor`, never `_run_sync` (it would wait for itself — guarded). Export columns go through `_as_list` — chroma 1.5.x returns `get(include=["embeddings"])` as a NumPy ndarray and `x or []` raises on it. One compaction at a time (`_COMPACT_LOCK`) — a second call, or in-flight work that does not drain within the budget, is `status="busy"` → 409 (the route maps on `report["status"]`, never on message text). Log line `MEMORY_INDEX_COMPACT before= after= elements_added= seconds=`. Nothing is cached per collection (client + EF caches stay valid across the swap). `GET /api/memories/maintenance/index-health` (internal token, read-only SQLite + pickle, never waits on the gate) is the tombstone report shared with the operator script via `memory_index_health.py` (stdlib only — scripts import it under any interpreter); `elements_added` = the pickle's `total_elements_added` + ADD/UPSERT records in the write-ahead log (`embeddings_queue`) above the vector segment's persisted `max_seq_id` — chroma writes the pickle and that row together, only every `hnsw:sync_threshold` (1000) records, and purges the WAL only below `min(max_seq_id)` with `COALESCE(…, -1)` for a never-persisted segment, so a just-rebuilt or small index (`fresh=True`, informational) is COUNTED from the WAL, never assumed to be ratio 1.0; when neither source can tell, `tombstone_ratio`/`compaction_advised` are `None` (`ratio_known=False`) and `tombstone_ratio` is never `inf` (live=0 → `None`; Starlette's `JSONResponse` is `allow_nan=False`). Weekly trigger = `scripts/maintenance/zoe-nightly-dreaming.py` (scripts/AGENTS.md): health on `ZOE_MEMORY_INDEX_COMPACT_DAY`, POST when advised OR when the ratio is unknown with live rows (at most once per period — never an indefinite skip), refuses + exits 1 when `maintenance_blocked`, treats a 409 as skipped-not-failed, never a rebuild from that process. `index_health()` runs through a bare `run_in_executor`, NOT `_run_sync` — it is read-only and is what an operator calls DURING a compaction to watch it, so it must never wait on the gate. Pinned by `tests/test_memory_index_compaction.py` + `tests/test_memory_index_health.py` (fakes, no chroma).

### ZD131 Physical erase of forgotten text

- **Forgotten text is physically erased** (`memory_residue.py` + `memory_service.erase_residue_sync` / `MemoryService.erase_rows`, flag `ZOE_MEMORY_PHYSICAL_ERASE` default ON, 2026-10-06; owner rule "forgotten means forever"): a Chroma API delete removes the row and leaves the text in SQLite free pages and in-page slack, the FTS5 trigram index, the `embeddings_queue` write-ahead log, orphan HNSW segment dirs (chroma's `delete_collection` never removes them) and, rarely, HNSW heap residue — measured on the live palace with a synthetic canary (`docs/knowledge/forgotten-text-physical-erase.md`). `delete_user`, the entity / last-memory forget handlers (archive FIRST as the fail-safe, then `erase_rows`: only the caller's rows, content-free `forget_erase` tombstones, per-row audit trail removed, the entity sweep also takes pending / disputed / superseded / archived / rejected rows) and the compaction rebuild all run the erase UNDER the maintenance gate (`_maintenance_window`: `_COMPACT_LOCK`, gate closed, leased ops drained, reopened in a `finally`): queue blank + purge, FTS5 `rebuild`, `VACUUM`, orphan dirs, then a verify scan of the live files for the forgotten text's heads (a rebuild if text is still in an index file and `ZOE_MEMORY_INDEX_COMPACT` is on). Never raises; `ok=False` + a WARNING (counts only) if text remains. One-time scrub for an existing store: `POST /api/memories/maintenance/scrub-residue` (internal token, ~1 s on 63 MB). Verifier: `scripts/maintenance/memory_residue_check.py --token T [--also-scan DIR]` (byte-scans a COPY, counts only). Host heap scrub `ZOE_MEMORY_HEAP_SCRUB=1` (`mallopt(M_PERTURB)` when the palace opens, default OFF: process-wide, the voice STT shares the process; 5/60 -> 0/60 runs with residue on chromadb 0.6.3). ZMB cells `F5` / `F6` (REAL Chroma, capability `disk`) + control `physical_erase`. The removal lockdown in `tests/test_memory_loss_class.py` (`ci_safe`: it runs in the required `validate` lane - it sat unmarked and silently off until 2026-10-14) allows `_delete_ids` from exactly `delete_user` and `erase_rows`; its other allow-listed deleters each carry a reason, e.g. the forgotten ledger's own hash rows (`memory_forgotten.release`, `clear_pending` - the latter provably limited to the pending-marker digests, `test_forget_cascade_durable_retry.py`). Pinned by `tests/test_memory_physical_erase.py` (`ci_safe`, skips without chromadb; every claim has a flag-off negative control).

### ZD132 Identity is an account fact

- Identity is an ACCOUNT fact, never a recalled one (2026-10-05): `identity_facts.py` answers "what's my name / who am I / what do you call me / where do I live / what's my address" from `auth_users`/`users`/`user_preferences`(`preferred_name`, `home_address`)/`weather_preferences`/`system_preferences` — tier run by `fast_tiers.resolve` for the `chat`+`telegram` profiles only (`identity_tier`; voice keeps its scope gate), unflagged; registered accounts only (guests/harness ids fall through). `MemoryService.ingest`/`review(edit)` refuse a "user's name is X" assertion from every source NOT in the `identity_facts.DIRECT_USER_SOURCES` allow-list (so `chat_regex_fallback` and future labels are walled by default) (the nightly digest's contradiction pass superseded a genuine name with a transcript fragment naming a third person; `review(edit)` carries source/session forward, so the row looked like a regex write). An explicit first-person rename on chat/telegram ("call me Jay") writes `prefs["preferred_name"]` — the one field identity answers, the prompt line and the greeting read. `ZOE_IDENTITY_BLOCK` (default ON) adds a `[Today — household context]` block ("You are talking to <name>, a member of this household in <place>.") behind the `zoe-uid` envelope in `zoe_flue_client.py` (voice-scope file → replay gate; rides the pinned `[Today` family so stale copies are elided; one joined query, 0.3 s budget). `session_continuity.py` (`ZOE_STICKY_SESSION` default ON, `ZOE_STICKY_SESSION_MINUTES`=20) lets an id-less `/api/chat/` request continue the user's last `ask_` session — never a `web_` desktop session, never one with a turn in flight. Audit: `scripts/maintenance/identity_memory_audit.py --dry-run`. Reference: `docs/knowledge/identity-and-session-continuity.md`; pinned by `tests/test_identity_facts.py`, `test_identity_block_prompt.py`, `test_session_continuity.py`, `test_identity_memory_audit.py`.

### ZD133 Spoken arithmetic fast tier

- **Spoken arithmetic is a deterministic fast tier (2026-10-15): `calc_speech.py`.** One tiny closed-vocabulary recursive-descent parser (number words, digits, pi / e, symbols and words, squared / square root / percent of; NEVER `eval` / `exec` / `ast`, pinned by `tests/test_morning_transcript_fixes.py`) answers in speech ("Two plus two is four.", "That's about 2,857.14."). It is whole-utterance anchored: any word it does not know rejects the turn ("two plus two in French", "times are hard", "pi day" go on). The `fast_tiers.resolve` wrapper runs it (after `session_status`, every channel) with a bounded per-`user|session` last result (`WINDOW_S` 180 s) so a follow-up ("that one divided by 3.5", "times three") needs a recent sum; `intent_router.detect_intent` uses the same parser statelessly and `_execute_calculate` speaks its result. There is no panel card for it (none exists).

### ZD135 Session status voice answer

- **"Who is logged in / am I signed in" is a deterministic voice-lane answer (2026-10-14): `session_status.py`.** A whole-utterance-anchored tier in the `fast_tiers.resolve` wrapper chain (after `self_model`, `channel="voice"` only) answers from the TURN identity the voice lane hands it as `extra_ctx["scope_user"]` (`_scope_identity_user` in `routers/voice_tts.py`: fresh PIN / verified voice session / named speaker, never a stale binding, `None` = nobody): a member hears only their OWN name (+ the voice-session time left via `voice_session.seconds_left`, when one is open for them), a guest hears that nobody is signed in and how to sign in (PIN), and no other member is ever named. ### ZD137 Own words wall

- Memory OWN-WORDS wall (2026-10-06, `own_words.py`, `docs/knowledge/memory-own-words-wall.md`): a user turn is not always the user speaking. `own_words.analyze(turn)` (pure) splits it into the owner's own voice and pasted content (email headers, forwarded/`>`/`system:` lines, paste introducers, signatures, long or URL-heavy pastes, override phrases) plus third-person direct speech ("Dana says: I live in Hobart"); every text-mining writer reads `Own.masked` / `Own.text` only (`memory_extractor`, `expert_dispatch.store_fact`, `memory_digest` turn/nightly, `memory_idle_consolidation`, `person_extractor*`), `MemoryService.ingest` checks a per-turn MODEL writer's fact against the owner's part, and `is_storable_fact` refuses an instruction-shaped fact. Drops are reject-ledger `guard_pasted_content` / `guard_third_person_speech`; a paste leaves at most one `pasted_content` (model_from_turn) note; the recall packet renders it "something you pasted" and withholds instruction-shaped text. A NEW text-mining writer must call `own_words.analyze` first. Pinned by `tests/test_own_words_wall.py` (negative controls: `own_words.analyze` as a pass-through reproduces the leak).

### ZD138 Memory authority

- Memory AUTHORITY (2026-10-05, `memory_authority.py`, `docs/knowledge/memory-authority.md`; audit `docs/research/memory-fidelity-audit-2026-10-05.md`): who SAID a fact decides who may change it. Every row carries `authority_class` from an allow-list ranked operator 6 > user_confirmed 5 > user_stated 4 > user_stated_derived 3 > user_unverified 2 > model_from_turn 1 > model_from_transcript 0 (UNKNOWN writers rank 0), plus `authority` (user_stated|user_confirmed|inferred), `authority_basis`, `origin`, `turn_ref`, `model` - stamped at write time in `MemoryService` in every mode. ONE choke point (`ingest` / `review` edit|archive|reject|approve / `supersede_by` / `archive_duplicate`): a write whose class is below the user classes (rank < 3) and below the row's rank can never supersede, archive or contradict it - it becomes a `disputed` candidate (`contradicts_id`, never recalled, `review(approve)` by a person makes it `user_confirmed` and retires the disputed row) and logs `AUTHORITY_BLOCKED writer=<name> kind=<attr>` (labels only). A model writer earns `user_stated_derived` (rank 3, never overrides a direct statement) only when the user's OWN turn supports the fact (`supports`; pass `anchor_text` = USER turns only, never assistant text; the digest passes a verbatim `quote` via `memory_digest.fact_anchor`). `review(edit)` stamps the NEW writer and never inherits the old row's source/session/turn/excerpt. `ZOE_MEMORY_AUTHORITY=enforce` (default) | `shadow` (`AUTHORITY_WOULD_BLOCK`, no change) | `off`; every MCP review/forget passes `origin="mcp"`; `person_merge.merge_person(actor=)` is user-only; affective records (`emotional_moment`, feelings in metadata) are kept for EVERY household member INCLUDING children and NEVER for guests, no stored consent row (owner product decision 2026-10-05; governance note section 6): `ZOE_AFFECT_CONSENT_GATE=household|members|optin|off` - `household` is the DEFAULT (members incl. minors; guest sentinels `user_filters.GUEST_USERS` and an unknown/failed lookup refused), `members` = adults only (explicit stricter, fails open), `optin` = a stored `member_modes` row required (explicit stricter, fails closed; also what a typo falls to); `review(edit)` strips a feeling from edit metadata and does not carry one forward when the gate refuses. #1866's identity wall is the special case. Edges: migration 0037 (`person_relationships.authority/origin`), `person_extractor._write_relationship(authority=, origin=)`. A NEW writer must be added to the allow-lists in `memory_authority.py` (else rank 0) and to `tests/test_memory_authority_matrix.py`. Pinned by `test_memory_authority*.py` (writer x target-class matrix, `off` as the negative control). Held-back writes (`disputed`) are listed in `/api/memories/review`, asked about once via `pending_suggestions` (`memory_disputes.py`) and expire after 30 days to a logged STALE_DISPUTE. `user_unverified` has a hook (`speaker_verified=False`) the voice daemon does not feed yet. **Standing (2026-10-12, `has_standing`):** rank alone lets an equal-rank model row retire another (`may_override` is `>=`), so a write below the user classes whose `authority_basis` is `unanchored` (the writer READ the owner's words and they do not carry the fact) retires NOTHING - not through `supersede_by`, not through `review(edit)` (`_authority_refuses` / `edit_outranked`); the row is stored beside the old one and `expert_dispatch._ingest_or_supersede` logs `MEMORY_SUPERSEDE_REFUSED`, never a supersede that did not happen. `no_user_evidence` (a caller that offered no words) is deliberately not covered. Follow-ups: speaker gate wiring (P1.3, voice-path).

### ZD153 Verbatim evidence and recall

- Verbatim evidence: `MemoryService._build_metadata` is the ONE place `source_excerpt` is written — it PII-scrubs (`scrub_source_excerpt`, scrub BEFORE the cut; a hard reject drops the excerpt, never the fact) and caps at 400 chars, on ingest AND `review(edit)` (whose `source_excerpt=` replaces the carried-forward one). Writers therefore pass the whole user utterance (`memory_extractor.extract_and_ingest`, `run_turn_digest`, and the person extractors `person_extractor.process_text` / `person_extractor_llm.process_text_llm` via `apply_person_fact` → `_ingest_to_mempalace`, including their `review(edit)` supersedes), never a pre-cut slice. It is exposed in the owner-scoped `/api/memories` JSON (`_ref_to_dict`) and, only under the evidence flag below, in the prompt packet. **Evidence-bearing recall (flag-dark `ZOE_RECALL_EVIDENCE`, default OFF, per-call env read): `recall_evidence.py`** is rendered by the ONE packet builder `routers/memories._build_memory_prompt_packet` (so the Flue recall floor, the Flue `recall_memory` tool — which returns `/for-prompt`'s `packet` verbatim — the core lane and memory.ts all get it; the continuity packet never does). Each bullet gets ` (Mon 22 Sep, 8 days ago)` before its cite, in `ZOE_TIMEZONE`, from `added_ts` else `added_at`; a row whose EFFECTIVE writer (`reviewed_by` for an edit with `supersedes_id`, else `source`) is a batch pass (`digest`/`synthesis`/`consolidation`/`idle_consolidation`/`music_digest` — the nightly digest stores at ~03:00 over a 30 h lookback) gets NO date, and nothing is ever dated from a guess. On an evidence-shaped turn (`memory_gate.EVIDENCE_QUESTION_PATTERNS`: when-did-I / what-did-I-say / are-you-sure, table-driven) the first `MAX_QUOTES`=3 presented bullets with a quotable excerpt get ` — you said: "…"` (≤120 chars, the sentence sharing most content words with the fact, one line, brackets and double quotes neutralised, each utterance quoted once); quotable = effective writer in `chat_regex`/`turn_digest`/`voice_regex`/`voice_turn_digest`/`voice_fact`/`conversation`/`voice` (the last two = the chat/voice person extractors; `notes`/`journal` person rows keep the excerpt but are never quoted — a note is not something they SAID) (Skybridge stores a name or the fact, Hindsight appends refs — never "you said"). One instruction line follows the authority rule. The tool path cannot see the user's words (it sends the MODEL's query), so `_run_flue_brain_streaming_turn` calls `recall_evidence.note_turn(uid, message)` — an in-process per-user mark (single uvicorn worker), overwritten every turn, 300 s TTL — that `wants_quotes` also honours. Budget: the floor block keeps its 12-bullet / 1,600-char cap (`_truncate_packet`); evidence can push bullets out, and the cut always takes the least-relevant TAIL first (measured on a realistic full packet with quotes: 11 of 12 bullets kept; dates alone: 12 of 12). Measured with Gemma's tokenizer: +12 tokens per dated bullet, ~+30 for the instruction, ~+25-35 per quote. Each packet with the flag on logs `RECALL_EVIDENCE user=… quotes=… bullets=… dated=… quoted=… chars=…` at INFO. Flag off is byte-identical (pinned). Pinned by `tests/test_recall_evidence.py`; live probe `scripts/perf/recall_evidence_probe.py`.
