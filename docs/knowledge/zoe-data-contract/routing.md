### ZD11 SetFit and two stage router

- SetFit router head + two-stage router: `semantic_router.py` optionally loads the logreg head (shadow) and, via `router_two_stage.py`, the MLP head (both trained in `labs/setfit-router`; never import from `labs/` at runtime). Both go through `router_heads_numpy.load_head()`: the default `ZOE_ROUTER_HEADS_BACKEND=numpy` serves `models/router_head_{logreg,mlp}.npz` + `.json` with pure numpy — **zoe-data never imports scikit-learn/scipy/joblib** (pinned by `tests/test_router_heads_numpy.py`, which also holds sklearn parity ≤1e-6 on a committed 50-vector corpus fixture, a negative control, and a joblib-sha drift check); `joblib` is the one-release fallback that unpickles the `.joblib` training artefacts. The configured paths (`ZOE_ROUTER_HEAD_PATH` / `ZOE_ROUTER_HEAD_MLP_PATH`) stay the `.joblib` names; the numpy backend reads the pair beside them. A CUSTOM `.joblib` path (outside `models/`) with NO export beside it falls back to joblib for that head only (WARNING logged, sklearn imported) instead of disabling the head. A SHIPPED head (inside `models/`) with a missing export is an ERROR — the head is disabled, sklearn is never imported for it; a stale/tampered export always refuses. **Retraining a head means re-exporting it**: copy the new `.joblib` in, run `scripts/maintenance/export_router_heads.py --corpus --fixture services/zoe-data/tests/fixtures/router_heads_parity.npz` under the training pins, commit all four model files + the fixture (each export file is whitelisted in `.gitignore` by name). Flag `ZOE_ROUTER_HEAD` = `off` (default) | `shadow` (logreg head logs prediction/agreement, never routes) | `shadow2` (the FULL two-stage decision — MLP top-3 shortlist + 0.5 chat gate + grammar-constrained FunctionGemma sidecar on :11436 — computed in a background thread and logged, never routes) | `active` (the two-stage decision picks the domain; execution stays in expert dispatch; ANY sidecar failure/timeout/gate-abstain falls back to similarity → brain — the Gemma 4 brain remains the rock; this is a fast-tier front, proven 90.1%/0% chat-FP in `labs/router-90-campaign`). Sidecar unit: `scripts/setup/systemd/functiongemma-router.service`. Env: `ZOE_ROUTER_SIDECAR_URL`, `ZOE_ROUTER_TWO_STAGE_GATE` (0.5), `ZOE_ROUTER_TWO_STAGE_TIMEOUT_S` (1.5), `ZOE_ROUTER_HEAD_MIN_CONF` (0.70) — the **low-confidence floor**: a NON-chat head top with gate ≤ conf < floor abstains before the sidecar call → chat lane (brain + recall packet), logged `gated: true, reason: low_conf` (every gated decision carries `reason` = `chat_top` | `below_gate` | `low_conf`); `0` restores the pre-2026-09-28 behaviour; a value outside 0.0–1.0 (or unparseable) logs a WARNING and keeps 0.70; the Skybridge router gate treats `low_conf` as a chat verdict (veto), never as `router_unsure`; the value is MEASURED (table + regeneration recipe: `docs/knowledge/two-stage-router-rollout.md` → *Low-confidence floor*) — change it only with a new table. Real misroutes are fed back as committed rows in `labs/setfit-router/data/misses.jsonl` (stage 1) and `labs/functiongemma-finetune/data/train_misses.jsonl` (stage 2), never by editing the builder-regenerated train files. Pinned by `tests/test_router_low_conf_floor.py` (`ci_safe`; real shipped head on committed S1 embeddings — a head swap must regenerate that fixture). Rollback = `ZOE_ROUTER_HEAD=off` + restart. Logs — utterance HASH only, never raw text — go to logger `zoe.router_head_shadow` and `data/router_head_shadow.jsonl` (gitignored); score with `scripts/maintenance/router_shadow_report.py`. The file is **rotated, never truncated**: append goes through `_append_shadow_line`, which rolls the log to `<log>.1`/`.2`/… past `ZOE_ROUTER_SHADOW_MAX_BYTES` (16 MB) keeping `ZOE_ROUTER_SHADOW_KEEP` (4) segments — ~80 MB ≈ 1.7 years at the observed ~133 KB/day (0 disables). Truncation is NOT an option: the self-train miner reads the WHOLE history (`--since` defaults to 0), so dropping records in place would silently starve the mine→label→ratchet loop. **Readers MUST go through `semantic_router.shadow_log_segments(path)`** (oldest→newest) — the miner and both shadow reports do; anything reading only `<log>` silently sees just the newest slice. Pinned by `tests/test_router_shadow_rotation.py`. The training-pin agreement rule (scikit-learn/joblib = `labs/setfit-router/requirements.txt`) now binds the EXPORT step, not the runtime: the numpy heads do not depend on any sklearn version. zoe-data's manifests still pin `scikit-learn`/`joblib` only because librosa (Resemblyzer, speaker ID) declares them as install requirements — and, until the joblib fallback is removed, at the training pins so that fallback can unpickle. Voice-path files ⇒ replay-gated — and so is **`models/` itself**: `services/zoe-data/models/*` is a directory glob in `VOICE_PATH_PATTERNS`, because swapping a tracked head re-routes every voice turn with no code diff. Both heads are **hand-committed**; the `ZOE_ROUTER_SELFTRAIN` ratchet promotes only the stage-2 GGUF to `~/models/functiongemma-router/` (outside the repo) and covers **nothing** in this directory. Copy a promoted head in from `labs/setfit-router/artifacts/` (which stays ungated) and expect the PR/deploy gate to demand a fresh revision-bound replay artifact. Pinned by `tests/test_router_head_shadow.py` + `tests/test_router_two_stage.py` (`ci_safe`) and `tests/unit/test_voice_gate_check.py`. Public harness contract: `semantic_router.route_two_stage(text) -> RouterDecision` (dataclass: tool/args/confidence/source/latency_ms) — standalone with the sidecar up, no server; the 81-case corpus-through-prod-path harness ships separately against it.

### ZD18 Research web lookup honesty

- Web lookup for research turns (B10.0): `research_evidence.py` + `web_search_provider.py`. `fetch_web_fallback` returns a `WebFallbackOutcome` (`status` ∈ results/no_results/blocked/error/off, `provider`, rows) — a DuckDuckGo challenge page (HTTP 202 + `anomaly-modal`, or a captcha/Cloudflare body at ANY status; `classify_ddg_response`, `DDG_BLOCK_MARKERS`) is `blocked`, NEVER `no_results` — but a page WITH `result__a` links is a results page even if a snippet or the echoed query mentions a wall phrase (markers are consulted only once result links are absent); `no_results` is a POSITIVE verdict that needs DDG's empty-results shell (`class="no-results"`, `DDG_EMPTY_RESULTS_MARKERS`) — any other anchor-less 2xx body (blank, truncated, consent/maintenance, markup change) is `error` with detail `unrecognised page (HTTP n)`. `build_package(..., web_lookup=...)` carries that status in the package (`web_lookup`) and renders an honest "Web lookup unavailable" / "Nothing found" row instead of a fabricated `duckduckgo.com/?q=` source. Provider order is `ZOE_WEB_FALLBACK_PROVIDER` (per-call env read): `auto` (default) = Tavily first when `TAVILY_API_KEY` is set and `ZOE_SEARCH_PROVIDER` is not `ddg` (`tavily_search_outcome`, status-aware; `tavily_search_sync` is the bare-list compat), then DDG; the best-quality verdict is kept — `results` beats everything and a completed Tavily `no_results` is NOT overwritten by a later DDG `blocked`/`error` (provider `tavily`, DDG's attempt in `detail`); `duckduckgo` forces the scrape; `off` makes no request. `fetch_web_fallback_results` is the bare-list compat shape `zoe_agent._ddg_search_sync` still consumes and is deliberately DDG-ONLY (`_web_search_ddg` already ran Tavily itself; going through `auto` would spend a second credit). A Tavily HTTP 200 without a `results` list is `error`, not `no_results`. `routers/chat._build_research_package` skips `_capture_research_screenshot` only when the rebuilt package has NO source at all (lookup failed AND the reply cites no URL; a reply's own URL is still captured whatever the lookup outcome) — otherwise the capture's `default_source_for_query` fallback would navigate to a DuckDuckGo URL, so `off` would still send the query out and a search-page image could be shown as evidence of a failed lookup. One INFO line per lookup (`web_fallback: provider= status= results= query_len=`) — never the query text. Backend status surface: `research_evidence.web_lookup_status()` (resolved `provider`, raw `configured`, `tavily_key_present`, in-process `last_outcome` {status, provider, detail, at} — never the query or the key) is served as the `web_lookup` block of `GET /api/system/status` (`routers/system.py`); the config fields go to every caller, `last_outcome` only to a signed-in non-guest (it is process-wide activity, `_web_lookup_block_for`). Pinned by `tests/test_web_fallback_honesty.py` (mutation-checked negative controls).

### ZD19 Brain callable web search

- Brain-callable web search (B10.1, FLAG-DARK): `ZOE_WEB_SEARCH_TOOL=1` (per-call env read; `research_evidence.web_search_tool_enabled`) serves `POST /api/system/web-search` (`routers/system.py`, same `require_intent_dispatch_auth` gate as intent-dispatch; body `{query, max_results≤5}`) = `fetch_web_fallback(…, WEB_SEARCH_TOOL_PROVIDER_TIMEOUT_S, enrich_prices=False, deadline_s=WEB_SEARCH_TOOL_DEADLINE_S)` + `web_search_tool_payload` (the outcome fields verbatim + ≤5 title/url/snippet rows, nothing else from a row). The 3s provider timeout is per socket OPERATION, so the lookup runs on ONE monotonic end-to-end budget (`WEB_SEARCH_TOOL_DEADLINE_S`, 6s) shared across Tavily → DDG: the second provider gets only what is left and is never started once it is spent (`detail` says so), and the endpoint answers `status=error` / `detail=timeout…` at the deadline (`asyncio.wait_for`) instead of waiting on a slow-drip provider. No per-row page fetches. The budget must stay under the sidecar's `WEB_SEARCH_TIMEOUT_FLOOR_MS` (8s) — pinned from both sides; B10.0 callers pass no deadline and keep 8s/provider + price enrichment. Off (default) → 404 and the lookup is never called. The Flue sidecar's `web_search` tool (`labs/flue-zoe-brain-2x/src/tools/zoe-tools.ts`, `optionalZoeTools()`) is registered only under the sidecar's OWN copy of the flag and is a thin wrapper over that endpoint — a 404 is reported to the model as "switched off on this box". Trust boundary (W15, enforced in the SIDECAR, `src/untrusted-content.ts`): results reach the model fenced (fixed untrusted-content preamble + delimited block, markup/control tokens/role markers neutralised, fields capped, http(s) links only) and a turn that received results refuses every state-changing tool AND any further `web_search` (an outbound exfiltration channel) until it ends — zoe-data returns the rows as data and must not pre-render them into prose the fence would not cover. `web_lookup_status()` carries `tool_enabled`. Never log the query. Pinned by `tests/test_web_search_tool.py` (caplog tripwire with negative control) and the sidecar's `test/web_search_tool.test.ts`.

### ZD63 WebSocket role policy

- **WebSocket role policy — one rule, every socket (`main._ws_role_signed_in` / `_ws_channel_forbidden`, 2026-10-08).** zoe-auth's roles are `admin`, `user` (the DEFAULT for every ordinary account), `family_member`, `child`, `guest`, passed through verbatim by `auth._normalize_auth_user`; `member` is zoe-data's own name for degraded pass-through sessions. Admins can also CREATE arbitrary roles (`api/admin.py::create_role`), so signed-in is decided by EXCLUSION — a real identity (not the `guest` sentinel) with a non-empty role that is not `guest` — never by enumerating roles. `/ws/push` and all six `/api/{lists,calendar,people,reminders,notes,journal}/ws/{user_id}` sockets admit every signed-in role; only `auth.is_admin_role` (honours `family-admin`) or `agent` may subscribe on another user's `{user_id}` channel, everyone else only their own (journal lacked this check until 2026-10-08). Every `{user_id}` socket registers with the broadcaster under the REQUESTED channel owner, not the session user — scoped broadcasts filter by the registered id, so a delegated admin socket registered under itself received nothing. Until this rule they accepted only member/admin/agent, so every real `user` account was closed 1008 on every socket and reconnected forever. Never inline a role tuple in a socket handler — extend the two sets. Pinned by `tests/test_ws_roles.py` (`ci_safe`, with the actual default role end-to-end). Panel push (`main._resolve_subscribable_panel`): a VALID guest session (`_is_ws_guest`) uses its bound `ui_panel_sessions` row when it has one, else falls back to exactly the session-less policy (`panels.allow_guest` + `is_active`) via `_resolve_bound_panel` / `_panel_allows_guest_push` — so the member to guest reclaim window (300 s, `routers/ui_actions._PANEL_RECLAIM_STALE_AFTER_S`) cannot deafen a non-home touch page; it only ever returns a panel channel, never a user channel, and a non-guest member still needs a bound row (`tests/test_push_panel_session.py`).

### ZD64 Panel push liveness

- **Panel push liveness (2026-10-12): `push.py`.** `PushBroadcaster.panel_subscriber_count` / `panel_push_status` / `panel_live` / `warn_if_panel_deaf` (+ module `push.panel_live`). A voice turn whose panel channel has zero subscribers logs ONE WARNING per `DEAF_PANEL_WARN_INTERVAL_S` (called via `voice_tts._warn_if_panel_deaf`, in its own try so it can never skip a broadcast); `GET /api/panels/{id}/push-status` (`routers/panel_config.py`, unauthenticated, counts + timestamps only: `subscribers`, `last_(dis)connect_at`, `deaf_turns`, `deaf_for_s`, `deaf_alert`) feeds `zoe_ground_truth.sh` (which prints a DEAF ALERT line). A panel deaf for `DEAF_PANEL_ERROR_AFTER_S` (300 s, measured from its last disconnect or process start) while voice turns keep arriving also logs one `PANEL DEAF` ERROR per `DEAF_PANEL_ERROR_INTERVAL_S` (600 s); the server never reloads the kiosk. `panel_live` = a subscriber, or a `success` ack (`ui_actions.ack_ui_action` → `note_panel_ack`) within `PANEL_LIVE_WINDOW_S` (60 s); **any voice line that sends the person to look at the panel ("check the panel", "tap Done/Confirm") must go through `voice_tts._panel_can_see` and otherwise say the result aloud** (`_list_add_reply_text`, `_calendar_form_reply_text`). With a dead panel NO form is queued and the reply never claims a write (the insert happens only on Done): "I haven't added X yet". The stream path always ends the screen's turn (`_finish_panel_screen` in `_generate_voice_stream`: full-text `show_card`, then `voice:done`, scheduled from the `finally` on barge-in/disconnect/error) and never slices `voice:responding`/card text. **Liveness is not identity:** the push socket that shows a form is unauthenticated, so the form is bound to the member it was presented for (`panel_form_state.set_active_form(..., owner_user_id=)`, set by `_broadcast_action_form_panel` from `effective_user`; the panel's own `/panel/form/open` keeps the owner) and `ui_actions.confirm_action_form` returns 403 (`confirm_is_misattributed`) for a GUEST Done unless the live form is bound to `guest` — a member's form, a form with no owner, and NO form at all (past `_FORM_TTL_S`, zoe-data restart) all fail CLOSED rather than save under `guest`; a signed-in member is never refused here; `/panel/form/open` binds the caller as owner of an unowned form (`adopt_owner`), so a guest-opened form stays the guest's to save. Pinned by `tests/test_push_panel_status.py`, `tests/test_voice_stream_screen.py`, `tests/test_panel_form_confirm_owner.py`.

### ZD65 Biometric ownership scoping

- **Biometric ownership scoping (MANDATORY for any new biometric endpoint): `biometric_scope.py`.** `_require_voice_auth` is AUTHENTICATION only — device token OR any non-guest session — so on its own it let any signed-in household member list, re-target, or DELETE another member's voiceprint/faceprint. The authorisation half lives in ONE shared module used by BOTH biometric routers so they cannot drift: `require_person_scope(caller)` → `(user_id, is_admin)` and 403s a device token (a shared panel credential owns nothing; its only feed is the device-token-only `/profiles/sync`); `authorize_profile_access(owner, caller, is_admin, kind=…)` enforces **404-before-403** (unknown id → 404, someone else's id → 403 — the order `routers/proactive.py` + `routers/lists.py` use); `resolve_enroll_target(payload_user_id, caller)` forces a session caller to enrol ITSELF (enrolling under another `user_id` is identity takeover, not a bad row) while a device token still enrols the person at the panel. Admin power is EXPLICIT and fail-closed via `auth.is_admin_role` (honours the `family-admin` alias; a non-string role is never an admin) — never an inline `role == "admin"`, which misses the alias. Listing is scoped in the SQL, not post-filtered. Retention/deletion policy of record: `docs/knowledge/biometric-retention-policy.md` — keep it in step with this code. Pinned by `tests/test_biometric_ownership_scope.py` (`ci_safe`).

### ZD156 Skybridge command not keyword

- **The Skybridge fast path (`skybridge_service.classify_skybridge_intent`) claims a COMMAND or a QUESTION, never a bare keyword inside a statement** (live over-claim 2026-09-28: "…just get updates from the family." → "I found 0 contacts."; same class as #1150). The people branches (directory show, name search, `remember that…` fact write) require an imperative/interrogative anchored at the START (after wake-word/filler/politeness — `_SHAPE_LEAD`/`_SHAPE_POLITE`) with the noun as the verb's object (`_PEOPLE_DIRECTORY_ASK_RE`, `_PEOPLE_NAME_SEARCH_RE`, `_PEOPLE_FACT_SHAPE_RE`); a new people phrasing is added THERE, never as another `any(term in text …)`. The calendar/lists/weather keyword fallbacks stay loose on purpose — Moonshine drops leading wh-words ("That's on my calendar" = "What's on my calendar" in real transcripts) — and are covered by the router veto instead. **Router veto:** `resolve_skybridge_request(router_decision=…)` defers to the ACTIVE two-stage router (`skybridge_router_gate`): when it picked `chat` or an incompatible domain (`_ROUTER_AGREEING_DOMAINS`), Skybridge returns `handled: False, vetoed: True` BEFORE any auth challenge or side effect and the turn goes on to the brain; logged `SKYBRIDGE_GATE router= conf= skybridge= action= decision=allow|veto reason=`. Allowed without a verdict: router off / similarity-only (`router_unavailable` — the similarity router has no music/smart_home examples), a stage-1 abstain under the 0.5 chat gate on a real domain (`router_unsure` — ONLY `reason: below_gate`, or a record with no `reason`; a `low_conf` abstain from `ZOE_ROUTER_HEAD_MIN_CONF` is a deliberate send-to-the-brain verdict and VETOES, otherwise the Samantha-bar S1 shape with a calendar cue gets a deterministic calendar reply), a card-context follow-up the router cannot see (`context_followup` — EXCEPT a reply to the new-list naming prompt, which captures the whole reply as the name, so a reply that OPENS with a hesitation/refusal marker (`_NAMING_REFUSAL_RE`: actually, wait, not now, never mind, cancel, let's not, maybe later, … after optional filler) is not exempt and gets the router's verdict — deliberately narrow, since "Things to do" / "Books I want to read" are real names), a domain the router has no class for (`voice`). `router_decision` defaults to `UNGATED` (touch taps, card buttons, the brain-tool card builder — unchanged); conversational lanes pass the turn's `semantic_router.route()` dict or `ROUTE_ON_DEMAND`. Flag `ZOE_SKYBRIDGE_ROUTER_VETO` (default ON; `false/0/off/no` = pre-fix behaviour). Pinned by `tests/test_skybridge_router_veto.py` (`ci_safe`, with negative controls).

### ZD157 Everyday command shapes

- **Everyday command shapes are read ONCE, in `command_shapes.py`, by both deterministic matchers (2026-10-14, measured by `tests/test_ha_phrasing_corpus.py`).** Pure/stdlib. **The default is INVERTED for destructive and later-time commands:** a timer cancel / change and a list remove / tick-off ACT only on an allow-listed shape (`allowed_timer_cancel`, `allowed_timer_adjust`, `plain_list_item`; any cancel- or change-cue (`CANCEL_CUE`, `CHANGE_CUE`) outside the list - an ordinal, "other", a subset, a qualified quantifier, a negation, "except", a conjunction, an unknown word - is a status read, never a write), and a device command with ANY time cue (`_TIME_CUE_RE`) is never run now - except a trailing sign-off clause, which modifies nothing ("…, see you tomorrow", "… and good night": `_without_trailing_pleasantries`; a clause that points back, "…, do it tomorrow", still counts); a NEW destructive phrasing is added to the allow-list, never handled by loosening the fallback. Pinned by the property sweeps in `tests/test_everyday_commands_p0.py` (hundreds of verb x modifier x object variants). (1) Durations incl. halves/quarters/decimals (`parse_duration_seconds`; "half an hour" = 1800, Skybridge `_parse_timer_duration` delegates). (2) A change to a RUNNING timer (`timer_adjust`, `timer_pause_resume`) is checked BEFORE the timer create/cancel/status rules: Skybridge `timer/increase|decrease` moves the ONE timer meant (`_TimerStore.find`: by name AND/OR the length it was SET for - `set_seconds` - or the only one running; a described name fits the only UNNAMED timer; several running and nothing says which = ask, never guess; never past 0 or 24 h; no amount in the words = ask how much; receipted); `timer/pause|resume` answers honestly that it can't (the panel has no paused timer) - none of them EVER creates a timer, and `intent_router.detect_intent` claims none of these shapes (its list patterns used to read them as list writes). `timer/cancel` uses the same `find` (a bare cancel with several running asks; "cancel all timers" cancels all; it no longer falls back to the soonest). A question or statement about a timer (`asks_or_mentions`: "should I…", "why did you…", "I was going to…"; "can I…" for a change/cancel) is a STATUS read, never a write. The panel learns a moved end on its next `GET /api/skybridge/timers` poll (≤ ~25 s). (3) A device/playback command for LATER (`delayed_command`: "in 5 minutes", "at 10pm", "when I get home", "tomorrow" - day words/conditions only in the command's own clause or a later clause that points back at it ("…and do it tomorrow"); "for 20 minutes" is a command for NOW that lasts; music PLAY uses `strict` - explicit amounts/clock times only, since titles say "tonight" - while transport verbs ("stop the music tomorrow") do not) becomes `<domain>/delayed` (Skybridge) / `smart_home` action `delayed` or `music_play` slot `delayed` (intent_router) and gets `DELAYED_COMMAND_REPLY` - nothing runs now and nothing is queued (no scheduler for device commands exists). A tile tap (exact entity id) is always now. (4) The loose list/calendar read fallbacks match WHOLE words (`_LIST_KEYWORD_RE`, `_CALENDAR_KEYWORD_RE`); "play" must OPEN a music command (`_command_shaped`); a % of speed/position/colour is not a dim (`_NOT_BRIGHTNESS_RE`); intent_router's light action reads the FIRST clause, OFF words first, and a light QUESTION is not a command. (5) Lists: remove/complete accept "on|in <list>" endings and a NAMED list ("my chores list" → `list_name`; demonstratives and typed words are not names; a named list that does not exist is "I could not find that list", never the default); a pronoun is never an item; a question/statement about removing or ticking off writes nothing; "is milk on the list" is `lists/contains`, answered yes/no first (`_list_contains_answer`). (6) Politeness / wake words (lexicon `command_filler`, HA's skip words minus the first-person "I need/want to", which turns statements into commands) are stripped and the match RETRIED only when the words as said matched nothing (`conversation_cues.strip_command_filler`; `_filler_retry` on both matchers), so an existing claim never changes. Pinned by `tests/test_everyday_commands_p0.py` (`ci_safe`, with break-the-fix controls).

### ZD158 Router head authority intent gate

- **The router head is the authority over every deterministic KEYWORD claim (INTENT_GATE, 2026-09-28).** Samantha bar S1 ("Who is flying in on Thursday, and where from?") was routed to chat by the two-stage router (people @ 0.5371, `low_conf`) and then answered anyway by the chat.py keyword lane: `^who is (.+)$` → `people_search` → `No contacts found for "flying in on thursday, and where from".`.
