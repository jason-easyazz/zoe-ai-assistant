### ZD46 User selectable voice

- User-selectable voice: `voice_settings.py` — the persisted HOUSEHOLD voice preference (`app_settings` key `tts_voice`, migration `0018`; user-scoped prefs stay in `user_preferences`) + the voices-bin catalogue (`ZOE_KOKORO_VOICES` NPZ namelist — stock `af_*` etc. plus operator-installed `zoe_*` blends; the UI never hardcodes names). Resolution per synth call in `tts_waterfall.py`: explicit override → persisted pref (5s in-process TTL cache, fail-open to env on any DB error) → `ZOE_KOKORO_VOICE`/`af_sky`. API: `routers/voice_settings.py` (`GET /api/voice/voices`, `PUT /api/voice/voice`, `POST /api/voice/preview` — preview text is SERVER-FIXED, never caller-supplied, so the kiosk-reachable endpoint can't become a free-text TTS proxy). Panel: skybridge `voice` intent (`skybridge_service._resolve_voice_settings`, household-shared like clock/music — no identity gate) → `voice_settings` card. The sidecar phrase cache is voice-scoped (`<voice>|<text>` keys in `scripts/setup/kokoro_sidecar.py`) so a voice switch can never replay stale audio in the old voice; pre-scoping persisted entries just miss and age out. Pinned by `tests/test_voice_settings.py` (`ci_safe`).

### ZD47 Voice capability helpers

- Voice capability helpers: `tts_waterfall.py` (TTS engine mechanics — Kokoro sidecar, Edge TTS, espeak-ng, speech-text cleaning; the in-process ONNX singleton/fallback is RETIRED — there is no in-process TTS model, synthesis is the Kokoro PyTorch sidecar over HTTP with the Edge/espeak-ng fallbacks; the waterfall ORDER is policy and stays inline in the `routers/voice_tts.py` handlers, pinned by `test_canonical_invariants.py`), `stt_wake_strip.py` (Moonshine wake-word strip from #854), `voice_speaker_id.py` (speaker-ID embedding/similarity mechanics), and `voice_delivery.py` (W11 expressive delivery — a PURE deterministic mapper from reply text + wall-clock hour to a Kokoro `speed`, flag `ZOE_EXPRESSIVE_TTS` default OFF; `tts_waterfall._synthesize_kokoro_sidecar` adds `speed` to the payload ONLY for a non-neutral profile, so flag-off is byte-identical. **Neutral is `None`, never `1.0`, and utterances at or under `ZOE_EXPRESSIVE_MIN_CHARS` (60) are never touched** — the sidecar phrase cache serves only at speed 1.0 (~2ms vs a 1-2.5s cold synth), so every slowed utterance is one that stops being cacheable; the short-text guard is what keeps confirmations/acks/fillers on the fast path. W4 prosody is blocked behind the W3 RAM gate, so valence/arousal is not an input yet — when it lands it joins this mapper rather than replacing it. Pinned by `tests/test_voice_delivery.py` (`ci_safe`), whose load-bearing cases are the negative ones). `routers/voice_tts.py` re-exports their symbols so importers and monkeypatching tests keep targeting the router module. `conversation_opener.py` — flag-gated (`ZOE_CONVERSATION_OPENER_ENABLED`, default OFF, read per call) "let's talk / let's chat" session-opener fast-path: pure allowlist matcher + warm ack + fire-and-forget LiveKit warmup, wired as an early return in the `/ws/voice/` handler in `main.py` AND in `/api/voice/turn_stream` (the real panel lane: the Pi daemon holds the conversation, sends `conversation: true` on each turn so enders are honoured, and reads `conversation_mode` / `conversation_end` off the done frame) — never enters the brain, like `voice_presence` wake acks. `broadcast_conversation_turn` pushes the ack to the panel as `voice:responding` + `voice:done` carrying the same flag, because the fast path returns before `voice_command`, which is where every other turn's panel text is broadcast (contract in `routers/AGENTS.md`). Live-activity strip: the `/ws/voice/` brain lane filters brain `__TOOL__`/`__THINKING__` sentinels through `routers/voice_tts._forward_voice_activity` (never spoken) and forwards tool start/result as `{"type": "activity", "phase", "tool"}` frames — name+phase only, args/results never cross the wire (`tests/test_voice_activity_frames.py`).

### ZD48 Moonshine STT loader

- Moonshine STT loader (`routers/voice_tts._ensure_moonshine`, warmed by `warm_moonshine` — the CANONICAL loader marker, do not rename): the call shape (`get_model_for_language` → `Transcriber` → `transcribe_without_streaming`) is identical on moonshine-voice 0.0.62, 0.1.3 (pinned + live since 2026-09-27) and 0.1.5, so the loader is written for ALL of them and feature-detects the one optional step — `ZOE_MOONSHINE_KEYTERMS` (comma-separated, `env_list`, default EMPTY = off) is applied once via `Transcriber.set_keyterms` right after the singleton loads, only if the installed package has that method (never version-gated: 0.0.62 reports `__version__ == "0.1.0"`). Biasing is best-effort — an unsupported or refused list logs a WARNING and the rock keeps its transcriber; a real load failure still raises. State surfaces at `/readyz` `dependencies.stt.keyterms`. Pinned by `tests/test_moonshine_keyterms.py` (`ci_safe`, fakes the module). The package pin in `requirements.txt` follows the box (header rule); the upgrade/replay/rollback runbook is `docs/knowledge/moonshine-0-1-5-upgrade.md`. Any change here is replay-gated.

### ZD49 Spoken rhythm pacing guard

- Spoken-rhythm pacing + guard: the streaming voice path (`routers/voice_tts._generate_voice_stream`) synthesizes one Kokoro utterance per sentence THE INSTANT a sentence closes in the buffer, so the /synthesize cadence tracks brain-delta ARRIVAL one-for-one. Flue 1.x paced deltas token-by-token; Flue 2.x (`ZOE_FLUE_WIRE=2`) flushes them in time-BURSTS, so a burst spanning ≥2 sentence boundaries fires synth back-to-back (rushed) then stalls — the "less natural rhythm" regression (measured 2026-08-10). `_pace_delivery` floors the gap between consecutive spoken sentences at `ZOE_VOICE_TTS_MIN_SENTENCE_CADENCE_MS` (default 0 = OFF/ship-dark; timed AFTER synthesis so the knob is the true delivery cadence; first-audio never paced), a no-op on a smoothly-paced stream. `voice_cadence_guard.py` is the stdlib-only instrument that scores a turn's /synthesize schedule (delivery timestamps + char-lengths) against the recorded band `tests/fixtures/voice_cadence_baseline.json` — load-bearing metric RUSH FRACTION (share of sentences delivered <80ms apart), because the replay gate stops before TTS and is BLIND to rhythm. ci_safe negative control `tests/test_voice_cadence_guard.py` (bursty→red, even→green); live capture `scripts/perf/measure_tts_cadence.py`. Advisory only — no automated gate hears rhythm; the operator's ear is the check.

### ZD50 Speaker identification

- Speaker identification (W5): endpoints in `routers/voice_tts.py` — `/api/voice/enroll` (consent-stamping: `consent: true` sets `speaker_profiles.consent_at`, migration `0023`; un-consented rows are stored but never matched/synced), `/api/voice/identify` (server-side cosine, consented rows only), and `GET /api/voice/profiles/sync` (DEVICE-TOKEN-ONLY feed of consented embeddings + the server threshold for on-Pi matching — never expose to browser sessions). Panels that match locally send `{voice_user_id, voice_score}` on `/api/voice/command`; acceptance is decided server-side by `_accept_panel_voice_claim` against `ZOE_SPEAKER_ID_THRESHOLD` (per-call env read, default 0.82) — a panel claims, the server decides, and the accepted claim enters the existing `identified_user_id` precedence (P-F6 guards unchanged). Profile list/delete are ownership-scoped — see the biometric-scope bullet below. Pinned by `tests/test_voice_profile_sync.py` (`ci_safe`). **Memory contract:** server-side embedding (`voice_speaker_id.py`) is RARE (enrol, and identify only when a client sends raw audio) and resemblyzer pulls torch (~+568 MB on first use), so nothing may import `resemblyzer`/`torch`/`transformers` at module import — `import main` stays free of them — and the encoder is ONE cached, lock-guarded, CPU-pinned `VoiceEncoder` (never the CUDA default: no GPU context inside zoe-data). Pinned by `tests/test_speaker_id_lazy_load.py` (`ci_safe`); measurements in `docs/knowledge/resident-memory-hygiene-2026-09-27.md`. **Guarded profile adaptation (flag-dark, `ZOE_SPEAKER_ADAPT=off|shadow|on`, default off — migration `0048`):** `speaker_adaptation.py` (policy authority; numpy only) + `routers/voice_speaker_adapt.py` (`POST /api/voice/adapt`, device-token-only; `DELETE /api/voice/adaptation` resets the caller's own adapted profile). The panel daemon (`SPEAKER_ADAPT_SEND`) offers a high-certainty turn's embedding (never audio); the server re-derives the score and applies every guard (score ≥ 0.85, still near the enrolled anchor, ≥ 2 s speech, server-verified corroboration — panel bound / fresh login session / face claim, margin to every other member, rate limits, drift bound ≥ 0.92 cosine to the anchor) before an EMA step (α 0.05). `speaker_profiles.embedding_blob` stays the immutable ANCHOR (only an enrolment moves it); the adapted profile is `adapted_blob`, invalidated by a re-enrolment via `adapted_from_count`, and the existing profile DELETE removes both ("forget my voice"). `/profiles/sync` and `/identify` serve it ONLY in mode `on` (`serve_adapted_profiles`; any other mode is byte-identical to before). Shadow logs the would-be update and writes nothing; the audit line is `zoe.speaker_adapt`. Never loosen a guard to make the numbers look better; measure with `scripts/perf/measure_speaker_adapt.py`. Pinned by `tests/test_speaker_adaptation.py` + `tests/test_speaker_adapt_measure.py` (`ci_safe`); record in `docs/knowledge/biometric-retention-policy.md` §1. **Speaker-model identity (migration `0051`, `speaker_models.py`, flag `ZOE_SPEAKER_MODEL` = `resemblyzer` (default) | `dual` | `resnet34`, per-call, MIRRORED by the panel daemon):** every `speaker_profiles` row carries a `model_id` (NULL/empty = `resemblyzer`; ResNet34 = `wespeaker_resnet34+i8qdq-u8s8+c1` = model + quantisation + centring version) and profiles of different model_ids NEVER compare - sync serves per model and only what the panel names in `?models=` (none = Resemblyzer only), `/identify` filters on the query's `model_id`, `_accept_panel_voice_claim` honours a claim only in the ACTING model against that model's threshold (ResNet34: length groups 2 s or less / longer, `speaker_models.claim_threshold`), consent is checked per model, adaptation guards are per model (ResNet34 score 0.342 + anchor cosine 0.45) and only the acting model is adapted. `/enroll` takes either audio (Resemblyzer only; the server embeds) or a finished panel-built profile (`embedding_base64` + `model_id`, DEVICE-TOKEN-ONLY, validated, replaces that model's row and drops its adapted profile); the server never loads ResNet34. Forbidden: comparing, averaging or overlaying vectors across model_ids; reusing a model_id for a different file / quantisation / centring vector; accepting a claim outside the acting model. Pinned by `tests/test_speaker_models.py` (`ci_safe`, incl. drift against the panel module); runbook `docs/knowledge/speaker-resnet34-switch.md`.

### ZD51 Silero VAD and smart turn

- Silero VAD: `voice_vad.py` — streaming ONNX wrapper (lazy singleton session, per-stream `SileroVAD` state, 512-sample/32ms hops each fed with the previous hop's last 64 samples as upstream `OnnxWrapper` does — a 576-sample model input, pinned by `tests/test_voice_vad_context.py`; dropping the context silently degrades v6.0 and kills v6.2; `create_vad()` returns None on any load failure so callers fall back to RMS energy VAD). Powers LiveKit barge-in in `routers/voice_livekit.py`, gated by `ZOE_VOICE_BARGE_IN` (default OFF — flag off is the legacy half-duplex RMS path, unchanged). Tunables: `ZOE_SILERO_VAD_MODEL`, `ZOE_VAD_SPEECH_THRESHOLD` (0.5), `ZOE_BARGE_MIN_MS` (192), `ZOE_BARGE_SPEECH_THRESHOLD` (0.30). Both `voice_vad.py` and `voice_turn.py` are voice-gated (`VOICE_PATH_PATTERNS`), and the Silero model FILE (outside git — live = v6.0, md5 `00bdd414…`) is checked nightly by the probe's VAD stage: a model that loads but detects no speech is a silent failure (`create_vad()` only falls back to RMS on a load error) — test any candidate file with `ZOE_SILERO_VAD_MODEL=<candidate>` before swapping (docs/knowledge/incident-runbook.md §8). Smart-turn endpointing: `voice_turn.py` — smart-turn-v3.2 ONNX end-of-turn scorer (lazy singleton, degrades to None → fixed-silence endpoint), consulted at the silence window on the Silero path when `ZOE_SMART_TURN_ENABLED` (default OFF); a mid-thought verdict extends the listen, bounded by `ZOE_SMART_TURN_MAX_CHECKS` (2, fail-open). Tunables: `ZOE_SMART_TURN_MODEL`, `ZOE_SMART_TURN_THRESHOLD` (0.5). LiveKit pipeline failure paths (P-F3): the pipeline's `brain_oneshot` call is bounded by `ZOE_LIVEKIT_BRAIN_TIMEOUT_S` (default 20s; a timeout routes through the same apology path as any LLM error), and an empty transcript speaks a canned "Sorry, I didn't catch that." before returning to ambient (any feedback failure degrades to the legacy silent-ambient path) — `tests/test_livekit_failure_paths.py`.

### ZD52 Voice memory and event loop

- **Voice memory + event-loop contracts (B6.6):** `voice_turn.py` computes Smart Turn's Whisper log-mel in pure numpy (`log_mel_features`, bit-identical to transformers' numpy path) and must never import `transformers`/`torch` — transformers 5.x drags torch in (+~360 MB resident). Pinned by `tests/test_voice_turn_no_torch.py` (`ci_safe`) and `tests/test_voice_turn_logmel_parity.py` (host-only). Details: `docs/knowledge/voice-pipeline.md` (Smart Turn section).

### ZD53 WebRTC audio ingest

- WebRTC audio ingest: `livekit_aiortc.py` — pure-Python aiortc backend for the LiveKit room (selected by `ZOE_LK_USE_AIORTC=1`, which the Jetson sets because the bundled libwebrtc cannot init a PeerConnection on Tegra). `_AudioStream` resamples each track frame to 16 kHz / mono / s16 for the VAD. **Never extract PCM with `bytes(frame.planes[0])`** — FFmpeg over-allocates each plane to its SIMD alignment, so that returns the padded buffer, not the valid audio (measured on av 16.1.0 AND 17.1.0: 160 samples → a 448-byte plane for 320 valid bytes, 28.6% junk). The padding is not zero-filled: the resampler recycles its buffer pool, so it carries stale PCM from earlier frames (silent input emitted peak |sample| 32638), which both corrupts and time-stretches the stream fed to the VAD and STT. Use `frame.to_ndarray().tobytes()` (shape `(1, samples)` for mono s16). Pinned by `tests/test_livekit_audio_frame_bytes.py` (`ci_safe`), whose load-bearing case is the silence-stays-silent one.

### ZD54 First turn greeting

- First-turn-of-day greeting: `voice_greeting.py` — flag-gated (`ZOE_VOICE_GREETING_ENABLED`, default OFF, per-call env read) time-of-day greeting ("Good morning/afternoon/evening"). The **turn_stream** handler (`routers/voice_tts.py` `_wrapped`) emits it as its OWN leading spoken chunk (`{"chunk": -2, "provider": "greeting"}`) ahead of the answer — decoupled from the reply text (no UI-card pollution) and voice-only (NOT the shared `expert_dispatch`/chat core). Keyed by `panel_id` only (a single stable namespace — "first turn of the day at this panel"; mixing a per-turn speaker id would double-greet across key spaces), so it fires once per local day. The phrase (period form, e.g. "Good morning.") is pre-warmed in `kokoro_sidecar` `_WARM_PHRASES`, so it's ~instant. Last-greeted local date per key persists to `~/.zoe/voice_greeting_state.json` (`ZOE_VOICE_GREETING_STATE_PATH`), backed by an in-memory mirror so an unwritable store degrades to "at most one extra greeting per restart" (not every turn); all state I/O best-effort (any failure → no greeting, never breaks the turn). Variable-value TTS caching for weather/time (temp×desc×city, 1440 minute combos) is the separate segment-stitching follow-up. Pinned by `tests/test_voice_greeting.py` (`ci_safe`).

### ZD55 Segment stitched TTS

- Segment-stitched TTS: `voice_stitch.py` — flag-gated (`ZOE_VOICE_STITCH_ENABLED`, default OFF) engine that renders high-frequency TEMPLATED voice replies (weather/time) by concatenating cached, finite-vocabulary phrase segments instead of synthesising the novel full sentence. `weather_segments(temp:int, cond, city)` / `time_segments(h,m)` build ordered natural-phrase segments from a bounded vocab (0–100, weather conditions, hours, minutes, am/pm); `concat_wavs` joins 24 kHz / mono / 16-bit WAV PCM with a 70 ms gap (refuses a format mismatch → caller falls back to full TTS); `stitch(segments, synth)` synths each (sidecar-cache-backed) + concats. After a one-time `prewarm_vocabulary` (wired flag-gated in `main.py` startup, paced + best-effort) every segment is a ~2 ms cache hit, so ANY weather/time value stitches in ~7 ms vs ~2 s synth. **Wired live:** `stitch_reply(text, synth)` strictly matches the exact intent replies (time `"It's 7:42 AM."`, weather `"It's 14 degrees and clear in {city}[, with a top of 20 today]"` — both digit-form, converted to the word-form prewarmed segments), called in `routers/voice_tts.py` `_wrapped` (the dict-return path, before its per-sentence synth); any non-match / out-of-vocab / synth miss → None → unchanged full-sentence TTS (never emits guessed audio). Uses `ZOE_LOCATION_CITY`. Pinned by `tests/test_voice_stitch.py` (`ci_safe`).

### ZD56 Spoken weather answers

- Spoken weather answers: `weather_speech.py` — PURE classifier + speaker shared by the Skybridge lane (`skybridge_service._resolve_weather`, actions `current` / `today` / `forecast`; `SkybridgeIntent.query` = asked-for fact high|low|rain|outlook|current, `range_label` = today|tonight|tomorrow) and the expert/intent lane (`expert_dispatch._plan` → `intent_router._execute_weather_direct(focus, day)`), so they cannot drift. A question ("how hot is it going to get today", "what's the high", "how cold tonight") is answered with the asked-for number FIRST in whole degrees; plain current/outlook replies stay inside `voice_stitch`'s shape and append `, with a top of N today`. The classifier is deliberately scoped (subject must be `it`, tail limited to time/place scope words) so "how hot is the oven" is never weather. Data contract: `routers.weather._get_forecast` returns `today` (high/low/rain_chance/description — NOT in `daily`, which starts tomorrow) beside `hourly`/`daily`; a missing `today` degrades to the plain current reply, never an invented number. Provider asymmetry: Open-Meteo's `today.high/low` are the full-day range; OpenWeatherMap's are the REMAINING slots of the day (its 3-hourly list starts now), so a late-day OWM high can understate. Spoken forecasts cap at three days. Pinned by `tests/test_weather_today_outlook.py` (`ci_safe`).

### ZD57 STT under speech

- STT under speech: `voice_stt_stream.py` — flag-gated (`ZOE_STT_STREAM_UNDER_SPEECH`, default OFF, per-call env read) lane where the panel daemon uploads PCM16 batches to `POST /api/voice/stt_stream/chunk` (409 when off) WHILE the user speaks; a bounded session (2 sessions, 30 s of audio, 30 s idle TTL) feeds a Moonshine stream on its own worker thread under the shared `_moonshine_infer_lock`, and `/api/voice/turn_stream` takes the finished text via `_take_stt_stream_text` -> `_transcribe_audio(pre_text=)`. The WAV is still POSTed: the stream text is used only when its sample count equals the WAV's and it is non-empty; every other shape (seq gap, mismatch, unknown/reused id, timeout, engine error, empty) falls back to the unchanged batch STT, and speculative (B1.1) turns never take a stream. Streaming is not bit-identical to batch (about 7.6 percent word edits vs a 2.3 percent noise floor), so the replay A/B arm `ZOE_REPLAY_STT_UNDER_SPEECH=1` gates any flip. Numbers, enable/rollback: `docs/knowledge/prefill-under-speech-2026-10-10.md`. Pinned by `tests/test_voice_stt_stream.py` (`ci_safe`, break-the-fix control on the sample-count check).

### ZD58 Pre brain utterance gate

- Pre-brain utterance gate: `voice_utterance_shape.py` — pure, stdlib-only, per-language data (`_LANGS`, en + es) behind `gate_frame(payload, transcript, speculative=)`, called in `/api/voice/turn_stream` right after STT and BEFORE the `voice:transcript` broadcast / any brain work; it answers with a done frame instead of the brain and the router FAILS OPEN if it raises. (1) `{"done": true, "incomplete": true}` when the daemon sent `can_continue` and the transcript ends on a continuation word (`ends_incomplete`: and/but/because/or/... strong; that/which/que weak, only in a 6+ word non-question; fewer than 3 words, a `?`/`!` ending, a verb-final object-fronted question like "What symptoms does mold cause", "so"/"though" never): the daemon listens `ZOE_CONTINUE_WINDOW_S` and re-sends ONE merged clip marked `continued` (never held twice; kill switch `ZOE_VOICE_CONTINUATION_HOLD=off`, default on). (2) `{"done": true, "skipped": "not_addressed"}` for side speech in a no-wake-word window (`window` = `followup` | `conversation`; absent on wake turns and barge-in seeds), flag `ZOE_FOLLOWUP_ADDRESSED=off|on|strict`, default OFF (a typo is off): `on` drops only an utterance that names another person (a vocative) with no question/command shape and no "Zoe" (an acknowledgement does not override a vocative; the one exception is a bare short answer like "Yes, Casey." right after Zoe asked a question); `strict` also requires a 5 s follow-up utterance to look like a question/command/acknowledgement, answer a question Zoe just asked (`prev_reply_question`), or be 3 words or fewer. Speculative turns are never gated. Trade-offs, wiring and rollback: `docs/knowledge/voice-pipeline.md` -> *Long speech is one turn*. Pinned by `tests/test_voice_utterance_shape.py` (`ci_safe`, break-the-fix controls).

### ZD59 Mishear clarification

- Mishear clarification: `mishear_clarify.py` (flag `ZOE_MISHEAR_CLARIFY=off|shadow|on`, default OFF, a typo is off; one decision per turn via `evaluate(...)`, called in `/api/voice/turn_stream` right AFTER the utterance gate and BEFORE the `voice:transcript` broadcast; never on a speculative or `continued` turn; fails open). A SHORT (<=5 words) feeling-shaped line whose STT looks unreliable (`slow_stt`: STT wall time vs clip length, with a recent-median load guard; `sparse`) that the router sends to CHAT and that carries no explicit cue (distress hand-off, restraint affect/health/grief/family-conflict, risk cues, `lexicons_data/<lang>.json` `mishear_clarify.cues`) and no deterministic owner gets a spoken "Sorry, what was that?" (lexicon `mishear_clarify.phrases`, all questions so the daemon's follow-up window opens) INSTEAD of the brain: no transcript broadcast, no memory write. One clarification in a row (the next turn on that panel is answered whatever it is); `prev_reply_question` turns are never clarified; no Moonshine confidence is exposed (word timestamps need an attention decoder this deployment does not load). The router verdict computed on the way is handed to `voice_command` (`_router_decision` / `_router_text`) so it is not computed twice. One `MISHEAR_CLARIFY ...` metric line per short turn, never any transcript text. Doc: `docs/knowledge/voice-pipeline.md` -> *Mishear clarification*. Pinned by `tests/test_mishear_clarify.py` (`ci_safe`, paired negative controls).

### ZD60 STT snap

- STT snap (misheard-command recovery, 2026-10-14): `stt_snap.py` (flag `ZOE_STT_SNAP=off|shadow|on`, **default shadow** = decide + log + struggle note, nothing user-facing; read per turn), ONE stage in `routers/voice_tts.voice_command` right AFTER the conversation tiers and BEFORE the Pi hybrid / Skybridge / keyword-intent stages. It runs only when no deterministic matcher claims the words (`classify_skybridge_intent` with the panel context, then `intent_router.detect_intent`), they are not a question/statement about a write (`command_shapes.asks_or_mentions`), and the Tier-1.5 experts could not act on them (`expert_may_claim`, a conservative over-approximation of `expert_dispatch`'s gates). ONE of the first three words (`command_shapes.command_core`) may be swapped for a sound-alike from `lexicons_data/stt_snap_vocab.json` - GENERATED from the HA/OVOS corpus sentences the cascade claims correctly + the `command_shapes` verbs, drift-pinned (regenerate: `python3 tests/stt_snap_eval.py --write-vocab`); polarity/negation words are never swapped, a number word only as the first word; the words before the swap must already open a handled command; the snap needs exactly ONE resulting command (by intent + slots) in its domains (clock, weather, timers, lists, calendar, smart home, music - never people / memory / notes / panels / engineering) with a `MARGIN` over any other command AND over any likelier repair Zoe cannot serve. Safety: `read` and `act` (one light on/off, music play/pause/resume, one list item added, one new timer) continue AS the snapped words (their own receipt says the command back); every other write (cancel/delete/remove/complete, timer changes, scenes, brightness, volume, calendar, keyword-intent writes, all/everything, a plural device group, locks/doors/alarm/thermostat/...) asks "Did you mean: ...?" via `_PENDING_CONFIRMATIONS` (`stt_snap_text`); a "yes" makes the snapped words that turn's words so every later gate judges them, and `_router_decision` is recomputed on them (`stt_snap.route_for`). A speculative turn awaits the verdict before it acts or asks. Log: one `STT_SNAP from=<hash> to=<intent> outcome=...` line per snap, words only for a member (never a guest / a rejected voice). Struggle feed: `struggle_detector.note_snap` -> MISHEAR, fix `stt_snapped`. ### ZD61 Speculative turn start

- B1.1 speculative turn-start: `voice_speculation.py` — flag-gated (`ZOE_SPECULATIVE_TURN`, default OFF, per-call env read) server-side speculation gate for `/api/voice/turn_stream`. The panel daemon fires the turn at its FIRST end-of-turn verdict (`speculative: true` + `turn_id`); the gate is registered BEFORE STT (a verdict can never outrun it), forwards non-audible frames, HOLDS every audible frame (`chunk`+b64 line, `full_audio`, greeting/filler chunks) in order, and releases only on a `commit` or transcript-equivalent `resolve` verdict from `POST /api/voice/turn_stream/speculation`. `cancel`, a non-equivalent `resolve`, or the `ZOE_SPECULATIVE_MAX_HOLD_MS` (5000) valve drops the held audio, closes the upstream generator (its `finally` cancels the brain task) and ends the stream with `{"done": true, "cancelled": true}` — nothing audible for a cancelled turn, ever, and a committed turn is released exactly once. Every gated stream LEADS with `{"speculation": "gated", "turn_id"}` (`ack_frame`) — the daemon's proof the server is gating; never emitted with the flag off. An EMPTY speculative transcript (nothing processed) closes the slot and answers `cancelled` (`reason: empty_transcript`) DIRECTLY, bypassing `gate_frames`, so the daemon runs the full recording: it is an upstream fact, not a verdict, and the daemon's commit routinely wins the slot before STT returns (fire→commit ≈ 320-480 ms < a Moonshine pass) — through the gate a won commit would pass a plain `done` and the turn would be lost; the non-speculative empty path is unchanged. A verdict that lands before the router's generator was ever pulled (cancel during STT) still cancels the brain task: `gate_frames` primes a never-started upstream to its first yield before `aclose()`, because `aclose()` on an unstarted async generator skips the `finally` that cancels `sub_task`. `turn_id` is request-supplied: `open_gate` refuses an id whose gate is still unresolved (`DuplicateTurn` → 409) rather than replacing it. Flag off: the fields are never read (wire bytes identical) and the verdict endpoint is 409. Metric `zoe_voice_speculation_count{outcome=commit|equivalent|cancel|hold_timeout|empty_transcript}` — only `cancel` is a user interruption for the cancellation-rate gate. **Phase 2 — side effects wait for the verdict** (same flag): the router `bind`s the gate into a `ContextVar` for the `voice_command` task and `gate_frames` runs every pre-verdict upstream pull under it (the brain lane executes inside the lazily-pulled body, not the task). While a speculative turn is unresolved: `voice_command` holds the WHOLE turn before any side effect unless the intent layer calls it read/chat (`turn_is_speculation_safe`: regex `detect_intent` ∈ `SPECULATION_SAFE_INTENTS`, Skybridge (domain, action) read-only, a routed domain outside {chat, weather, time}; a MISSING routed domain — router off, its default — is NEUTRAL, so the verdict then rests on the read allowlist + the Skybridge pair); the write funnels hold again for anything that misjudges — `intent_router.execute_intent` (every non-read intent), `skybridge_service.resolve_skybridge_request` (non-read actions), `expert_dispatch.dispatch` (write/expert kinds, before slot extraction); `_spawn_bg` queues every background side effect (history rows, memory passes, escalations) and runs them in spawn order BY COMPLETION via `defer_until_commit` (a 60 s cap only guards a wedged predecessor, with a WARNING); and `POST /api/system/intent-dispatch` (brain tool writes — a SEPARATE request the ContextVar cannot reach) holds a non-read intent ONLY when it carries the originating turn's `speculative_turn_id` — `zoe_flue_client` puts the bound turn id on an OUTERMOST ` zoe-spec:<id>` envelope line (wire 2 only; mirrored by `labs/flue-zoe-brain-2x/src/speculative-turn.ts`, prefix pinned equal) and the sidecar echoes it on every dispatch; other sessions' writes run at once; a dispatch arriving after its gate closed follows the recorded verdict (`_RECENT_VERDICTS`); an id with neither a gate nor a recorded verdict (e.g. zoe-data restarted mid-turn) is REFUSED while the flag is on — fail-closed, a cancelled turn's write must never run; on any refusal it answers `ok: false` with `reason` (`speculative_turn_cancelled` / `speculative_turn_unknown`) (`hold_speculative_dispatch`). Lanes that cannot echo — zoe-core/legacy (`brain_dispatch._fallback_streaming` / `_fallback_oneshot`, incl. runtime failover), Flue wire 1, or a turn id outside `[A-Za-z0-9_-]{1,64}` — wait for the verdict before the brain starts. Commit/equivalent → the held effect runs exactly once; any other verdict → `SpeculativeTurnCancelled` (a `CancelledError`, so `except Exception` write paths cannot swallow it and carry on) and it never runs; `gate_frames` treats an upstream ended by that as the verdict's consequence, not a stream error. Nothing bound (flag off, every normal turn, every other channel) → all no-ops. Allowlists are fail-closed (an unknown/new intent waits). Design, protocol, failure modes, offline evidence and flip criteria: `docs/architecture/b1-speculative-turn-start.md`. Pinned by `tests/test_voice_speculation_gate.py` and `tests/test_voice_speculation_write_deferral.py` (`ci_safe`, each with break-the-fix negative controls).

### ZD66 Zoe driven voice enrolment

- **Zoe-driven voice enrolment** (`enrollment_state.py`, `voice_enrollment.py`, `routers/enrollment.py`, `lexicons_data/voice_enrollment_<lang>.json`, migration `0046`; `ZOE_ENROLL_OFFER` = off (DEFAULT) | shadow | on, per-call; `ZOE_ENROLL_OFFER_KIDS` default OFF; `ZOE_ENROLL_DECLINE_DAYS` 60; `ZOE_ENROLL_OFFER_PIN_DELAY_S` 20; record + operator steps `docs/knowledge/zoe-driven-voice-enrollment.md`). Owner rule: a member who has not enrolled is KNOWN to Zoe, offered it by voice at a natural moment, and a "no" is fine — nobody runs a command. **State is READ, never copied:** enrolment comes from `speaker_profiles` / `face_profiles`; only what Zoe offered and what the member answered lives in `enrollment_offers` (a failed read is `None` = unknown, never "not enrolled"). **Offer policy** (`enrollment_state.decide_offer`, pure; the first failing rule is the logged reason): flag on; a real member (never a guest/synthetic id; positively an ADULT via `member_modes` + `auth_users.role` — a child only with `ZOE_ENROLL_OFFER_KIDS`, an owner decision on minors' biometrics; an unknown role is refused); not already enrolled; not inside the quiet period after a "no" (60 days) or three ignored offers; nothing in the last 24 h across BOTH moments (`claim_offer` is an optimistic atomic slot); not quiet hours. Moments: a correct PIN on the panel (`panel_auth.submit_pin` → `schedule_offer_after_pin`, delayed so the resumed command's reply goes first) and the close of a conversation (a thanks/"that's all" on a voice turn — NEVER a goodbye, whose reply stays clean). The offer is spoken through the daemon announcement queue (`trigger=voice_enroll_offer`, claimed with `follow_up` so the daemon listens for the answer) and always says what is kept (a voice signature, not recordings) and that it can be deleted. **One deterministic tier** in `fast_tiers.resolve` (after provenance, before the self-model): a pending yes/no through `routers.voice_tts._pending_decision` plus the language file (a question is never a yes), "learn my voice" (any time; clears a decline; refused for guests, children when off, an unverified voice, a non-panel channel; "already enrolled" is said, not redone), "forget my voice" (deletes the server row AND queues a `voice_profile_forget` command for EVERY panel with a device token, starts the quiet period; also pushed by the settings delete route; works for a child with the kids switch off), "do you know my voice?" (answered from the real state; the self-model's `know_me` adds the honest gap clause when the flag is on). **Commands ride the announcement lane** (`voice_announce.enqueue_command` / `COMMAND_TRIGGERS`): a claimed command has an EMPTY `text` and a `command` object, so a daemon that predates commands says nothing instead of reading JSON aloud; the `voice_enroll` and `voice_profile_forget` triggers are PANEL-SCOPED (`start_enrollment` queues only for a panel that holds a live device token). The yes/no is armed by the daemon's played-ACK (`on_announcement_played`), never at enqueue; a failed enqueue releases the offer slot (`release_offer`). `POST /api/enrollment/result` (device token only) records a decline ONLY for `cancelled` with reason `said_stop` / `tapped_stop` (a daemon `shutdown` is not a "no"). `POST /api/enrollment/screen` (device token only) pushes the enrolment prompt (phrase, step counter, state, one localized line — never a name) as a TRANSIENT `voice_enroll` frame to the calling token's panel ONLY (`voice_session.send_to_panel`: never the `all` fallback, a body `panel_id` is ignored, nothing queued or stored; `tests/test_enrollment_screen.py`). Read API: `GET /api/enrollment/state` (own; `?user_id=` admin), `/household` (admin), counts and timestamps only. No English in the code (the language files hold every cue and sentence). Forbidden: offering to a guest/synthetic/child (unless the kids switch is on)/unknown account, offering twice in 24 h, re-offering inside the quiet period, enrolling from a typed channel, treating an unread state as "not enrolled", a forget that leaves the panel's copy. Pinned by `tests/test_voice_enrollment.py` and `tests/test_speaker_engine_import_failure.py`.

### ZD67 Voice signature engine load failure
