# The flag registry

Deep dive B6 (2026-10-18). Before this: 673 `ZOE_*` flags, 647 raw `os.getenv` reads against 164 `typed_env` calls, a flag
read with different defaults in different files, and 68 non-`ZOE_` names the inventory could not see. A flag's meaning lived
in N call sites. Now each flag **declares itself once** and CI keeps the declaration and the code from drifting.

## Design

| Piece | Where | Job |
|---|---|---|
| Registry | `services/zoe-data/flag_registry.py` | One `_f(name, type, default, allowed=, doc=, note=, divergent_ok=)` per flag: `type` is `bool/int/float/str/list`; `allowed` lists the values of a mode flag (`off/shadow/enforce`); `doc` is the owner doc; `note` records the live value; `divergent_ok={file: reason}` acknowledges a reader that legitimately defaults differently. Pure data, stdlib only. |
| Reader | `typed_env.flag("ZOE_X")` | Type, default and allowed values come from the registry; call-time read; the canonical bool table (`1/true/yes/on` vs `0/false/no/off`); an unlisted mode value or an unparseable number falls back to the declared default with one journal warning. An unregistered name raises `KeyError`. |
| Inventory | `docs/knowledge/flag-inventory.{md,json}` | **Generated** from the registry joined with the scanner's facts (readers, the defaults each reader hard-codes, `typed_env` use, `.env.example` coverage, the conflict table, the non-`ZOE_` names). Regenerated by the pre-commit hook. |
| Scanner | `tools/audit/flag_inventory.py` | AST scan of Python plus a `process.env.X` scan of TS/JS. Resolves flag-name constants, `x or "default"` reads and local `(name, default)` wrappers. |
| Tests | `tests/unit/test_flag_registry.py` (`ci_safe`) | The three rules below, each with a synthetic negative control. |

Existing `env_bool("ZOE_X", False)` / `os.environ.get(...)` call sites are untouched. Migrate them as their files are touched
(the voice-path files stay on the legacy ratchet until a replay-gated change reaches them).

## Workflow

- **New flag:** read it with `typed_env.flag("ZOE_X")`, then `python3 tools/audit/flag_inventory.py --sync-registry` (adds an
  entry with an inferred type and default; correct it by hand, in place, and set `doc=`). Inferred types are a starting
  point: a flag read as `== "1"` registers as `str`; fix the type when you touch it.
- **Changing a default:** edit the registry entry, not N call sites. A reader that hard-codes a different literal is a CI failure
  unless its file is acknowledged in `divergent_ok` with a reason.
- **Regenerate the inventory:** `python3 tools/audit/flag_inventory.py` (the `zoe-flag-inventory-fresh` pre-commit hook does it).

## The CI rules (`validate` runs them; all `ci_safe`)

1. **No unregistered read.** Any `ZOE_*` name read by prod or lab code (Python or TS) must be in the registry.
2. **No contradicting default.** (a) A flag whose readers hard-code different *effective* defaults (`'1'` = `True`; `''` = unset;
   `dynamic` is skipped) must carry `divergent_ok`; (b) a reader whose literal default differs from the declared one is a
   failure unless acknowledged. A reader that hard-codes no value (`''`, unset) asserts nothing, so it cannot contradict.
3. **Legacy direct reads only go down.** `docs/knowledge/flag-ratchet.json` holds a per-file ceiling for prod `ZOE_*` reads
   that bypass `typed_env` (697 sites in 203 files at landing). A file over its ceiling, or a new file with a direct read, fails.
   Lock in a migration with `python3 tools/audit/flag_inventory.py --tighten-ratchet`. A file that drops below its ceiling is
   not forced to tighten (a deletion must not freeze `main`); the pre-merge habit is to run `--tighten-ratchet`.

Break-the-fix evidence (run when the rules landed): adding an unregistered `os.environ.get("ZOE_B8_PROBE")` to a zoe-data
module, a second direct read to a ratcheted file, and a contradicting `os.environ.get("ZOE_TIMEZONE", "UTC")` each turn the
matching test red; removing each restores green (recorded in the PR).

## Scope limits

Shell scripts and systemd `Environment=` lines set or default flags but are not scanned; `in os.environ` membership tests are
not reads; a dynamically built name (`f"ZOE_{x}"`) is invisible. TS reads count (the live brain under `labs/flue-zoe-brain-2x`
and `services/zoe-core`: 44 flags are read from TS, 40 of them only from TS). Non-`ZOE_` names are inventoried (245; 73 are read by `services/`) but not registered.

## The 14 conflicting read defaults (decisions)

Found by the stricter comparison above (29 flags have more than one *spelling* of a default; the deep dive counted 18; 15 of the
29 were the same default spelled two ways, `'1'` vs `True`, or `x or "d"` expressions the old scanner read as "no default").
Rule applied: **keep what is effective live today and record it; no call site was changed, nothing live flips.** Voice-path files
(`zoe_core_client.py`, `routers/voice_tts.py`, `voice_settings.py`) were not touched. Each row is `divergent_ok` in the registry.

| Flag | Declared default | Divergent reader(s) and why | Live (`.env`) |
|---|---|---|---|
| `ZOE_BASE_URL` | `https://192.168.1.218` | `zoe-auth/oidc/startup.py` `http://zoe.local` (separate service, OIDC issuer fallback); `routers/system.py` `http://localhost:8000` (in-process self-URL fallback) | `https://192.168.1.218` |
| `ZOE_CHEAP_PR_AGENT_MODEL` | `deepseek/deepseek-chat-v3.1` (the model actually used) | `greploop_guard.py` `cheap-pr-agent` is a cost-event LABEL; changing it would split the cost history | unset |
| `ZOE_DATA_URL` | `http://127.0.0.1:8000` | `zoe_core_client.py` (voice path) resolves `ZOE_CORE_DATA_URL`, then this, then `:8011` for the brain subprocess | `ZOE_CORE_DATA_URL` set, so `:8011` is never taken |
| `ZOE_DIGEST_CHUNKED` | `True` | `digest_pack.py` presence-tests (blank or unset = on) | unset |
| `ZOE_ENV_FILE` | `/home/zoe/assistant/services/zoe-data/.env` | two maintenance scripts read `''` = no override, falling back to the repo-relative then the canonical file | unset |
| `ZOE_HA_BRIDGE_URL` | `http://127.0.0.1:8007` | `routers/stubs.py` only echoes a configured URL in the settings display | `http://127.0.0.1:8007` |
| `ZOE_HOST_LAN_IP` | `''` (unset = discover) | `zoe_agent.py` prompt-text fallback `192.168.1.218` | unset |
| `ZOE_LOCATION_CITY` | `Geraldton` | `identity_facts.py` asserts no city unless configured | `Geraldton` |
| `ZOE_LOCATION_COUNTRY` | `AU` | `identity_facts.py`, `distress_handoff.py` assert nothing unless configured | unset |
| `ZOE_MOONSHINE_ARCH` | `MEDIUM_STREAMING` | `routers/voice_tts.py` (voice path): the arch read agrees; two STT-backend LOG LABEL reads default `v2` (cosmetic, label only) | `MEDIUM_STREAMING` |
| `ZOE_PANEL_ID` | `zoe-touch-pi` | `zoe_latency_probe.py` uses its own identity so probes never pose as the real panel | unset |
| `ZOE_SPEAKER_MODEL` | `resemblyzer` (code default) | Pi daemon / enrol flow: `''` = let the server decide | `dual` (the registry never changes it) |

| `ZOE_URL` | `https://zoe.local` | `zoe_latency_probe.py` runs on the host and defaults to loopback | unset |

Two latent oddities surfaced and recorded rather than changed (both are cosmetic or masked live): the `v2` log label above, and
`zoe_core_client.py`'s `:8011` fallback, which only matters if `ZOE_CORE_DATA_URL` and `ZOE_DATA_URL` are both unset.

## Not done here (the L half of B6)

Promoting flags that have been `on`/`enforce` for 30 days into code is a decision per flag against the live `.env` and the
bar, not a mechanical change. The registry makes the candidates visible (the `note` field carries the live value for the mode
flags and the conflicting ones); the 30-day promotion list and the migration of the ~700 legacy direct reads are follow-ups.
