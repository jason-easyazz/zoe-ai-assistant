# Zoe roadmap

**The one place that says what is next.** Three horizons: **Now** (this week, at most 5), **Next** (at most 10), **Later** (a link list).
Every other plan, tracker and register is an **evidence or design record** linked from an item here; none of them carries its own
"NEXT ACTION" any more (deep dive task C1, [`docs/research/architecture-deep-dive-2026-10-18.md`](research/architecture-deep-dive-2026-10-18.md) section 6).
[`PLANS.md`](PLANS.md) stays the human-readable status index per workstream; this file orders the work.

**How to read a flag on this page.** A claim about what the **code ships** is written `[default <FLAG>=<value>]` (flag name, then the value); CI
(`tests/unit/test_roadmap_flag_claims.py`) fails when it contradicts the defaults derived from the code in
[`knowledge/live-state.json`](knowledge/live-state.json) (generated by `tools/audit/live_state.py` from the flag inventory). Those are **defaults, not live values**:
what is ON in the running processes is read with `scripts/maintenance/zoe_ground_truth.sh` and recorded, dated, in the "Live flag state" block of
[`PLANS.md`](PLANS.md). `unset` means "no static default or an empty one"; `off` accepts it. Never write a live value as a bracketed claim.

**Cadence.** Monday, 30 minutes, owner plus one agent: (1) regenerate `live-state.json`; (2) read live flags with `zoe_ground_truth.sh`; (3) move at most 5 items into
Now; (4) triage the week's new [`knowledge/open-problems.md`](knowledge/open-problems.md) lines into items here, `wontfix`, or delete (a fixed line is deleted, never kept);
(5) retire absorbed research records per [`research/index.md`](research/index.md). Update this file in the same PR as the change that moves an item.

**Item shape.** outcome in plain words · owner (`agent` / `owner` / both) · flag and its default · acceptance (the bar, gate or test id) · PR or record.
