## 2. Home Assistant / Music Assistant (what changed)
- 2026.9 (2026-09-02) [P]: LLM tool names now domain-prefixed (`homeassistant__GetLiveContext`, `intent__HassTurnOn`) = already in review. New: Cloud-only experimental Soniox STT (Labs; irrelevant to local), Voice assistants moved to Connectivity, Gemini thinking budget/level options, scripts startable from Assist.
- 2026.10 (2026-10-07; patches .1 10-10, .2 10-16) [P]: climate fan modes by voice; MCP card + auto-discovery of apps that run their own MCP server; profile name/picture editable by every user and used "from the sidebar to your dashboards and Assist" (person-linked identity, still no speaker ID); MA announcements can speak text through a TTS entity; music search lets the AI choose the best of a result list and search inside an artist/album/playlist; Threema E2EE notify; active security alerts on the Home dashboard; Companion notification settings per device.
- Remote access: Home Assistant Cloud renamed **Home Assistant Link** (blog 2026-10-02, official in the December release); Nabu Casa moved to bare metal and a boot-time latency checker that picks the fastest server; refresh tokens revoked when a user is removed (2026.10.2). Relay architecture is unchanged (no port forward, no VPN) [P]. Piece worth copying: pick-nearest-relay-by-ping at boot (relevant to the Headscale/the411 plan).
- Voice PE firmware [P]: 26.9.0 (2026-09-17), 26.6.0 (2026-06-18: HA can request UNPROCESSED audio for STT engines that do their own processing; Sendspin sync), 26.4.0 (multiple Sendspin servers; TTS timeout fix). No wake-word or satellite-feature release in 2026. Voice PE still cannot take custom wake words (microWakeWord, firmware build only) [S].
- Satellites: rhasspy/wyoming-satellite **archived 2026-01-27**, replaced by OHF `linux-voice-assistant` (ESPHome protocol, not Wyoming) [S]. Piper archived 2025-10-06 [S]. `assist_satellite` actions unchanged: announce (preannounce chime default on, `preannounce_media_id`), start_conversation (needs a multi-turn agent; built-in agent unsupported), ask_question (rides START_CONVERSATION) [S]. No built-in intercom; the community answer is custom sentences + announce, or VoIP Stack / Kiosk Satellite (row 5).
- Community satellites worth knowing: Voice Satellite card/integration (jxlarrea, AGPL-3.0): browser-side wake word (vsWakeWord / microWakeWord / openWakeWord), TWO wake words each routed to its own Assist pipeline, fires `voice_satellite_chat` and `voice_satellite_timer` events per turn [P]. Kiosk Satellite (Android, first public release 2026-07-18) [S]. Same author's stack is a near-twin of Zoe's panel; the per-turn event with transcript + reply + tools used is a clean audit hook.
- Android companion app wake word and iOS Watch tap-and-hold: see row 12. CarPlay Assist needs iOS 26.4+ [S].
- **Music Assistant 2.8 (2026-03-25)** [P]: Player Merging (one entry per physical speaker across AirPlay/DLNA; breaking for HA groups), Sendspin Bridges (wrap Chromecast/AirPlay/Sonos so mixed brands stay in sync), Party plugin (QR guests), karaoke lyrics, Background Tasks settings. **2.9 (2026-06-10)** [P]: Discover page, Audio Analysis providers (Smart Fades beat-matched crossfade; Sonic Similarity for "Radio Mode / Don't Stop the Music" on local libraries; AcoustID), Sendspin visualizers + Hue beat bridge, Smart Playlists, per-player min/max volume, playback speed, MCP Server Provider, WebDAV/QQ/NetEase/NTS sources, WiiM / Local Audio Out / MPD / Samsung WAM. Neither release notes TTS ducking; ducking depends on the player's native announce support.
- Sendspin (Open Home Foundation sync protocol) is at Release Candidate 1; Snapcast server is v0.35.0 (March 2026) [S]. Sendspin is where HA/MA/ESPHome multi-room is heading; Snapcast is the stable fallback.

## 3. Open voice stacks
- Pipecat 1.0.0 (2026-04-14) [S]: universal `LLMContext` switchable at runtime; turn/interruption/mute/idle strategies moved into the user aggregator (UserIdleProcessor and STTMuteFilter removed); VAD config moved there; default `stop_secs` 0.8 -> 0.2; async function calls can stream intermediate results (`is_final=False`); Python >=3.11. Smart Turn is still v3.2 (8 MB, 23 languages, BSD-2) [P].
- LiveKit Agents: 1.5.0 (2026-03-19) adaptive interruption + dynamic endpointing; 1.6.1 (Jun 2026) built-in Turn Detector v1 (audio, 14 languages; v1-mini open-weight CPU, free everywhere, "LiveKit Model License", falls back to mini if v1 unavailable; docs advise compute-optimised instances because burstable ones time out) [P]; 1.8.0–1.8.8 (2026-09-05 -> 10-15) with `DuplexModel` (OpenAI GPT-Live first) [P]. Turn detection needs onnxruntime 1.30.x [S].
- OpenVoiceOS [P]: speaker verifier (09-26), WakeForge 1.2 MB wake words (10-02), speech servers callable by any agent via UTCP/MCP (07-15), real-time offline ASR via ONNX (02-16), terminal client (07-24), Pre-Wake-VAD (2025-11) to cut false wakes. raspOVOS image 2026-07-12. Neon AI: nothing.
- Wyoming/Rhasspy: protocol is a maintained OHF standard but the reference satellite is archived (see section 2).
- Full-duplex models worth KNOWING (none fit 16 GB with the brain resident, none should replace the rocks) [S]: NVIDIA PersonaPlex (2026-01; 7 B; MIT code + NVIDIA Open Model weights; sources disagree on 16 vs 24 GB VRAM; Moshi base is CC-BY-4.0); NemotronLabs VoiceChat (arXiv 2609.21967, Sep 2026; streaming encoder + decoder-only LM with parallel text and function-call streams; 82.5% tool-selection F1 on FDB 3.0; weights/licence not confirmed by the page I read); Kyutai Moshi (2024) and Unmute (wrapper: needs CUDA GPU >=16 GB per its README); OpenAI GPT-Live-1 (2026-07-08, hosted only); a 2026 benchmark finds barge-in stop latency still ~1.7–2.6 s for several full-duplex models. Useful idea from the tool-call paper: separate parallel streams for "say" and "do" (what Zoe's router already does structurally).

## 4. Companion / household agents (open source)
- OpenClaw is still shipping (2.0 = v2026.8.1 late Aug; 2026.10.x point releases; Gateway worker-thread SQLite changes; MCP Apps; shared cloud sessions) [S]. Zoe has retired it; nothing to borrow beyond "interrupted turns and subagents resume after a restart", which is a good property for the PR harness.
- Letta [S]: Conversations API (Jan 2026; one agent, shared memory, many concurrent user sessions = the household shape), Context Repositories / MemFS (Feb; git-versioned memory that can sync to the user's own repo), Server 0.16.7 (2026-03-31; default 128k context, compaction overhaul, **removed enforced block size limits**), Context Constitution (Apr). Counterpoint to row 11 of 09-25 ("blocks with `limit`"): Letta itself dropped the hard cap. `/sleeptime` in Letta Code = periodic "dreaming" (page updated 2026-09-20).
- mem0 [S]: see table row 11. External graph stores removed in Python SDK v2.0.0, replaced by entity linking inside the vector store (one fewer service, matches Zoe's Postgres+Chroma). OpenMemory reported deprecated (DeepWiki only).
- Hindsight (Vectorize) [S]: 91.4% LongMemEval at launch (2025-12-16), homepage now 94.6%, "Memlake" for 100 M memories on object storage; its 2026-03-23 Agent Memory Benchmark manifesto argues LongMemEval/LoCoMo were built for 32k-context models and "dump everything in context" scores competitively. Take the lesson for Zoe's own memory evals: with a 4B model and a small context, test retrieval under Zoe's real token budget, not public leaderboards. All numbers are vendor-reported.
- Omi (open-source pendant; main repo updated 2026-10-13; self-reported LoCoMo 86.6 / LongMemEval 83.3) [S]; Limitless acquired by Meta, capture cut off 2025-12-19; Bee (Amazon) closed-source. Omi remains the only open day-review hardware path, which Zoe already uses.
- "Jarvis" repos: HarryDeBiasse/jarvis-voice-assistant (Pi, openWakeWord + Silero + tiered brain, half-duplex echo control; default STT is hosted Deepgram) and roanbrasil/voice_assistant_code (Pi 5/Jetson, HA control, Telegram bot) are look-alikes, nothing Zoe lacks. danielsantos2310/jarvis is the only "proactive + presence" repo and is planning-stage only. QwenPaw v2.2.0 (Sep 2026) added a self-hosted multi-user Hub; its family features are unverified.
- Gap confirmed: no open project combines per-person household memory + kids mode + family lists + who-is-talking. Commercial references are Google (Gemini for the whole family incl. kids, 2026-06-23; Storytime co-creation 08-05) and Apple (HomeView below). ha-agenthub (mainzerp) is the closest open "agent hub for HA" with speaker ID, still prompt-context-only.

## 6. Phone ("Zoe on your phone") — the pragmatic 2026 route
1. **Primary: a PWA installed to the Home Screen** with Web Push. iOS rules [S]: the user must add it to the Home Screen, permission must be requested from a tap, push does not work in Safari tabs or in-app WKWebView, no silent/data-only push, no background sync. Declarative Web Push (iOS/iPadOS 18.4+) removes the service-worker requirement. EU: one 2026 guide says push is off in the EU; two others say Apple reversed that before iOS 17.4 shipped. Unresolved, so test on a real EU-region phone if it matters. I could not find iOS 27 (released 2026-09-14 per a search snippet) PWA changes.
2. **Android: ntfy/UnifiedPush** as the self-hosted notification channel, optional.
3. **Telegram stays the always-works fallback** and now has streaming drafts, voice-note blocks, ephemeral messages (row 9). Bot API 10.0 (2026-05-08) allows bot-to-bot messaging by username; relevant only if Zoe ever talks to another bot, and a new attack surface otherwise.
4. **Push-to-talk / calls:** Companion-style on-device wake word is experimental with real battery cost [S]; prefer tap-and-hold in the PWA (getUserMedia works in Home Screen web apps) and a WebRTC/SIP call page for intercom. HA's iOS app added tap-and-hold Assist on Watch; Android has system assistant gesture and (since app 2026.2.3) on-device wake word [S].
5. **Native shell (Tauri/Capacitor) not researched this session** — I have no 2026 evidence either way; treat as an open question, not a recommendation.
6. Remote reach for all of the above is the Headscale tailnet; HA's "Link" shows the nearest-relay-by-ping trick.
