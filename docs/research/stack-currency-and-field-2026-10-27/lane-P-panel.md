## 2. Kiosk hardening and health (24/7 wall panel)
1. Cooling first. Pi 5 default soft throttle/mitigation starts ~80 C, hard ~85 C [S]; panel is at 79.6 C idle with historical throttle flags and no fan device. The Active Cooler (fan header, firmware-controlled curve; dtparam=fan_temp0..3/fan_temp0_speed.. in /boot/firmware/config.txt, defaults 50/60/67.5/75 C; level 4 reportedly not settable) is a ~US$5 part. https://forums.raspberrypi.com/viewtopic.php?t=386330 [S]. Also reduces the voice daemon's torch burn. This needs the owner at the panel (case open); a heatsink-case alternative if the DSI display housing leaves no room.
2. SD wear. Evidence says Chromium profile churn + daemon files, not journald. Options in increasing effort: (a) `--disk-cache-dir=/dev/shm/chromium-cache --disk-cache-size=50000000` plus move `--user-data-dir` volatile bits (GPUCache, GrShaderCache, Dawn*Cache, component_crx_cache) to tmpfs via symlink; FullPageOS issue and peppe8o guide: https://github.com/guysoft/FullPageOS/issues/121 [S] (one report: root-owned tmpfs dir broke it; pi user must own it); (b) whole `--user-data-dir=/run/user/1000/chromium-kiosk` on tmpfs (profile is 175 MB; kiosk is stateless, panel auth is device token, so cost is a cold start after reboot) - probably the cleanest and removes ~all browser writes; (c) overlay root: raspi-config overlay works on bookworm but one source says bookworm's menu has bugs and Trixie moves to read-only-root mount instead [S]; needs a writable data partition for ~/.zoe-voice (profiles, speaker_profiles.json, voice.log, inbox, shadow metrics), so it is a later, bigger item; (d) boot from USB SSD or NVMe HAT (Pi 5 supports both) - the real fix for endurance, owner at panel; if staying on SD use an endurance/industrial card, not A2 consumer (A2 is about IOPS, not TBW). No primary source retrieved for the USB/NVMe/endurance points [U/own knowledge]. No SMART/life_time exposed by this card (mmc name USD00; `life_time` sysfs absent), so remaining life is unknown -> measure writes, don't guess.
3. TLS: replace `--ignore-certificate-errors` with a household CA. Chromium on Linux trusts the NSS db, not /usr/local/share/ca-certificates: `certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n zoe-household-ca -i ca.pem` (libnss3-tools) for the user that runs Chromium, AND note the profile is --user-data-dir elsewhere but NSS lives in $HOME/.pki, fine. Leaf must carry a SAN matching https://192.168.1.218 (IP SAN) [S]. Also install CA in OS store for the python daemon (`verify=` currently VERIFY_SSL flag). The flag also disables HSTS/pinning for every site the kiosk can reach, which matters because the panel can navigate (touch UI links). Also blocks QR/auth flows to real HTTPS. This is a code-in-repo + one-time on-panel step (SSH is enough; owner not required).
4. `--no-sandbox`: only truly required when running as root; a non-root `pi` user on Debian's chromium works with the setuid/userns sandbox [S, with caveat that I found no Debian-specific source]. The kiosk runs as pi (ps shows user pi). Test by removing the flag on the panel after-hours; X11 vs Wayland is irrelevant to the sandbox. Reversible in one line. Pair it with the sandbox-free blast radius: the kiosk user also owns the voice daemon's tokens.
5. Remote debugging: 127.0.0.1:9222 is correct posture; keep nftables rule; do not expose via Tailscale ACL. DevTools gives full page control - treat access to 9222 == the panel session.
6. Watchdog: today = systemd Restart=always + 1-min timer script. TouchKio recovers via MQTT-triggered reload and has no real watchdog [S: https://github.com/leukipp/touchkio]. Add: systemd `WatchdogSec` with sd_notify from the daemon, a Chromium liveness probe through the CDP port (Runtime.evaluate heartbeat, not just process alive), and hardware watchdog (`RuntimeWatchdogSec=15` in /etc/systemd/system.conf; Pi 5 has bcm2835-wdt) so a kernel hang reboots itself [own knowledge U].
7. Screen: xset dpms off + sleep card is already the design; brightness is via zoe-panel-agent (DSI backlight 10-0045 present as a sysfs backlight) - fine. For burn-in on the DSI LCD nothing needed.
8. Wi-Fi loss: panel is on eth0 or wlan0? Two NM profiles exist (preconfigured Wi-Fi, "Wired connection 1"). The status gate already shows link-home state. Add NetworkManager `connection.autoconnect-retries=0` (infinite) and a watchdog that `nmcli radio wifi off/on` after N failed pings [U/own knowledge].

## 3. Audio
- Jabra Speak 750: spec sheet lists full duplex + acoustic echo cancellation = yes (on-device DSP), Jabra release notes mention echo and "double talk" fixes in firmware 2.24.0 and 2.43.0, newest listed 2.45.0 (Windows tool). https://www.jabra.com/support/release-notes/release-note-jabra-speak-750 [S]. I found no Linux firmware updater for the 750 (Xpress for Linux lists other models; jabridge support unverified) [U]. Consequence: the daemon's barge-in on the raw mic already benefits from hardware AEC; stacking Pulse module-echo-cancel (webrtc) on top risks double-cancellation distortion, and needs a monitor reference on a different clock domain [S]. Recommendation: do NOT add software AEC; measure instead (replay: play TTS, record mic, check residual with VAD prob). If firmware is old (<2.43) a one-time update from a Windows/macOS box would help double-talk barge-in; owner needs the Jabra on a PC.
- Pulse settings seen: tsched=0 (fixed latency) on udev-detect and alsa-card; 44.1k/2ch default. Set `default-sample-rate=48000`, `avoid-resampling=yes`, and `resample-method=speex-float-3` or soxr in daemon.conf (Jabra is 16 kHz-native in speakerphone mode [U]) - an experiment, replay-gated. Keep capture at 16 kHz mono, 80 ms/1280 chunks is the standard oww frame (oww wants multiples of 80 ms) - fine. Run the daemon with `Nice=-5`? Memory note says never negative Nice for --user units; instead use CPUWeight in a drop-in [own memory note].
- PipeWire vs Pulse on this panel: gain = Pi OS default stack, `echo-cancel` as a filter-chain module with better monitor-clock handling, WirePlumber policy for ducking (role-based), and shairport 5.6 has a native pipewire backend with `mixer_type` sink/stream [P shairport notes]; loss = a stack swap on a working panel, and the repo's own notes (panel-as-ma-speaker-feasibility.md) show Pulse mixing already solves TTS-over-music contention. The pressure to move is only the OS upgrade (Trixie ships PipeWire; pipewire-pulse keeps PyAudio and `pulse` device names working). Decide at the Trixie reflash, not before.
- Ducking: the daemon has no music ducking (feasibility note: "auto-ducking is nice-to-have"). OHF linux-voice-assistant ducks music to ~half volume on wake word and restores after; the PR (#478) was reverted so the code path is unsettled [S: https://github.com/OHF-Voice/linux-voice-assistant/pull/478]. HA Voice chapter 10 states ducked-announcement as a goal [S]. A Pulse-only way: `module-role-ducking` is already loadable (module-role-cork is loaded; role-ducking would duck "music" role streams when "phone/announce" role plays) - tag shairport stream `media.role=music` and TTS `phone` [U, needs a test]. Cheap and needs no new software.
- Dedicated DSP array: XVF3800 (Seeed reSpeaker, ~US$61, USB, 4 mics, AEC/AGC/beamforming/DoA/NS, plug and play) https://www.seeedstudio.com/ReSpeaker-XVF3800-USB-Mic-Array-p-6488.html [S]. HA Voice PE's XMOS XU316 pipeline AEC->IC->NS->AGC, but a community loud-music investigation found AEC underperformed other taps for wake firing and ESPHome is effectively half-duplex https://github.com/esphome/voice-kit-xmos-firmware/issues/10 [S]. Verdict: far-field beamforming genuinely beats a single omni speakerphone mic in a noisy room and gives DoA; against the Jabra's AEC it is not a guaranteed barge-in win (needs the playback ref fed to the XVF; with USB output through the XVF it is). Treat as a measured A/B with the replay corpus, not a purchase decision yet. Owner at panel to swap.
- What the field does: Voice PE/XMOS = hardware AEC chip; linux-voice-assistant = optional WebRTC AEC in a PipeWire filter-chain plus ducking on wake [S]; OVOS/raspOVOS images use PipeWire+wireplumber [S https://openvoiceos.github.io/raspOVOS/].

## 4. Camera and presence
- PanaCast face-box size = coarse distance (face width in px ~ 1/distance; panel already uses FACE_MIN_PX=36 per memory notes). Works only in light, only facing the camera, and USB camera power is shared with the Jabra (feasibility note) - fine as "looking at me" signal (attention) not "in the room".
- mmWave: HLK-LD2410 (UART 256000 baud, moving/static target, distance, 8 gates, GPIO out) and LD2450 (3 target tracking x/y, ~6-8 m, sources disagree) both are ~US$5-8, 3.3 V logic; on Pi 5 UART on /dev/ttyAMA0 after disabling serial console (the panel's hdmi/dsi usage doesn't conflict). https://componentindex.net/components/ld2410/ [S]. LD2410S differs (115200 baud). Pi has no free 5V-safe issue: wire to 3.3 V TX/RX GPIO 14/15.
- BLE presence: phone/watch RSSI via bluez (panel has hci0) is room-level only, needs per-person devices; useful as identity hint, not distance.
- "Distance-aware UI" in the field: HA community pattern = mmWave (ESPHome LD2410) distance bins -> dashboard layout (large clock/far vs dense controls/near) [S, the search found no wall-panel UI writeup, so this is pattern not product]. Memory note: the house has zero presence sensors and the sleep card is an inactivity timer; one LD2410 on the panel gives a real wake-on-approach and screensaver gate. ~US$8, owner at panel to wire 4 pins.

## 5. Peers 2026 and what to copy
- HA Voice PE firmware 26.9.0 (17-18 Sep 2026; ESPHome min 2026.6.0; 26.6.0 added Sendspin sync and unprocessed-audio-for-STT) https://github.com/esphome/home-assistant-voice-pe/releases [S]. Copy: signed OTA with version pinning + HA-side "update available" entity + unprocessed-audio flag per consumer.
- OHF linux-voice-assistant: ESPHome protocol, wake-word on-device, optional AEC and ducking, Sendspin multiroom; config in a file/ENV and systemd user unit; no image mechanism [S]. Copy: ducking-on-wake and the AEC filter-chain recipe.
- Wyoming satellites: archived (per brief). OVOS/raspOVOS: ready-to-flash images, PipeWire, no OTA details found [S]. Kiosk Satellite / TouchKio: Electron app deb + MQTT control; Kiosk Satellite not found [U].
- Commercial bar (Sonos, HomeView): A/B partitions, signed delta OTA, health telemetry, silent auto-update windows [own knowledge U].
- What this panel lacks vs all of them: (1) config as code on the device: scripts are in-repo but ~/.zoe-voice has .bak-2026* files and a hand-run venv, so state drifts (several pi-requirements.txt.bak-*); (2) any update channel: deploy is `ssh` + copy; (3) health reporting: temperature/throttle/mem/last-wake not pushed anywhere; (4) rollback: no A/B; (5) pip pins unreproducible (venv 4.2 GB with unlisted librosa/numba/scipy).
- Piece to copy first: Voice PE's "version + health entity" idea, done cheaply: the panel agent (already an HTTP service) posts {git sha of deployed bundle, vcgencmd get_throttled, temp, free mem, daemon uptime, last wake ts, chromium CDP ok} to zoe-data every minute; zoe-data shows it on the Zoe page and alerts. Then a pull-based updater (timer: fetch signed tarball/commit, verify, switch a `current` symlink, restart, auto-revert if health fails in 2 min) gives A/B-ish rollback without new hardware.
