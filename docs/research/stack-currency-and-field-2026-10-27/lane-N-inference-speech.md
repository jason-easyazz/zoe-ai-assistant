## 2. Kokoro
- kokoro 0.9.4 (2025-04-05) is STILL latest on PyPI [P]; misaki 0.9.4 latest [P, date not visible]. Package is effectively unmaintained for 6+ months, so no upgrade exists; nothing to bump.
- torch: JetPack 6 / cu126 / py3.10: jetson-ai-lab index had torch 2.9.1 (libcudss.so.0 ImportError reports), 2.10.0+cu126 reported working on JP 6.2.1, no official 2.11+ for JP6 yet [S]. https://forums.developer.nvidia.com/t/pytorch-2-11-wheel-for-jetpack-6-2-1-cuda-12-6-aarch64-needed-to-build-vllm-main/378388 ; community wheels https://github.com/Shattered217/Jetson-Orin-Wheels. So 2.8 -> 2.10 is possible but gains for an 82M model are nil; skip.
- ONNX path: no Orin-specific Kokoro RTF/RAM numbers found anywhere [U]. Field pitfalls: kokoro-onnx TensorRT EP fails at init (STFT/ISTFT gather has no input shape) https://github.com/thewh1teagle/kokoro-onnx/issues/50 [S]; ORT CUDA EP >=1.5 GB RAM, TRT EP >=2 GB on Xavier NX [S]; Orin Nano TRT builds see only ~85 MB free during tactic selection on JP 6.2 [S]. ORT on Jetson needs a from-source build (1.24.2 vs TRT 10.3/CUDA 12.6/cu DNN 9.3/sm_87) [S]. Conclusion: do not expect ONNX-CUDA/TRT to beat the 2.3 GB torch sidecar; most of 2.3 GB is CUDA context + cuDNN/cublas libs, not weights (weights ~330 MB). Cheapest lever to MEASURE: CUDA_MODULE_LOADING=LAZY (default >=11.7, verify), torch.backends.cudnn off for the sidecar, fp16 (.half()) on the model, no JIT warmup on every voice, `PYTORCH_NO_CUDA_MEMORY_CACHING` untested. CPU INT8 ONNX Kokoro exists (~280 MB FP16 RAM) but RTF on the Orin A78AE cores while LLM runs is unmeasured and would steal the cores Moonshine uses.
- Streaming by chunk: KPipeline already yields per-segment; Zoe's chunking is policy side. Voice blending: supported by kokoro voices (tensor mix) [S].
- Advisories: none found for kokoro/misaki [S].

## 6. JetPack / platform
- JetPack 7.2 announced GTC Taipei 2026-06-01; 7.2.1 released ~2026-08-11/12 for Orin Nano/NX/AGX Orin. https://jetsonhacks.com/2026/08/12/jetpack-7-2-1-released/ [S]. Stack: Ubuntu 24.04, kernel 6.8, CUDA 13.2, cuDNN 9.20, TensorRT 10.16, Python 3.12 default [S]. JetPack 6.2.2 (Jetson Linux 36.5, same libs, fixes a CUDA allocation bug) is the final Orin-only 6.x; you are on R36.4.3 (6.2.1 line) [S].
- Memory: Seeed single-workload: post-load memory 24.6 -> 14.7 GB (-40%), GPU clock 930 MHz -> 1.36 GHz, PP +42%, TG +28%; caveated (different boards, baseline 6.2, power mode changed) https://iotdigitaltwinplm.com/jetpack-7-2-1-vs-6-2-2-jetson-orin-migration-2026/ [S]. Matches the repo note; still unmeasured on E4B.
- Costs: full reflash (no apt upgrade), rebuild llama.cpp (CUDA 13), Kokoro torch wheels (CUDA13 aarch64 wheels exist: community lists torch 2.12 for JP 7.2), TRT engines, OOT audio/camera drivers, and ReSpeaker/USB audio re-test [S]. ## 7. Why torch is in zoe-data
- Grep of non-test python found NO `import torch` in services/zoe-data. Torch is installed only as Resemblyzer's dependency: requirements-py312.txt line 119 pins torch-2.14.0+cpu wheel solely for `resemblyzer==0.1.4 --no-deps`; voice_speaker_id.py documents ~360 MB RSS when loaded and keeps `main` from importing it (lazy). transformers==5.17.0 is imported only by tests (test_voice_turn_logmel_parity.py mel_filter_bank). So: torch (wheel size hundreds of MB) and likely transformers can be dropped from the prod venv if Resemblyzer is retired and the parity test gets vendored fixtures. RAM gain at runtime is 0 unless Resemblyzer is currently loaded (up to ~360 MB when it is); install-size/CVE-surface gain is real. Verify with `ZOE speaker_mode` live setting before removal.
