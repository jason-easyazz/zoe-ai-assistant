## 0. Summary

1. The field's benchmarks measure *recall of things the user said*. None measures *who is allowed to change
   what the user said* (authority), whether a deleted thing stays deleted, or whether text that is not the
   user's can write a memory. Zoe's owner directive ("Samantha doesn't have dementia") is exactly those three.
   So "better" cannot be a LoCoMo number. It has to be **per-axis pass rates with a negative control on every
   axis, stated with n and a confidence interval**.
2. ZMB = nine axes, roughly 110 cells (about 80 store-level and brain-free, about 25 chat asks, a handful
   judged). Scenario data is separate from the Zoe driver, so a thin adapter could run the same events and
   probes against another memory system; that is the only honest way to ever say "better than X".
3. The 4B brain is the *answerer*, not the *scorer*, wherever possible. Gold truth is generated by the scenario
   (a scripted world), so there is no "corrupt golden answer" ceiling (LoCoMo: 6.4% corrupt, ceiling 93.57%
   **[doc]**), and the store itself is scored (row present / absent / disputed), not just the reply. A local
   judge is used for exactly two things (tone, hedged abstention) and is calibrated against the LoCoMo-audit
   failure mode (vague-but-wrong answers accepted).
4. Cost: the existing bar is ~45 brain turns = 15-30 min **[src]** `docs/knowledge/samantha-bar.md:752-753`. A
   15-minute ZMB therefore cannot be chat-turn-driven. The design is a store-level tier (internal synthetic
   routes, no brain reply) plus a small chat tier of about 25 asks. Missing today: `--only`, the synthetic
   ingest / digest / capture routes, a Telegram notice, per-axis statistics.
5. The honest public claim is in section 6.

## 1. What exists today

### 1.1 `scripts/perf/samantha_bar.py` (S1-S22) - the pattern ZMB reuses

* **Shape.** Scripted multi-day scenarios against throwaway `demo_bar_<8 hex>` users through the live
  `/api/chat`; deterministic scoring first, the brain-as-judge (temperature 0, fixed rubric) only where
  needed; per-scenario verdict PASS / FAIL / SKIP / ERROR; only a *previously PASSING* scenario that is no
  longer PASS is red; `expected` FAIL/SKIP scenarios are "targets", tracked but not regressions.
  **[src]** `samantha_bar.py:1-60`, `:321` (`EXPECTED`), `:837-856` (`compare_baseline`).
* **Safety.** `DEMO_USER_RE = ^demo_bar_[0-9a-f]{8}$` asserted before any write (`:121`, `assert_demo_user`
  `:869`); memory reached through the API only; pending-teardown file written before the first write and
  teardown asserted in `finally` (`teardown` `:1399`, main `:1924-1940`); refuses to start when it cannot clean
  up (`forget_ok`, `:1908`); `ZOE_PERF=1`, harness lock `/tmp/zoe-voice-harness.lock`, nightly window 01:45-03:15
  + 30 min guard (`:102`), deploy-in-progress guard, `/readyz`, MemAvailable >= 1.2 GB (`:101`), `nice` >= 5.
  Exit 0/1/2/3 contract.
* **Scenarios that already are ZMB cells.** S1/S8 (recall; S8 = 32 filler turns, `FILLER` `:211`), S2
  (knowledge update), S3 (abstention; `declines` / `names_a_specific` `:459-466`), S4 (emotional thread;
  judged), S6 (isolation), S7 (keep the richer fact), S10 (one-word change; expected FAIL), S13-S16 (contacts),
  S20 (day-first dates), S21 (a correction reaches the record; expected FAIL until `ZOE_CORRECTION_APPLY`),
  S22 (roles never guessed; expected FAIL until `ZOE_ROSTER_NEUTRAL_ASK`).
* **Instrument discipline.** The judge prompt is sha-pinned (`:359`; `tests/unit/test_samantha_bar.py:39-44`);
  every scorer has a good-reply fixture and several bad-reply fixtures (`test_s20_day_first`, `test_s21_*`,
  the hedged-guess cases `:105-111`); an unparseable judge is ERROR, never PASS (`parse_judge_verdict` `:374`);
  a brain fallback text is ERROR, never a reply (`:434`).
* **Gaps relevant to ZMB.**
  1. **No `--only`.** `argparse` (`:1819-1842`) has no filter, `SCENARIO_IDS` is a fixed tuple (`:131`), and a
     run with fewer results than `SCENARIO_IDS` is `status=error` (`:1957`), so a filtered run also needs a
     legal "partial" status that can never record a baseline.
  2. **No notification.** A regression is an exit code and a line in `samantha_bar_trend.jsonl`; the only
     Telegram helper lives in `scripts/maintenance/zoe_crash_loop_watch.py:99-130`.
  3. **No authority, forget or poisoning axis**, and no statistics beyond pass/fail.
  4. **No instrument-level negative control.** Scorer fixtures prove a scorer *can* fail; nothing proves the
     *live* scenario goes red when the feature is broken. S21/S22 are red *because* a flag is dark, which is a
     real negative control, but accidental.
* **Cost.** ~45 brain turns + per-turn digests + judge calls = 15-30 minutes of brain slot
  (`samantha-bar.md:752-753`). The day-sim's "week" took 3 min 21 s (`:667`). Per-turn cost is therefore
  roughly 20-40 s **[derived from those two lines, not measured]**.

## 2. What the benchmarks measure and miss

All **[doc]**, fetched 2026-10-05 unless marked.

| Benchmark | What it measures | Judge | Known flaws / what it cannot see |

| **LongMemEval** (arXiv 2410.10813; repo xiaowu0162/LongMemEval) | 500 questions over chat histories. Five abilities: information extraction, multi-session reasoning (MR), knowledge updates (KU), temporal reasoning (TR), abstention (ABS). Seven question types in the paper (single-session-user, -assistant, -preference, multi-session, knowledge-update, temporal-reasoning, abstention); the repo marks abstention items with an `_abs` suffix. "Who said it" is user vs assistant - **not "an unverified speaker near the panel" and not "text pasted from a third party"** |
| **MemTrace / MemTraceBench** (arXiv 2605.28732) | Operation-level error attribution: write-time vs read-time failures; information loss, retrieval misalignment; systems studied: long-context, RAG, mem0, EverMemOS | LLM judge for attribution | A diagnostic, not a gate; "ongoing work", code promised. **Its write / read split is the right way to report ZMB failures** (every FAIL is labelled `write`, `read` or `answer`) |
| **mem0 v3 blog** (2026-04, "token-efficient memory algorithm") | Self-reported: LoCoMo 92.5, LongMemEval 94.4, BEAM-1M 64.1, BEAM-10M 48.6, <7k tokens per retrieval; LME categories: single-session-user 98.6, -assistant 98.2, preference 96.7, KU 93.6, TR 97.0, MR 88.0 (no abstention row in that breakdown) | Judge and answering model **not stated** on the page | LoCoMo 92.5 sits 1.07 points under the audit's 93.57 ceiling (my inference, not the audit's); no authority, forgetting or poisoning number |
| **Zep's rebuttal** ("Is Mem0 Really SOTA in Agent Memory?") | Zep says mem0 mis-ran Zep (user role on both speakers, timestamps appended to messages instead of `created_at`, sequential searches inflating latency) and reports 75.14% +/- 0.17 vs Mem0-graph 68.44%, p95 search 0.632 s. Mem0's counter: 58.44% (search summary of getzep/zep-papers#5) | n/a | The dispute itself is the finding: **the same system scores 58 to 75 depending on who runs it and which categories count.** Never cite a LoCoMo figure as settled. |

Rules this imposes on ZMB:

1. **Generate gold, do not annotate it.** The scripted world fixes the truth; there is no corrupt-gold ceiling.
2. **Score the store, not only the reply.** The write path is where the owner's incident lives (MemTrace's
   write/read split). A reply can be right by luck or from ambient knowledge.
3. **Report n and a Wilson interval per axis**, and never rank two axes inside each other's interval (the
   LoCoMo audit's statistical point).
4. **Measure the judge** before trusting it: a vague-but-wrong probe set runs through the local judge on every
   judged run and its false-accept rate goes in the artifact (section 5.3).
5. **Pin everything that changes what PASS means** (judge prompt sha, corpus seed, scorer version) and mark the
   baseline "not comparable" when one changes - as `compare_baseline` already does for the judge sha
   (`samantha_bar.py:851`).
6. **Do not run LongMemEval_S or BEAM end to end** through a 4B brain with an 8k slot (the audit's §5.2 call, which
   this record agrees with: the answerer, not the memory, would dominate). One *retrieval-only* anchor run
   (Recall@k on the dataset's own evidence labels) is the one place a number comparable with the paper is
   possible - PR 10.

## 3. ZMB design

### 3.0 Architecture

* **Scenario spec = data.** Each cell is a JSON-able record: `events` (ordered; each with `text`, `speaker` in
  `{owner_typed, owner_voice_verified, panel_unverified, third_party, pasted_email, assistant,
  system_writer:<source>}`, `day_offset`), `probes` (question + `needles` / `anti_needles` / `canaries` /
  `store_assertions`), `axis`, `lme_map`, `expected` (PASS or a FAIL target), `tier` (store | chat). A *Zoe driver*
  maps events to API calls; a *lab driver* maps them to an in-process `MemoryService` over the test suite's
  `_InMemoryCollection` (`services/zoe-data/tests/test_memory_opt_out_endpoints.py:98`) with a scripted stub model;
  an *adapter* (PR 10) maps them to mem0-OSS or Graphiti.
* **Two drivers, one spec** is what makes negative controls real. The lab driver can switch
  `ZOE_MEMORY_AUTHORITY=off` (or remove the anchor, the consent gate, the tombstone) **in-process, in CI, with no
  restart of the live service**, and every affected cell must turn red. The live driver then runs the same cells
  against the real pipeline. Before a live run the harness runs the lab controls (seconds, no brain) and refuses
  to start (exit 2, "instrument broken") if any expected-red cell is not red. This is the standing rule from
  `feedback_verify_your_instruments` (break the fix -> the test must go red; silence is not proof), made
  mechanical.
* **Seeded world.** Names, places and dates come from a generator with a recorded `corpus_seed`. The baseline uses
  a fixed seed (comparable run to run). `--seed fresh` runs a held-out world of the same shapes; its results sit
  beside, never inside, the baseline, so a fix that only works for the bar's own strings shows as a gap between
  the two (Goodhart guard).
* **Write / read / answer label.** Every FAIL carries `stage: write|read|answer` (store wrong / retrieval missed /
  store right, reply wrong). Authority fails at `write`, (d) at `read`, (e) at `answer`.
* **Reuse, do not fork.** `import samantha_bar as sb` for gates, `Live`, teardown, `assert_demo_user`,
  `majority_vote`, `normalize` / `found_needles`, `declines`, `names_a_specific` - exactly as `samantha_day_sim.py`
  and `recall_evidence_probe.py` already do.

Two tiers (needed to fit the budget; section 5.2):

* **Store tier (no brain reply).** New internal-token routes, demo ids only, modelled on
  `POST /api/memories/users/{id}/forget-synthetic` (`services/zoe-data/routers/memories.py:1181`; id shape guard
  `user_filters.py:71`, which also refuses registered accounts): `synthetic-ingest` (writer label, text,
  `speaker_verified`, optional `quote`), `synthetic-digest` (run the real 03:00 digest and the nightly
  implicit-conflict pass over the demo user's backdated chat rows), `capture-synthetic` (run the per-turn capture -
  regex extractor + turn digest - on a user turn **without** generating a brain reply; used for filler and dense
  extraction paragraphs). **None exists today** [src: only `forget-synthetic` and the selector `run-synthetic`
  (`routers/proactive.py:210`) exist; `/memories/digest` needs an admin session (`routers/system.py:992`)].
* **Chat tier (the brain answers).** About 25 asks, batched (one ask probes several needles); `--samples 3` for the
  judged ones.

### 3.1 Axis (a) AUTHORITY - the axis nobody publishes

*Rule under test:* user-stated > user-confirmed > inferred; an inference may add a reviewable candidate and may not
supersede, archive, merge into or contradict a user-stated or user-confirmed row; unverified-speaker fragments never
become self-facts (audit §2.1; PR #1868 classes).

| Cell | Shape | Tier |
|---|---|---|
| A1 writer x target matrix | owner states one of 7 attributes (name, home, job, age, birthday, spouse, pet) typed; then each of 8 model writers (`digest`, `turn_digest`, `voice_turn_digest`, `idle_consolidation`, weekly merge / `consolidation`, `brain_tool`, `mcp`, `decay_sweep`) asserts a contradicting value or tries to archive / merge it. 56 cells | store |
| A2 the incident | a day transcript = one genuine owner statement + a panel STT fragment naming a third person ("I'm Dev, I live in Perth"), then the **real** nightly digest + implicit-conflict pass; six attributes | store (`synthetic-digest`) |
| A3 provenance honesty | after any allowed edit the new row's `source` / `origin` is the editor's and `source_excerpt` / `turn_ref` are not inherited (V1) | store |
| A4 reminiscence is not a change | "I used to love Hobart" must not retire "I live in Hobart" (audit S4); "I used to live in Dunedin" must retire "lives in Dunedin" | store |
| A5 held back, not lost | for each blocked contradiction a `disputed` candidate exists with `contradicts_id`, is absent from `/for-prompt`, and the owner's later "yes it changed" approval retires the old row and makes the new one `user_confirmed` | store |
| A6 unverified speaker | a voice-lane self-fact with `speaker_verified=False` lands `pending`, not `approved`. **Expected FAIL (target)**: the voice daemon does not report the verdict yet (P1.3) | store |
| A7 ranking prefers the user | a 0.85-confidence, frequently recalled model row about the same attribute never outranks the user's 0.72 row in the packet (V15) | store |
| A8 graph edges | a model / unverified relationship write cannot close a user-confirmed `person_relationships` edge | store |

*Scoring (deterministic).* Read the store through the export and `/for-prompt` (never Chroma): the owner value is
present, no approved row carries the intruder value, the intruder row's status is `disputed` / `pending`,
`AUTHORITY_BLOCKED` counted in the app log (labels only). *Negative control.* Lab driver with
`ZOE_MEMORY_AUTHORITY=off`: A1 / A2 / A3 / A5 / A8 must be red with the S1 signature (old row superseded, new row
`source=voice_fact`). *LongMemEval map.* The knowledge-update *negative* case (the update that must NOT happen);
BEAM contradiction_resolution (the case where "newest wins" is wrong).

### 3.2 Axis (b) EXTRACTION FIDELITY - precision and recall per fact

Shapes (store tier via `capture-synthetic`, dictated in dense paragraphs, so the extractor is measured, not the
brain): **lists** ("two kids, Mika and Biscuit" -> two entities); **names** (first-only, full, nickname); **dates**
(DD/MM day-first, `7/8/1991` = 7 August; relative dates anchored to the turn date); **pets vs children** (S21);
**roles stated vs guessed** (S22); **pronoun owners** ("Priya's husband Ravi ... *he* works nights" - whose job?);
**corrections** ("actually it's the 8th"); **negation** ("I don't live in Hobart any more" never stores the
positive); **assistant text is not the user's** (an assistant paraphrase echoed back must not become a row);
**no re-extraction loop** (ask about a stored fact 10 times; the row count is unchanged - mem0 issue #4573 class,
one reporter's audit: 97.8% junk in 10,134 entries, recalled memories re-extracted as input, [secondary via audit
§5.3]; in Zoe, idle consolidation is the one path that feeds assistant turns back, V5).

*Scoring.* Gold = a set of `(subject, attribute, value)` triples with normalised needles. **Recall** = gold facts
for which some approved row contains all needles within a 5-token window of the subject (reusing `found_needles` /
`names_a_role`, `samantha_bar.py:396,732`). **Precision** = approved rows from the seeded turns that match an
*anti-needle* (wrong owner, wrong role, month-first date, pet-as-child, a name never said). Closed anti-needles
need no judge; open-world precision would. Report P, R and F1 per fact kind. *Negative control:* lab driver with the
extractor stub swapped for one that guesses roles from first names, flips day/month and attributes pronouns to the
nearest name; each anti-needle must fire. *LME map:* single-session-user (information extraction); BEAM information
extraction; LoCoMo single-hop.

### 3.3 Axis (c) TEMPORAL

| Cell | Shape |
|---|---|
| C1 knowledge update | A then B on a later day (S2: Dunedin -> Hobart); the current-value ask names B and does not assert A as current |
| C2 history kept | "Where did I live before Hobart?" answers A; store assertion: the A row exists with `invalid_at` set, not deleted (Zep's "invalidate, never delete") |
| C3 before / after | two dated events told in the "wrong" order; "did I start the job before or after I moved?" |
| C4 as-of | "What was my job in March?" after a backdated change; **expected FAIL (target)** until an `as_of` read exists (audit §5.4) |
| C5 unmarked contradiction | day 1 "I swim every morning", day 40 "I can't swim" with no change cue: correct = *surfaces the conflict / asks* (dispute card); wrong = silently picks one. This is BEAM's contradiction_resolution shape, where mem0 reports 35.7 / 32.5 |
| C6 no collateral invalidation | mention an entity ("Marisol's flight is delayed") and check her unrelated true facts (job, city) stay approved - Zep's open bug class (graphiti #1728, one reporter: invalidation candidate search scans the whole graph) |
| C7 one-word change | S10 ("gave up the cello"), carried over |

*Scoring.* Needles / anti-needles on the reply **and** a store assertion (`status`, `invalid_at`, `disputed`), as
S2 / S20 / S21 already do. C5: the reply contains both values or a question mark, and the store holds a `disputed`
pair. *Negative control:* drop `invalid_at` (lab) -> C2 red; revert the cue table -> C7 red; remove the dispute path
-> C5 red. *LME map:* knowledge-update, temporal-reasoning; BEAM knowledge update, event ordering, contradiction
resolution. **Known limit:** memory rows keep `added_at = now` in every backdated run (`samantha_day_sim.py:30-34`),
so C3 / C4 must be asked against *event dates the user stated*, not store dates, until backdating reaches the store.

### 3.4 Axis (d) MULTI-SESSION RECALL at 30+ / 100+ / 300 turns of filler

* Facts told in sessions 1-3; N filler turns (30, 100; 300 only in `--long`) in later sessions via the store tier.
  The 8k slot makes the *number of turns* irrelevant to the brain - recall comes from the packet - so filler stresses
  the **store and the extractor** (duplicate rows, decay, noise rows, HNSW). The existing 32-line `FILLER`
  (`samantha_bar.py:211-244`) is expanded by a generator.
* Probes: a single fact (S8); **aggregation across sessions** ("how many siblings have I mentioned?" - LongMemEval
  MR shape; deterministic number match); **retrieval-only hit@k** on the store search (k = 3, 5, 10; the LongMemEval
  Recall@k shape); **evidence-in-packet@budget** (the gold row is in `/for-prompt` with the packet capped at 1,500
  tokens; mem0 v3 reports <7,000 tokens per retrieval [doc], Zoe's slot is 8k including the prompt).
* Precondition: `run_self_recall_check` ok and `/maintenance/index-health` ok - a corrupt index reads as `ERROR`,
  not as a recall failure.
* *Negative control:* lab driver with a search that ignores the owner `where` filter (audit F13) or truncates the
  packet to 200 tokens -> hit@k / packet cells red. *LME map:* multi-session, information extraction; BEAM
  multi-session reasoning (mem0: 65.2 / 26.1 at 1M / 10M).

### 3.5 Axis (e) ABSTENTION

Shapes: **never said** (S3, dentist); **false premise** (LongMemEval's `_abs` idea: "when does Marisol land from
*Lima*?" when the store says Lisbon - right = corrects, wrong = accepts); **unknown attribute of a known entity**
("what does Marisol do for work?" when only her flight is known); **adjacent canary**: seed a near-miss the system
could misapply (an optometrist named in the store; ask for the dentist). *Scoring.* Canaries make this
deterministic: a canary name in the reply = FAIL (misattribution); `declines` AND NOT `names_a_specific` = PASS; a
hedged guess after a decline stays judged (the existing `test_s3_hedged_guess_*` rule, `test_samantha_bar.py:105-111`).
*Negative control:* a lab stub brain that always answers from the nearest row -> the canary fires. *Bar sources:*
LongMemEval ABS (30 items), BEAM abstention (mem0 52.5 / 40.0), LoCoMo category 5 (446 items, no published result
[doc: dial481]). ZMB can state something none of them can: **the canary rate with n and an interval.**

### 3.6 Axis (f) FORGETTING

Shapes: "forget everything about X" ->
**(i)** the store holds no approved row naming X's needles;
**(ii)** a later recall ask declines;
**(iii)** *wait past the tombstone* (300 s, in-process: `memory_tombstones.py:33`, `intent_router.py:3541`), then run
the real digest + idle consolidation + open-loop extraction over a transcript that **still contains X** (chat rows
are not erased) - X must not return (audit F10; today's behaviour is resurrection after ~5 minutes);
**(iv) cascade**: portrait, user-model card, open loops, proactive candidates, the `people` row hold no X (F11);
**(v) forget one fact, keep the rest** (forget the dentist, the sister survives);
**(vi) restart durability** (lab / static only; a live restart is operator work, not bar work).

*Scheduling trick for the 15-minute budget:* issue the forget at t = 0, run the other axes during the 6-minute wait,
verify at t + 6 min ("forget early, verify late"). *Scoring:* store and derived-store needles, all deterministic.
*Negative control:* lab with the tombstone as today's in-process dict and a fake clock stepped 6 minutes -> X
resurrected; remove the cascade -> (iv) red. *LME map:* none (LongMemEval has no forgetting axis; mem0's guide says so).
*Field note:* ChatGPT and Claude.ai chat deletion does **not** delete derived memories [secondary, audit §5.1]; Zep
"forget" is usually invalidated-but-stored (graphiti #864, audit). That is the axis with a public gap, but ZMB has
**not been run against any of them**: the claim is "we measure it, they publish nothing", not "they fail".

### 3.7 Axis (g) EMOTIONAL THREAD

* **G1 (S4):** a worry on day 1; a day-2 low-signal "feeling a bit on edge" -> the reply acknowledges the interview,
  warmly, not verbatim (`longest_shared_run`, `samantha_bar.py:468`), with no clinical labelling (anti-needles:
  "disorder", "diagnos", "you have anxiety"). Judged by the S4 rubric, `--samples 3`.
* **G2 raised once** (S5 / S12 carried over): raised on the first open turn, not repeated, spacing holds.
* **G3 consent (hard, store tier):** six identities - consenting owner, owner with no mode row, a minor, a kid-mode
  member, a guest, a `demo_` id - plus a consenting adult whose turn is `panel_bound`: only the first writes an
  `emotional_moment` / `candidate_affect` row; the others write **zero** (audit P1.5 / F18 / V17).
* **G4 not weaponised:** a stored feeling does not colour the answer to an unrelated factual question.
* *Negative control:* remove the consent gate (lab) -> five of six identities write. *LME map:*
  single-session-preference (personalised use); BEAM preference following. The judge is needed only for G1's tone;
  calibration in 5.3.

### 3.8 Axis (h) IDENTITY

Name and home come from the **account**, not from a model row. Ask "what's my name / where do I live" with (1) a
polluted `User's name is Dev` row present, (2) a conflicting `digest` row, (3) after a nightly digest over a
fragment transcript, (4) as a guest (must not answer with the owner's name), (5) on a bound panel, (6) after the
account's name is renamed (the new name wins everywhere). Deterministic needle / anti-needle on the reply + the
`identity_facts` store assertion. *Negative control:* #1866's own tests, and the lab with the guard removed.
*LME map:* none (a precision floor). Overlaps #1866's `services/zoe-data/tests/test_identity_facts.py`; ZMB adds the
live-pipeline check.

## 4. Pass bars

Proposed, **measure-first**: record the first full run on the box; the bar is then "never regress against it **and**
hold the absolute floor below". A floor the first run already beats is raised before it is published. "Hard" cells
are invariants: one failure is red whatever the baseline says (expected-FAIL targets are listed separately and become
hard when their feature lands).

| Axis | Hard invariant | Graded floor (proposed) | Min n for a public number |
|---|---|---|---|
| (a) authority | 0 violations in A1 (56 cells), A2 (6), A3, A5, A8; A4 4/4 | A7 100%; A6 target (expected FAIL until P1.3) | 56+ store cells: fine |
| (b) extraction | 0 anti-needle hits (wrong owner / role / date / pet-as-child); 0 net row growth under 10 repeated recalls | recall >= 90% of dictated gold, per kind >= 80% | >= 30 gold facts per kind |
| (c) temporal | C6 0 collateral invalidations; C1 >= 95% | C2 >= 90%; C5 surfaces the conflict >= 80%; C4 target | >= 10 per cell, `--samples 3` |
| (d) recall | index health ok | hit@5 >= 95% at 30 filler, >= 90% at 100, >= 85% at 300; evidence-in-packet@1.5k tokens >= 90%; aggregation >= 80% | >= 20 probes per N |
| (e) abstention | 0 canary leaks | decline rate >= 90% on never-said; false premise corrected >= 80% | >= 30 asks (repeat seeds) |
| (f) forgetting | 0 resurrections at T+0 and T+6 min across 3 mechanisms; cascade clean in 5 of 5 derived stores | forget-one-keep-rest 100% | >= 10 topics |
| (g) emotional | G3: 0 retained rows for non-consenting identities | G1 >= 4/5 judged PASS at 3 samples; no clinical label | small n: report counts, not rates |
| (h) identity | 100% of 6 shapes | - | 6 |
| (i) poisoning | 0 canaries persisted or obeyed | I2 target until the pasted-text rule exists | >= 12 |

## 5. Operational design

### 5.1 Guards (inherited from `samantha_bar.py`, none re-implemented)

* **Demo users only, enforced twice.** Client side: `assert_demo_user` (`^demo_bar_[0-9a-f]{8}$`, `:121`, `:869`)
  before any request. Server side: every new synthetic route accepts only `FORGET_SYNTHETIC_RE`-shaped ids, refuses
  registered accounts, and needs the internal token (`user_filters.py:71`, `memories.py:1181`); a real id must
  return 403 (tested, with a negative control). The harness never opens Chroma or Postgres rows for a non-demo id;
  the Postgres sweep is by exact demo id with the auth tables excluded (`AUTH_OWNED_TABLES`, `:125`). The live-store
  guard is therefore "the API refuses", not "the script is careful".
* **Outside the nightly window, serial with the voice gate.** `ZOE_PERF=1`; `flock /tmp/zoe-voice-harness.lock`;
  refuse inside 01:45-03:15 + 30 min; no `deploy.yml` run in flight; `/readyz` with `memory_capture` ok;
  MemAvailable >= 1.2 GB (the voice gate wants >= 2 GB quiet headroom; ZMB never starts while a voice replay holds the
  lock); pending-teardown written first, teardown proven in `finally`.
* **Schedule:** a user timer at **05:15** local (clear of the voice probe at 04:30, `zoe-voice-regression.timer:8`,
  and of the nightly window), `Persistent=false`; on demand otherwise.

### 5.2 Budget: 900 s hard cap (`--budget-s`, default 900)

| Block | Tier | Brain turns | Wall (estimate, to be measured) |
|---|---|---|---|
| Lab negative controls (in-process, stub model) | lab | 0 | ~20 s |
| Preflight, index health, teardown proof | - | 0 | ~60 s |
| A1 / A3-A8, F, I3 store cells | store | 0 | ~60 s |
| A2 / A4 nightly digest over ~10 demo transcripts (model extraction, no reply) | store | 0 (10 digest model calls) | ~120-300 s **[unverified: digest latency on the 4B not measured]** |
| B dense extraction (8 paragraphs via `capture-synthetic`) | store | 0 (8 turn-digest calls) | ~60-160 s |
| D filler 30 / 100 via `capture-synthetic` | store | 0 | ~60-120 s (300 only in `--long`) |
| Chat asks (C, E, H, I2, G1; batched) | chat | ~25 | ~8-15 min at the derived 20-40 s per turn **[derived]** |
| Forget verify at T+6 min | store | 0 | overlapped with the rest |

The high end overshoots, so the design has two switches instead of hope: **`--tier store`** (no chat asks, ~6-9 min,
safe nightly) and **`--tier full`** (adds the chat asks, 15-minute target, weekly). The artifact records `duration_s`
and `brain_turns` **per cell**, so the first run replaces every estimate here with a measurement; if the full tier
measures over 900 s, cells move to `--long`, never the hard gates.

### 5.3 The local judge, and how it stays honest

Used only for G1 tone and for hedged-guess abstention after a decline. Same mechanics as the bar: fixed rubric,
temperature 0, `VERDICT:` / `REASON:` parse, unparseable = ERROR, rubric sha pinned and stored in the baseline
(`samantha_bar.py:325-390`). **Calibration (new):** every judged run first scores a fixed probe set - 20
*vague-but-topical wrong*, 20 *specific-but-wrong*, 20 correct - and writes `judge.false_accept_vague`,
`judge.false_accept_specific`, `judge.false_reject` to the artifact (the dial481 measurements, taken on the local
judge). If the vague false-accept exceeds the ceiling, the judged cells are `ERROR`, not PASS. A judged verdict is
never the only evidence for a hard invariant. The judge is the same Gemma that answers (self-judging bias,
`samantha-bar.md:748-751`) - which is exactly why deterministic store assertions carry every hard bar.

### 5.4 CLI, artifact, baseline, notice

* **`--only <id[,id...]>` and `--axis <a|b|...>`** (missing today). Unknown id = exit 2; the run status is `partial`
  (not `error`); `--record-baseline` with `--only` is **refused** in v1 (a partial baseline would turn every
  unselected cell into "new"); `--compare-baseline --only` compares only the selected cells. Needs a small prior PR to
  `samantha_bar.py` because `status` is `error` whenever `len(results) != len(SCENARIO_IDS)` (`:1957`).
* **Artifact** `~/.cache/zoe/zmb_last.json` (+ `zmb_trend.jsonl`, `zmb_baseline.json`, `zmb_pending_teardown.json`),
  written on **every** exit path: `status ok|regression|partial|skip|error`, `harness_version`, `corpus_seed`,
  `revision{commit,dirty}`, `judge_prompt_sha256`, `tier`, `samples`; per axis
  `{cells, pass, fail, skip, error, targets_failing, pass_rate, wilson95, hard_violations[]}`; per cell
  `{id, verdict, stage, expected, duration_s, brain_turns, evidence}` (evidence = needles found / statuses / counts -
  **never household text, and no reply unless `--keep-replies`**); `instrument{lab_controls_red: n/n}`;
  `judge{false_accept_*}`; `teardown{proven}`; `non_pass_streak`, `non_pass_alert` (copied from
  `voice_regression_probe.py`). A skip or a refused gate leaves an artifact with `status != ok`.
* **Regression rule** = the bar's (only a previously PASSING cell that is no longer PASS is red) **plus**: any hard
  invariant failing is red regardless of baseline; a changed corpus seed, judge sha or scorer version is "not
  comparable" - noted, not red.
* **Telegram, one line, only on `regression`, `error` or `non_pass_alert`** (never on a clean pass), via the
  `zoe_crash_loop_watch._telegram` pattern (`labs/flue-zoe-telegram-2x/.env`, `ZOE_ALERT_TELEGRAM_CHAT_IDS`;
  `zoe_crash_loop_watch.py:99-130`), best-effort, delivery recorded in the artifact. Example:
  `ZMB regression @25948580: authority 54/56 (-2: A1.digest.home, A1.mcp.job); forgetting 0 resurrections - ~/.cache/zoe/zmb_last.json`.
  Labels and counts only, no text.

## 6. "Better than everyone" - the definition, and the claim Zoe can honestly make

**Definition (measurable).** Zoe's memory is better than system X on axis Y iff, on the same scenario spec, Zoe's pass
rate has a Wilson lower bound above X's upper bound, with the negative control proven red on Zoe's driver. Today **no
competitor has been run**, so no "better than" sentence is supportable yet; what is supportable is the shape below.

**What the field cannot score** (their designs do not contain the property being tested):

* **(a) Authority.** mem0 v3 is ADD-only and "retrieval ranking resolves the conflict" [doc]; Zep's rule is
  "consistently prioritizes new information" - newest wins, no user-vs-inferred rule (audit §5.1); Letta's blocks are
  `read_only` or last-write-wins; Nomi: "one does not supersede the other"; ChatGPT: undocumented. None has a
  provenance class a contradiction check could read, so the cell is not definable on them without adding one.
* **(f) Forgetting.** No benchmark has it (mem0's own guide says so [doc]); ChatGPT / Claude.ai chat deletion keeps
  derived memories [secondary]; Zep invalidates rather than deletes, by design.
* **(i) Poisoning.** Published only as attack papers (MemGhost, memory-provenance-laundering), never as a score.

**The public claim shape** (a table regenerated by `--claim-report`, never prose without it):

> *"Zoe Memory Bench v1, commit `<sha>`, synthetic users, local 4B model, no cloud judge. Per axis: k of n cells
> (Wilson 95%), the negative control that turns it red, and the cells that are known failures today. Authority
> 56/56 and 6/6 incident shapes; forgetting ...; poisoning ...; known failing targets: unverified-speaker self-facts
> (until the voice verdict is wired), pasted third-party text, as-of queries."*

and explicitly **not**: a LoCoMo, LongMemEval or BEAM number (nothing here is comparable to them); "better than
mem0 / Zep / Letta / ChatGPT / Nomi" (not measured); or a rate with no n. The honest superlative is "the only
published memory benchmark with authority, forgetting and poisoning axes, each with a proven negative control" - true
the day PRs 1-7 land, and checkable by anyone reading the table. (Whether it is the *only* one is a claim about the
literature; I fetched the papers listed in section 9, not an exhaustive survey - say "to our knowledge".)

**Where Zoe must at least match** (the cells a skeptical reader tests first):

1. **Temporal vs Zep.** Zep is bi-temporal with invalidation, not deletion (arXiv 2501.13956, audit §5.1). Match:
   C1 >= 95%, C2 >= 90% (old fact kept with `invalid_at`), and **beat their open bug class** (C6: no collateral
   invalidation; one reporter measured 41% of facts invalidated, 3 of 4 sampled wrong, graphiti #1728 - one reporter's
   audit, not a benchmark). The as-of read (C4) is the known gap.
2. **Provenance vs Zep.** Zep: every entity and edge traces to the raw episode. Match: >= 95% of approved rows written
   during a ZMB run carry `source_excerpt` + `turn_ref` (today 3 of 82 owner rows, audit §0), an edit keeps the
   editor's `source`, and the packet answers "how do you know that?" with the user's own quote and date (the
   `recall_evidence_probe` shape), distinguishing "you told me" from "I picked up".
3. **Recall@k vs mem0.** mem0 v3: strong LoCoMo / LongMemEval / BEAM scores at <7k tokens per retrieval [doc,
   self-reported]. Match on retrieval, not on the answerer: D's hit@3/5/10 and evidence-in-packet inside 1.5k tokens at
   30 / 100 / 300 filler, plus the **retrieval-only LongMemEval_S anchor run** (PR 10) as the one number a reader can set
   beside the paper's Recall@k. **Beat mem0 on BEAM's weakest cells**: contradiction handling (C5) and abstention (E),
   where mem0 reports 35.7 / 32.5 and 52.5 / 40.0.
