# The three risks the previous currency sweep deferred, and what the audit found.
# Keep this note current — it is the reason the pins are safe to hold here.
#
#   * `strict_content_type` (FastAPI 0.132.0, default TRUE). A request is only
#     affected if the route declares a NON-FORM body AND the request carries a
#     non-empty body; the header is then required to be `application/*json`
#     (fastapi/routing.py:428-450). Every zoe-auth caller in the repo was
#     enumerated: all server-side Python uses httpx/aiohttp `json=` (which sets
#     the header), all browser JS sets it explicitly or goes through a wrapper
#     that does, and nginx never rewrites Content-Type. Bodyless POSTs (logout,
#     logout/all, reset-password) are unaffected either way. The OIDC endpoints
#     — the only ones EXTERNAL clients (Home Assistant, n8n, Matrix) call — are
#     all `Form(...)`, which takes the form branch and is not subject to the
#     check at all. So the default stays TRUE; we did NOT weaken it.
#   * Starlette 1.x. zoe-auth has ZERO direct `starlette` imports and already
#     uses `lifespan=` (not `@app.on_event`), so nothing removed in 1.x is
#     reachable. Verified by grep over the whole service.
#   * pydantic re.match -> re.search for `Field(pattern=)` (2.9.0). All five
#     `pattern=` constraints in this service are the passcode `^\d+$`, already
#     anchored at both ends, so the switch is a no-op for them.
#     tests/test_passcode_pattern_anchoring.py pins that: it asserts an
#     embedded-match passcode is REJECTED, which is exactly what an unanchored
#     pattern would start allowing. There are no multi-type Unions (only
#     `Optional[X]`), so 2.8.0 smart-union is not engaged, and no
#     `@model_validator` anywhere, so the 2.12 instance-method change is moot.
