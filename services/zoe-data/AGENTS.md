# services/zoe-data/ — production web + chat API

## Purpose

THE production Zoe API: FastAPI app served by host uvicorn on port 8000. Owns chat, intent routing, memory, MCP tools, auth integration, and background jobs. (It also still CONTAINS the OpenClaw/Hermes agent bridges, but those are retirement targets — see Local Contracts — not owned capabilities to extend.)

## Ownership

- App entry and core: `main.py`, `database.py` (+ `db_pool.py`, `db_compat.py`, `alembic/` migrations), `auth.py`.
- Routing/NLU: `intent_router.py`, `intent_classifier_llm.py`, `pi_intent_classifier.py`, `routers/` (see child doc).
- SetFit router head + two-stage router: `semantic_router.py` optionally loads the logreg head (shadow) and, via `router_two_stage.py`, the MLP head (both trained in `labs/setfit-router`; never import from `labs/` at runtime). Both go through `router_heads_numpy.load_head()`: the default `ZOE_ROUTER_HEADS_BACKEND=numpy` serves `models/router_head_{logreg,mlp}.npz` + `.json` with pure numpy — **zoe-data never imports scikit-learn/scipy/joblib** (pinned by `tests/test_router_heads_numpy.py`, which also holds sklearn parity ≤1e-6 on a committed 50-vector corpus fixture, a negative control, and a joblib-sha drift check); `joblib` is the one-release fallback that unpickles the `.joblib` training artefacts. The configured paths (`ZOE_ROUTER_HEAD_PATH` / `ZOE_ROUTER_HEAD_MLP_PATH`) stay the `.joblib` names; the numpy backend reads the pair beside them. A CUSTOM `.joblib` path (outside `models/`) with NO export beside it falls back to joblib for that head only (WARNING logged, sklearn imported) instead of disabling the head. A SHIPPED head (inside `models/`) with a missing export is an ERROR — the head is disabled, sklearn is never imported for it; a stale/tampered export always refuses. **Retraining a head means re-exporting it**: copy the new `.joblib` in, run `scripts/maintenance/export_router_heads.py --corpus --fixture services/zoe-data/tests/fixtures/router_heads_parity.npz` under the training pins, commit all four model files + the fixture (each export file is whitelisted in `.gitignore` by name). Flag `ZOE_ROUTER_HEAD` = `off` (default) | `shadow` (logreg head logs prediction/agreement, never routes) | `shadow2` (the FULL two-stage decision — MLP top-3 shortlist + 0.5 chat gate + grammar-constrained FunctionGemma sidecar on :11436 — computed in a background thread and logged, never routes) | `active` (the two-stage decision picks the domain; execution stays in expert dispatch; ANY sidecar failure/timeout/gate-abstain falls back to similarity → brain — the Gemma 4 brain remains the rock; this is a fast-tier front, proven 90.1%/0% chat-FP in `labs/router-90-campaign`). Sidecar unit: `scripts/setup/systemd/functiongemma-router.service`. Env: `ZOE_ROUTER_SIDECAR_URL`, `ZOE_ROUTER_TWO_STAGE_GATE` (0.5), `ZOE_ROUTER_TWO_STAGE_TIMEOUT_S` (1.5). Rollback = `ZOE_ROUTER_HEAD=off` + restart. Logs — utterance HASH only, never raw text — go to logger `zoe.router_head_shadow` and `data/router_head_shadow.jsonl` (gitignored); score with `scripts/maintenance/router_shadow_report.py`. The file is **rotated, never truncated**: append goes through `_append_shadow_line`, which rolls the log to `<log>.1`/`.2`/… past `ZOE_ROUTER_SHADOW_MAX_BYTES` (16 MB) keeping `ZOE_ROUTER_SHADOW_KEEP` (4) segments — ~80 MB ≈ 1.7 years at the observed ~133 KB/day (0 disables). Truncation is NOT an option: the self-train miner reads the WHOLE history (`--since` defaults to 0), so dropping records in place would silently starve the mine→label→ratchet loop. **Readers MUST go through `semantic_router.shadow_log_segments(path)`** (oldest→newest) — the miner and both shadow reports do; anything reading only `<log>` silently sees just the newest slice. Pinned by `tests/test_router_shadow_rotation.py`. The training-pin agreement rule (scikit-learn/joblib = `labs/setfit-router/requirements.txt`) now binds the EXPORT step, not the runtime: the numpy heads do not depend on any sklearn version. zoe-data's manifests still pin `scikit-learn`/`joblib` only because librosa (Resemblyzer, speaker ID) declares them as install requirements — and, until the joblib fallback is removed, at the training pins so that fallback can unpickle. Voice-path files ⇒ replay-gated — and so is **`models/` itself**: `services/zoe-data/models/*` is a directory glob in `VOICE_PATH_PATTERNS`, because swapping a tracked head re-routes every voice turn with no code diff. Both heads are **hand-committed**; the `ZOE_ROUTER_SELFTRAIN` ratchet promotes only the stage-2 GGUF to `~/models/functiongemma-router/` (outside the repo) and covers **nothing** in this directory. Copy a promoted head in from `labs/setfit-router/artifacts/` (which stays ungated) and expect the PR/deploy gate to demand a fresh revision-bound replay artifact. Pinned by `tests/test_router_head_shadow.py` + `tests/test_router_two_stage.py` (`ci_safe`) and `tests/unit/test_voice_gate_check.py`. Public harness contract: `semantic_router.route_two_stage(text) -> RouterDecision` (dataclass: tool/args/confidence/source/latency_ms) — standalone with the sidecar up, no server; the 81-case corpus-through-prod-path harness ships separately against it.
- Pi intent/hybrid evidence JSONL: `pi_intent_evidence.py` — every write goes through `_append_jsonl`, which holds an **exclusive `fcntl.flock` on the target across BOTH the append and the `_prune_jsonl` trim**. The trim is a read-modify-write (read all rows → `seek(0)` → rewrite → `truncate`), and `record_pi_hybrid_production_evidence` always passes a positive `max_records`, so the trim runs on EVERY write. Unlocked, concurrent writers silently lose records — `pi_hybrid_production.try_pi_hybrid_production`'s fast-accept branch has two (the awaited accepted-decision write and the fire-and-forget `_schedule_pi_audit_after_fast_accept` audit write, both via `asyncio.to_thread`), and the lane is SCORED on this evidence. Keep the inode (never rename/replace the file — flock follows the open file description, not the path), and keep `_prune_jsonl` lock-free so it can't deadlock against its caller's hold. Pinned by `tests/test_pi_intent_evidence.py::test_append_jsonl_does_not_lose_records_under_concurrent_writers` (`ci_safe`).
- Agents and tools: `mcp_server.py`, `openclaw_ws.py`, `hermes_http.py`, `zoe_agent`-related modules, `executors/` (engineering-board executors: `kanban_adapter.py` + `executor_queue_backend.py`).
- Browser surface: `browser_broker.py` — plan/executor registry over ONE Zoe-native CloakBrowser surface (stealth Chromium, Playwright-compatible; `zoeCloak`, with `hermesCloak`/`harness` as execution aliases). Two output modes, and the mode is chosen by the PLAN ACTION: any action returns a base64 PNG (`image_base64`), **except** `extract_text`/`fetch_text`, which return page TEXT and deliberately skip the screenshot. Text mode is opt-in precisely so existing callers (chat.py research screenshots, the MCP browser tool) are byte-identical — pinned by `tests/test_browser_text_extract.py`. Extraction is `extract_main_text(html) -> ExtractedText`, a **pure stdlib function** (`html.parser`, no `readability`/`bs4`/`lxml` — none are declared deps here, so requirements.txt is untouched) doing readability-lite main-content selection: drop-list for `script`/`style`/`nav`/`header`/`footer`/`aside`; then the semantic shortcut over `<article>`/`<main>` containers clearing the 200-char floor — a `<main>` wrapping a qualifying `<article>` is DROPPED first (it always holds more text than the article inside it, so pure length could never pick the tighter node and the shortcut returned article + related-cards), then longest wins among the survivors. The drop is deliberately wrapper-shaped and NOT "any ancestor": `<article>` inside `<article>` is the spec's idiom for COMMENTS, and demoting the parent there would return one comment and discard the post; then container scoring by text volume discounted by **quadratic** link density plus a deepest-near-tie tie-break — linear discounting lets the outer wrapper beat the article by a hair and drags every nav/footer line in with it. Every tree walk is ITERATIVE (explicit stack, `_BLOCK_END` sentinel for the post-order newline): page depth is publisher-controlled, a recursive render raised `RecursionError` at ~1000 nested elements, and nothing on the text path catches it — pinned by `test_a_deeply_nested_page_extracts_instead_of_raising`. It reports its own `strategy` (`semantic:<article>` | `scored-container` | `fallback:whole-document` | `empty`), which is what the tests assert on. Callable three ways: the pure function (the offline test seam), `await fetch_page_text(url)` in-process, or `await execute_text_extraction(broker, url=…)` through the normal plan pipeline. Both live paths SSRF-guard via `assert_public_url` + `guard_browser_page` and return `{"ok": False, "error": …}` rather than raising, so a failed enrichment degrades a search packet instead of breaking the turn. NOT a voice-path file (verified against `voice_gate_check.VOICE_PATH_PATTERNS`) — no replay gate.
- Agent security helpers: `agent_safety.py` — the single home for the bash-tool shell-injection guard (argv parsing, no shell) and the SSRF guards: `assert_public_url` (web fetch), `assert_panel_host` (panels = private-LAN only; loopback/link-local/metadata/public always rejected, allowlist narrows but never bypasses), `guarded_urlopen` (validates + **pins the connection to the validated IP**, defeating DNS-rebinding), and `guard_browser_page` (Playwright `page.route` that validates every request/redirect hop pre-connect). Stdlib-only so it loads in slim CI.
- Memory: `hindsight_memory.py`, `hindsight_retain_candidates.py`, `conversation_context.py`.
- Web lookup for research turns (B10.0): `research_evidence.py` + `web_search_provider.py`. `fetch_web_fallback` returns a `WebFallbackOutcome` (`status` ∈ results/no_results/blocked/error/off, `provider`, rows) — a DuckDuckGo challenge page (HTTP 202 + `anomaly-modal`, or a captcha/Cloudflare body at ANY status; `classify_ddg_response`, `DDG_BLOCK_MARKERS`) is `blocked`, NEVER `no_results` — but a page WITH `result__a` links is a results page even if a snippet or the echoed query mentions a wall phrase (markers are consulted only once result links are absent); `no_results` is a POSITIVE verdict that needs DDG's empty-results shell (`class="no-results"`, `DDG_EMPTY_RESULTS_MARKERS`) — any other anchor-less 2xx body (blank, truncated, consent/maintenance, markup change) is `error` with detail `unrecognised page (HTTP n)`. `build_package(..., web_lookup=...)` carries that status in the package (`web_lookup`) and renders an honest "Web lookup unavailable" / "Nothing found" row instead of a fabricated `duckduckgo.com/?q=` source. Provider order is `ZOE_WEB_FALLBACK_PROVIDER` (per-call env read): `auto` (default) = Tavily first when `TAVILY_API_KEY` is set and `ZOE_SEARCH_PROVIDER` is not `ddg` (`tavily_search_outcome`, status-aware; `tavily_search_sync` is the bare-list compat), then DDG; the best-quality verdict is kept — `results` beats everything and a completed Tavily `no_results` is NOT overwritten by a later DDG `blocked`/`error` (provider `tavily`, DDG's attempt in `detail`); `duckduckgo` forces the scrape; `off` makes no request. `fetch_web_fallback_results` is the bare-list compat shape `zoe_agent._ddg_search_sync` still consumes and is deliberately DDG-ONLY (`_web_search_ddg` already ran Tavily itself; going through `auto` would spend a second credit). A Tavily HTTP 200 without a `results` list is `error`, not `no_results`. `routers/chat._build_research_package` skips `_capture_research_screenshot` only when the rebuilt package has NO source at all (lookup failed AND the reply cites no URL; a reply's own URL is still captured whatever the lookup outcome) — otherwise the capture's `default_source_for_query` fallback would navigate to a DuckDuckGo URL, so `off` would still send the query out and a search-page image could be shown as evidence of a failed lookup. One INFO line per lookup (`web_fallback: provider= status= results= query_len=`) — never the query text. Backend status surface: `research_evidence.web_lookup_status()` (resolved `provider`, raw `configured`, `tavily_key_present`, in-process `last_outcome` {status, provider, detail, at} — never the query or the key) is served as the `web_lookup` block of `GET /api/system/status` (`routers/system.py`); the config fields go to every caller, `last_outcome` only to a signed-in non-guest (it is process-wide activity, `_web_lookup_block_for`). Pinned by `tests/test_web_fallback_honesty.py` (mutation-checked negative controls).
- Brain-callable web search (B10.1, FLAG-DARK): `ZOE_WEB_SEARCH_TOOL=1` (per-call env read; `research_evidence.web_search_tool_enabled`) serves `POST /api/system/web-search` (`routers/system.py`, same `require_intent_dispatch_auth` gate as intent-dispatch; body `{query, max_results≤5}`) = `fetch_web_fallback(…, WEB_SEARCH_TOOL_PROVIDER_TIMEOUT_S, enrich_prices=False, deadline_s=WEB_SEARCH_TOOL_DEADLINE_S)` + `web_search_tool_payload` (the outcome fields verbatim + ≤5 title/url/snippet rows, nothing else from a row). Trust boundary (W15, enforced in the SIDECAR, `src/untrusted-content.ts`): results reach the model fenced (fixed untrusted-content preamble + delimited block, markup/control tokens/role markers neutralised, fields capped, http(s) links only) and a turn that received results refuses every state-changing tool AND any further `web_search` (an outbound exfiltration channel) until it ends — zoe-data returns the rows as data and must not pre-render them into prose the fence would not cover. `web_lookup_status()` carries `tool_enabled`. Never log the query. Pinned by `tests/test_web_search_tool.py` (caplog tripwire with negative control) and the sidecar's `test/web_search_tool.test.ts`.

- B1.1 speculative turn-start: `voice_speculation.py` — flag-gated (`ZOE_SPECULATIVE_TURN`, default OFF, per-call env read) server-side speculation gate for `/api/voice/turn_stream`. The panel daemon fires the turn at its FIRST end-of-turn verdict (`speculative: true` + `turn_id`); the gate is registered BEFORE STT (a verdict can never outrun it), forwards non-audible frames, HOLDS every audible frame (`chunk`+b64 line, `full_audio`, greeting/filler chunks) in order, and releases only on a `commit` or transcript-equivalent `resolve` verdict from `POST /api/voice/turn_stream/speculation`. `cancel`, a non-equivalent `resolve`, or the `ZOE_SPECULATIVE_MAX_HOLD_MS` (5000) valve drops the held audio, closes the upstream generator (its `finally` cancels the brain task) and ends the stream with `{"done": true, "cancelled": true}` — nothing audible for a cancelled turn, ever, and a committed turn is released exactly once. Every gated stream LEADS with `{"speculation": "gated", "turn_id"}` (`ack_frame`) — the daemon's proof the server is gating; never emitted with the flag off. An EMPTY speculative transcript (nothing processed) closes the slot and answers `cancelled` (`reason: empty_transcript`) DIRECTLY, bypassing `gate_frames`, so the daemon runs the full recording: it is an upstream fact, not a verdict, and the daemon's commit routinely wins the slot before STT returns (fire→commit ≈ 320-480 ms < a Moonshine pass) — through the gate a won commit would pass a plain `done` and the turn would be lost; the non-speculative empty path is unchanged. A verdict that lands before the router's generator was ever pulled (cancel during STT) still cancels the brain task: `gate_frames` primes a never-started upstream to its first yield before `aclose()`, because `aclose()` on an unstarted async generator skips the `finally` that cancels `sub_task`. `turn_id` is request-supplied: `open_gate` refuses an id whose gate is still unresolved (`DuplicateTurn` → 409) rather than replacing it. Flag off: the fields are never read (wire bytes identical) and the verdict endpoint is 409. Metric `zoe_voice_speculation_count{outcome=commit|equivalent|cancel|hold_timeout|empty_transcript}` — only `cancel` is a user interruption for the cancellation-rate gate. **Phase 2 — side effects wait for the verdict** (same flag): the router `bind`s the gate into a `ContextVar` for the `voice_command` task and `gate_frames` runs every pre-verdict upstream pull under it (the brain lane executes inside the lazily-pulled body, not the task). While a speculative turn is unresolved: `voice_command` holds the WHOLE turn before any side effect unless the intent layer calls it read/chat (`turn_is_speculation_safe`: regex `detect_intent` ∈ `SPECULATION_SAFE_INTENTS`, Skybridge (domain, action) read-only, a routed domain outside {chat, weather, time}; a MISSING routed domain — router off, its default — is NEUTRAL, so the verdict then rests on the read allowlist + the Skybridge pair); the write funnels hold again for anything that misjudges — `intent_router.execute_intent` (every non-read intent), `skybridge_service.resolve_skybridge_request` (non-read actions), `expert_dispatch.dispatch` (write/expert kinds, before slot extraction); `_spawn_bg` queues every background side effect (history rows, memory passes, escalations) and runs them in spawn order BY COMPLETION via `defer_until_commit` (a 60 s cap only guards a wedged predecessor, with a WARNING); and `POST /api/system/intent-dispatch` (brain tool writes — a SEPARATE request the ContextVar cannot reach) holds a non-read intent ONLY when it carries the originating turn's `speculative_turn_id` — `zoe_flue_client` puts the bound turn id on an OUTERMOST ` zoe-spec:<id>` envelope line (wire 2 only; mirrored by `labs/flue-zoe-brain-2x/src/speculative-turn.ts`, prefix pinned equal) and the sidecar echoes it on every dispatch; other sessions' writes run at once; a dispatch arriving after its gate closed follows the recorded verdict (`_RECENT_VERDICTS`); an id with neither a gate nor a recorded verdict (e.g. zoe-data restarted mid-turn) is REFUSED while the flag is on — fail-closed, a cancelled turn's write must never run; on any refusal it answers `ok: false` with `reason` (`speculative_turn_cancelled` / `speculative_turn_unknown`) (`hold_speculative_dispatch`). - **`flue > core > legacy` is CONFIGURED LANE SELECTION, not runtime failover.** The order is resolved once per turn from `ZOE_BRAIN_BACKEND`/`ZOE_USE_CORE_BRAIN`; with `flue` selected and `:3579` down, every brain turn is answered by `zoe_flue_client._FALLBACK_TEXT` while the healthy core lane sits unused (#1613). Its trigger is deliberately narrow and must stay that way: **only** `zoe_flue_client.FlueTransportError`, which the client raises **only** under the opt-in `raise_transport_errors=True` and **only** for a pre-admission connect failure with no text yielded and no 2xx admission — proof the sidecar never executed the turn. A model error, an HTTP status error, a read timeout, or an empty 200 all mean the sidecar RAN the turn: they keep the sentinel and never re-dispatch (the #1137 duplicate-write class). **An HTTP 400 from a wire-mismatched sidecar is a REFUSAL, not an unreachable host** — the sidecar answered, so it is a config error to surface, never evidence a retry is safe. **The trigger is per-ROUTE, and `ZOE_FLUE_WIRE` adds routes:** wire 2 has no `?wait=result`, so its turns run through `_run_turn_aggregated_wire2` (non-streaming) or the streaming block's own wire-2 pre-admission branch. Each needs its OWN pre-admission raise, ordered BEFORE the wire-2 sentinel return — put it after and failover is silently dead on `ZOE_FLUE_WIRE=2`, the wire the 2.x sidecar actually speaks. Classification by exception class is never sufficient on its own: every raise site is also gated on `admitted`, because a connect-class error after a 2xx looks identical to a refusal and is not one. **A turn that has streamed its first token is NEVER re-dispatched under any condition** — the panel speaks each delta, so a replay makes Zoe say the reply twice. One retry, on the next configured lane; a short-TTL in-process circuit breaker then skips the dead lane so only one turn per cooldown pays the failed connect, and the first turn past the TTL re-probes. **Turns overlap, so the breaker is concurrency-safe by construction and must stay that way:** it is a `(deadline, generation)` pair, every mutation is a compare-and-set against the generation the turn OBSERVED (`_observe_circuit` → `_open_circuit`/`_close_circuit`), and the half-open probe is claimed by exactly one turn. Never make the close unconditional — an earlier turn's success would erase a later turn's open, and two turns crossing the same lapsed TTL would both re-probe a dead sidecar. This governs only WHETHER flue is attempted; the replay and exactly-one-retry invariants above do not depend on it. Every turn logs ONE greppable `BRAIN_LANE lane_attempted=… lane_served=… outcome=…` line (ids only, never message text) in BOTH flag states — that is observability, and it is how an operator asserts which brain answered (`grep BRAIN_LANE ~/.zoe-logs/*`; this service does NOT log to journald). Three properties keep that line trustworthy rather than merely present, and all three are easy to regress. **(1) Exactly one, on every path a turn can leave by — ONE-SHOTS INCLUDED.** The streaming wrapper is an async generator, so a consumer that disconnects after the first delta throws `GeneratorExit` at the yield and skips everything after it; a one-shot has the same hole with no generator to close, because it is routinely CANCELLED (the LiveKit lane awaits it under `asyncio.wait_for`, chat disconnect cleanup cancels its task) and cancellation exits the await without reaching any terminal branch. Both shapes emit through the once-only `_LaneRecord` wrapped in `try/finally`, so an interrupted turn logs `outcome=interrupted` (`reason=caller_cancelled` / `consumer_disconnected`, read from the live exception so an unexpected error is not mislabelled a cancel) instead of vanishing. Never put the only emission after the loop or after the await. **(2) The outcome is the client's verdict, not "the generator finished", IN BOTH FLAG STATES.** `zoe_flue_client` renders an HTTP error, a read timeout, an empty 200, a rejected wire-2 body and a post-admission stream death alike as its canned sentinel and ends the stream normally, so an INFERRED label calls every one of them `ok` — success reported for exactly the failed turns the line exists to diagnose. The client reports its terminal verdict through the opt-in `outcome_sink` and the line carries it (`ok`/`fallback`/`error`). The default-OFF flue path takes the same sink (`_flue_streaming_labeled`/`_flue_oneshot_labeled`) — it is the deployment actually running, and a pre-request `outcome=dispatched` label there was identical for a healthy turn and every failure mode. Its DISPATCH is unchanged: one client call, never `raise_transport_errors` (which would let `FlueTransportError` escape into a route with nothing to catch it), no lane hop, and **no breaker state touched in either direction**, so a later flag flip still starts from a closed breaker. The core/legacy lanes keep `outcome=dispatched`: they have no verdict to report, and wrapping them would move `_drop_flue_only_kwargs`'s fail-closed raise from call time to first-iteration time. Labels only: nothing in the sink is read before a dispatch decision, so a wrong label can misinform an operator but can never re-run a turn. `outcome_sink` and `raise_transport_errors` are both dispatch-INTERNAL kwargs, stripped from caller kwargs by `_sanitize_kwargs`. **(3) Breaker state must match the EVIDENCE, not the exit path.** The half-open probe re-arms the deadline as it claims the lapse, so only the probe's own outcome closes it — and reaching `_close_circuit` after the loop is not enough, because a consumer that disconnects after the first delta skips it and leaves a demonstrably reachable sidecar in the penalty box for another full cooldown. The streaming cleanup therefore closes the breaker (CAS against the observed generation, as always) when the turn YIELDED a flue delta before unwinding. The evidence is the yield and nothing else: `served_any` is set only inside the flue loop, a consumer that cancels before the first delta proved nothing and leaves the claim armed, and a one-shot never closes from cleanup at all (it yields nothing incrementally, so a cancelled await is not evidence flue answered). Pinned by `tests/test_brain_lane_failover.py` (`ci_safe`), whose load-bearing cases are the negative ones — the replay invariant, the four non-transport failure classes, the wire-2 route parity, the interrupted-consumer and cancelled-one-shot lines, and the guard-the-guard case where a probe that yielded nothing must NOT close the breaker.

## Forbidden

- **The startup memory probe checks RECALL CORRECTNESS, not just plumbing** (`_run_memory_capture_startup_probe` + `memory_recall_probe.run_self_recall_check`). The 2026-07-31 torn-HNSW corruption reported `memory_capture: ok` for ~8 hours because `search()` returned *something* — the probe only proved the call path worked, never that it returned the RIGHT row. The check now samples one real stored row and requires it (or an exact-duplicate embedding, distance < 1e-3) back in its own top-10; a MISS marks memory `degraded` on `/health`. It is read-only (`collection.get`/`query` directly, never `MemoryService.search`) so it ticks no access counters. **A self-recall MISS is deliberately NEVER fatal — not even under `ZOE_MEMORY_STARTUP_STRICT`** (it sits in its own try/except, outside the strict re-raise): a corrupt index is exactly when the service must stay up and observable, since lexical recall may still answer and an operator needs a live `/health` to diagnose from. Crash-looping on a bad index is the failure being detected, not a response to it. Strict mode still governs genuine plumbing failures, unchanged. Pinned by `tests/test_memory_recall_probe.py` + `tests/test_memory_startup_probe_wiring.py`. Independent backup/compaction tooling: see `scripts/AGENTS.md` (memory-store resilience trio).
