# ── Resemblyzer (speaker ID) — the ONE package that needs a two-phase install ─
# Resemblyzer 0.1.4 declares `webrtcvad>=2.0.10`, `torch>=1.0.1`, `librosa`,
# `numpy`, `scipy`, `typing`. Three of those are wrong for a 3.12 venv:
#   * webrtcvad 2.0.10 is sdist-only AND its module does `import pkg_resources`
#     at import time. setuptools 84 (what torch pulls) no longer ships
#     pkg_resources, so the sdist builds with gcc and then FAILS TO IMPORT
#     (measured). `webrtcvad-wheels` 2.0.14 is the maintained fork: same
#     `_webrtcvad` extension, no pkg_resources, cp312 aarch64 wheel.
#   * torch on PyPI for aarch64 became a 454 MB CUDA-13 bundle (+ nvidia-*-cu13,
#     triton) from 2.9; the CPU build lives on the PyTorch CPU index. Pinned to
#     the exact wheel so no index-precedence rule can swap it.
#   * `typing` is the py2 backport; it must not be installed on 3.12.
# So the build script installs this file, then `resemblyzer==0.1.4 --no-deps`.
webrtcvad-wheels==2.0.14
torch @ https://download.pytorch.org/whl/cpu/torch-2.14.0%2Bcpu-cp312-cp312-manylinux_2_28_aarch64.whl
# librosa 1.0.0 (>=3.12 only, API removals) is what an uncapped resolve picks on
